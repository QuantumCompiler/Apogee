# Apogee — Roadmap

How we work: features get discussed in chat, written up here (and in [SPEC.md](SPEC.md)), given their own document in [`backlog/`](../backlog/README.md) when they're specced, then an agent takes the backlog item and builds it straight from that document (there is no separate TODO file — the backlog is the queue). When work ships it's recorded in detail in [MILESTONES.md](MILESTONES.md); this file stays high-level — the running board of themes per release, plus what's next.

**Version scheme:** feature releases are `v0.x.0`, patch releases are `v0.x.y`; development happens on a branch named for the release being built (currently `v0.1.3`) and merges into `stable` — **and that merge is the release** (decided 2026-09-22): the pipeline publishes whatever version `CMakeLists.txt` names, if it hasn't shipped already. Checked boxes are shipped; the detailed write-up of each is in MILESTONES.md.

## Shipped releases

### v0.1.0 — The C++ harness *(tagged 2026-09-22 · [release notes](https://github.com/QuantumCompiler/Apogee/releases/tag/v0.1.0))*

The first release, planned 2026-08-24 from Ommi's documentation (see [SPEC.md](SPEC.md) → Background for the lineage and divergences) and built in exactly one month: a single, self-contained C++ binary that runs local and cloud language models from one harness — a one-shot completion, an interactive chat, or an OpenAI-compatible HTTP server — with the model a matter of configuration rather than architecture. Five platforms, no bundled models, no cloud account required, and it passes its own doctor on a fresh, keyless, modelless machine. The themes, each recorded in detail in [MILESTONES.md](MILESTONES.md) → Milestones A–Z:

- [x] **The walking skeleton** — CMake/Catch2 project skeleton, the config engine (typed loads, comment-preserving mutation), the harness core (message IR, router, capability probes), the Anthropic backend, `apogee complete`, the shared agent loop behind its Reporter seam, the terminal UX layer, and `apogee chat` with line editing *(Milestones A–H)*
- [x] **Eight backends behind one interface** — Anthropic, OpenAI and Google over their direct APIs (streaming, native tool use, typed thinking) for API billing plans; the same three vendors plus Ollama through their official CLIs (`claude-cli`, `codex-cli`, `gemini-cli`, `ollama-cli`) for subscription plans, each a characterized child process whose credentials Apogee never reads *(Milestones D, I, L)*
- [x] **Local inference and model depth** — llama.cpp linked in-process (KV-cached sessions, vision through mtmd, in-process quantization), `apogee models list/info/status/pull` over Hugging Face and the user's Ollama store with a copy → verify → commit ladder, and per-family model profiles with the three streaming filters *(Milestones J, N–P)*
- [x] **Serving and the control plane** — `apogee serve`, OpenAI-compatible and for server deployments only, over the same loop as every other surface; `/v1/admin/*` behind a per-install `0600` bearer token, its config edits byte-identical to the CLI's; the provider credential store and the one key resolver *(Milestones T–U)*
- [x] **The front-end contract** — stdio machine mode: the CLI's events as JSONL over stdin/stdout so a GUI can power the executable directly, never over a port *(Milestone M, [machine-mode.md](../reference/machine-mode.md))*
- [x] **Tools, agents and MCP** — native toolsets (sandboxed fs, gated shell, git, notes, retrieval) under the `permissions:` schema, the MCP stdio client plus the in-binary `__mcp-tools` server, and agents as data with per-agent tool policy, validated structured output and the bundled reviewers behind `apogee analyze` *(Milestones V–X)*
- [x] **Retrieval and knowledge** — the SQLite/FTS5 chunk store, lexical → vector → hybrid retrieval with reranking through the one per-turn resolver, `--rag` and `auto_rag` splicing excerpts without touching history, knowledge records with capture (`apogee knowledge`, `/capture`), and knowledge graphs up to communities and named cross-collection graphs *(Milestones Q–S, Y)*
- [x] **Training and distillation** — a Python environment Apogee owns, compiled-in kits, dataset preparation and teacher distillation, the train → eval → promote → rollback lifecycle producing versioned GGUFs, and the orchestration layer: gated pipelines, regimes, and the scheduler-invoked cycle *(Milestone Z)*
- [x] **One install contract** — `apogee check` / `--fix`, every install path reading one layout declaration, secrets `0600` and never over HTTP, shell completions for four shells, and the installers + GitHub Releases pipeline *(Milestone K)*

*Every decision the release consumed — the toolchain (C++20, CMake + FetchContent, Catch2 v3, nlohmann/json + CLI11 + libcurl + replxx + SQLite), the five-target matrix (`macos-arm64`, `linux-x64/arm64`, `windows-x64/arm64`; the Intel Mac dropped 2026-09-19), GitHub Releases as the distribution host, macOS unsigned, self-update deferred — is recorded in the milestone that consumed it; the living summary is [CLAUDE.md](CLAUDE.md) → Stack & environment. Known limitations are on the release page: unsigned macOS binaries, Windows the least-verified platform (the vendor-CLI backends refuse there), no self-update, and `serve` is plain HTTP behind your own TLS.*

### v0.1.1 — The release pipeline *(released hours after v0.1.0 · [release notes](https://github.com/QuantumCompiler/Apogee/releases/tag/v0.1.1))*

A maintenance release — nothing under `source/` changed; the binary is functionally identical to v0.1.0, rebuilt by a pipeline worth trusting. A merge into `stable` **is** now the release, with the version in `CMakeLists.txt` deciding which (an already-shipped version publishes nothing, so docs merges stay quiet); the version can no longer disagree with the tag (a local preflight, the workflow's gate job, and a PR-time `version bump` check); the tag and the release are created together after every blocking build passes, so a failed run strands nothing; the source-level suite — 1,411 cases, selected by construction rather than an exclusion list — gates all five platforms before anything is built for release; and the pipeline survives being re-run. The recorded cost: the 18 executable-spawning ctest entries (`cli.install_parity` among them) gate only `make test` now. The procedure lives in [DEVELOPER.md](DEVELOPER.md#cutting-a-release) → Cutting a release.

### v0.1.2 — The terminal and the model directory *(released 2026-09-25 · [release notes](https://github.com/QuantumCompiler/Apogee/releases/tag/v0.1.2))*

Quality-of-life for the two places a local-model user actually lives: the chat terminal and the model files. Existing installs move their models into the new store with `apogee models migrate --yes`.

- [x] **Completion at every depth** *(2026-09-23/24)* — shell completion now reads the whole live parser (every verb, alias and flag, at every depth), argument kinds are declared where each argument is added, and the 95 arguments that name something real complete to it; the stubs are exercised in the real shells.
- [x] **The model store** *(2026-09-23)* — one directory per model, per format (`gguf/`, `safetensors/`), per set of weights named by the weights' own hash, declared once in `modelstore/store.h`; `apogee models convert` (SafeTensors → GGUF through llama.cpp's vendored converter, image projector included); `models migrate` for existing installs; a pull that can no longer overwrite an earlier snapshot; training outputs land in the same structure.
- [x] **Conversion hardening** *(2026-09-23/24)* — llama.cpp repinned to `b11151` (Gemma 4's unified checkpoints), `quantize` carries the projector (claimed on day one, found unwired, fixed with a test), and `convert` shows hashing progress and cleans its staging on Ctrl-C.
- [x] **Chat and terminal UX** *(2026-09-25)* — the wait after every chat answer removed, a hybrid model's failing second turn fixed, `models list` coloured by what a row is, and room around the banner and each question.
- [x] **Terminal Markdown rendering** — backlog item 23, shipped 2026-09-25 *([Milestone G](MILESTONES.md#milestone-g--the-terminal-ux-layer))*: an answer's Markdown rendered as it streams — emphasis, headings, lists, quotes, fenced code, rules, links, tables — one open line redrawn in place and never the last column, while pipes, machine mode and the saved transcript keep the model's text byte for byte. Hand-written over md4c and no code highlighting yet (both the user's calls); `--raw` and `ui.markdown: false` switch it off.
- [x] **Chat input completion** — backlog item 24, shipped 2026-09-25 *([Milestone H](MILESTONES.md#milestone-h--apogee-chat))*: Claude Code's input affordances in `apogee chat`. Typing `/` lists the commands as you type, each with a one-line description; a command's values follow it (backends after `/model`, retrievers after `/retriever`); `@` completes files and folders from the working directory; Tab takes the top row. The rows are the line editor's own (not a TUI), never reach the last column, and never outlive the line they belong to. One table now feeds `/help`, completion and dispatch, and a missing handler fails the build; `/retriever` and `/rerank` are listed for the first time. A piped chat is unchanged. A sent `@file` stays text until attachments (26d) land (the user's call).
- [x] **Releases from the pull request's own build** *(2026-09-25, [Milestone K](MILESTONES.md#milestone-k--the-install-contract))*: a merge into `stable` no longer rebuilds anything, and no longer runs `release.yml`. CI packages every build as it runs. Once the pull request merges, `tag and release` checks those archives against the merged source, tags the version the executable reports, and publishes them. A dispatched rehearsal proves it before the merge, and a pushed tag remains the manual path. Its first use was this release's own merge, which published all five archives from the pull request's run with nothing rebuilt. Before the pull request even exists, `make pr-ci` rehearses its CI run on the developer's machine: the test merge into `stable`, then the same jobs through the same scripts, for the host's target.

## In progress

### v0.1.3 — Local agent tools + small-model depth

The two tracks specced 2026-09-25, eighteen backlog items in all, and one found on the way (26m) — see the [`backlog/`](../backlog/README.md) index's v0.1.3 table for the queue and gates.

- **Local agent tools** *(a spike split into six items, [25a–25f](../backlog/README.md#index))*: local models get files, the shell, git, notes, document search, page reading and web search — the tools every other backend already has. The spike found the gap (the llama.cpp backend never put tools into the prompt, so no local model was ever shown one) and measured the fix, llama.cpp's own chat layer linked in-process: 6 of 6 tasks on Qwen3.8-27B and Qwen3-VL-8B. In build order: **tool safety defaults** (fetch asks per new website, file tools start in the launch folder — closes an outbound-data exposure that exists today), **local tool calling** (the unlock), **hybrid prompt checkpoints** (Qwen3.5/3.8 stop re-reading the conversation every step), **tool ergonomics**, **web search through the user's own SearXNG** (revising the 2026-08-26 provider-search-only decision), and **`fetch_url` as a reader**. The user's calls: SearXNG, ask per website, the launch folder, and 8B-class models and up.
- **Small-model depth** *(a review split into twelve items, [26a–26l](../backlog/README.md#index), and 26m found shipping 26a)*: getting the most out of small local models. **Automatic attachments** — files, folders, PDFs, images, audio and video attached to a chat, indexed with the embedding model, handed to the model each turn with citations; media read natively when the model can and through a helper model when not. **Helper-model roles** (vision, transcription, a utility model for chores). **Reliability** — grammar-constrained JSON, tool selection by relevance, sampling that actually reaches local models, thinking on/off/auto with a budget. **Speed and memory** — a default window sized to the machine, a sliding-window model's cache kept at its window (26m, shipped), a persistent prompt cache, speculative decoding only if a clean measurement justifies it. **Memory across chats** — a per-turn context budget and automatic recall, never on `serve`. The user's calls: attachments kept with their chat and cached by hash, helper models used automatically, and external converters.

Landed on the branch so far:

- [x] **The CLI pipeline** *(2026-09-25, [Milestone K](MILESTONES.md#milestone-k--the-install-contract))*: CI and the release are now the CLI's pipeline, one per deliverable, ahead of the GUI applications. It builds only when what the CLI is built from has changed since the latest release. Otherwise it copies that release's CLI into the run and into the next release. Releases take their name from a new `lib/release/VERSION` file, and the CLI keeps its own version, which changes only with the CLI.
- [x] **Tool safety defaults** — backlog item 25a, shipped 2026-09-25 *([Milestone V](MILESTONES.md#milestone-v--the-native-toolsets))*: `fetch_url` asks the first time a run reaches each new website, showing the whole URL, and `always` adds the host to a new `tools.allowed_hosts` list. Where nobody can answer (a pipe, `serve`, a machine-mode run with no driver), only the listed websites are reached. Redirects are followed one hop at a time, and a hop to a new host is asked about like a direct fetch. Hosts are compared exactly, and the URL fetched is rebuilt from the one the gate saw. Downloads are capped at 5 MB. The file tools now default to the folder Apogee was started in, not the home directory. `check` reports both, and `config add-allowed-host` / `delete-allowed-host` have admin twins.
- [x] **Local tool calling** — backlog item 25b, shipped 2026-09-25 *([Milestone J](MILESTONES.md#milestone-j--local-inference))*: local models are shown their tools at last, through each model's own chat template (llama.cpp's `common` chat layer, linked in-process), and their calls come back as calls — the markup never reaches the screen or the transcript, reasoning goes to the thinking view, and a lazy grammar holds a call to its format. Every surface gets it at once: `chat`, `complete`, `serve --tools`, agents. The spike's six tasks pass 6/6 through Apogee on Qwen3-VL-8B and Qwen3.8-27B, with writes and the shell prompting through the gate. A model whose template cannot take tools says so in one line instead of answering quietly without them, and a third identical call in one turn is answered from the result already there.
- [x] **Hybrid prompt checkpoints** — backlog item 25c, shipped 2026-09-28 *([Milestone J](MILESTONES.md#milestone-j--local-inference))*: Qwen3.5 and 3.8 — whose memory llama.cpp cannot rewind — no longer re-read their whole conversation every turn and tool step. As llama-server does, the part that cannot be rewound is saved at two points in each prompt and restored when the next prompt diverges, so only what is new is read: on Qwen3.8-27B a tool loop went from 156 s to 47 s, each step reading 50–140 tokens instead of ~3,000, with byte-identical answers. Each checkpoint is about 150 MiB there; at most eight are kept, and `--verbose` prints what each turn reused and what the checkpoints hold.
- [x] **Tool ergonomics** — backlog item 25d, shipped 2026-09-28 *([Milestone V](MILESTONES.md#milestone-v--the-native-toolsets))*: the tools return less and ask for less generation, for local models that read a prompt at ~100 tokens/s. `run_command` keeps its output's first and last 8 KB; `read_file` reads line ranges, numbered, and a file past its 64 KB cap comes back as its size and length rather than a first 64 KB that fills a local window; `edit_file` replaces exact text, refusing an absent or ambiguous match; `grep_files` searches contents, at most 100 matches and 16 KB. Every request with tools now carries a short environment note — the date and time zone, the system, the working folder — which a model with tools could not know before, and which leaves the prompt cache intact. On Qwen3.8-27B and Qwen3-VL-8B, a one-line change in a 2,000-line file left the rest byte-identical, and a definition was found in one search.
- [x] **Web search through your own SearXNG** — backlog item 25e, shipped 2026-09-28 *([Milestone V](MILESTONES.md#milestone-v--the-native-toolsets))*: a `web_search` tool for every backend with tools, answered by a SearXNG instance you run — no key, no account, and queries leave only through your own instance. It revises the 2026-08-26 decision to leave search to the providers: a JSON API is not a scraped page, and the tool is never silently empty — no results, failing engines, JSON switched off, an instance that is down or rate-limiting, each is said, with what to change. It is off until `tools.search` names an instance; the instance is trusted by configuration, and every page a search finds is asked about like any website. A tool whose service cannot work is now withdrawn for the rest of the turn, so a small model stops retrying it. Setup is in the new [tools reference](../reference/tools.md). On Qwen3-VL-8B, asked what changed in a llama.cpp release, the model searched, opened a result after being asked, and cited it.
- [x] **`fetch_url` as a reader** — backlog item 25f, shipped 2026-09-28 *([Milestone V](MILESTONES.md#milestone-v--the-native-toolsets))*: a fetched page now reads as its own content — headings, lists, code, tables and links as Markdown, the links absolute so a model can follow them — without the menus, banners, ads and footers that used to fill the first 8,000 bytes. A page is read 6 KB at first, which is enough for a lookup, then 12 KB at a time with `offset`, to its end; a PDF, an image or any other file is refused by name instead of returned as noise; any charset becomes clean UTF-8. Hand-written, with no parser library, and held to a corpus of real and replica pages. On Qwen3-VL-8B, a model paged through a Python documentation page to its last section, followed a link to another page, and turned a refused PDF into a search for the paper's own page. That completes the local-agent-tools track.
- [x] **A context window sized to the machine** — backlog item 26a, shipped 2026-09-28 *([Milestone J](MILESTONES.md#milestone-j--local-inference))*: a local backend with no `context_size` now gets 32K tokens, or the model's own window when smaller, instead of everything it was trained for — and less only when free memory cannot hold that, as llama.cpp's own fitter judges. Its attention cache is kept at 8 bits (`q8_0`, flash attention on), about half of `f16`'s memory; a new `cache_type` setting chooses `f16`, `q8_0` or `q4_0`. On Qwen3.8-27B the cache went from 16 GiB to 1.1 GiB, and the process's peak memory from 16.7 GiB to 1.7 GiB. `models info` and `check` show the window and what its cache costs, from the header and matching llama.cpp to the MiB, and a long local chat is now warned at 80% and compacted at 90% of the window it really has — before, a local backend without `context_size` had no window the chat knew of, so it never was.
- [x] **A window-sized cache for sliding-window models** — backlog item 26m, found shipping 26a and shipped 2026-09-28 *([Milestone J](MILESTONES.md#milestone-j--local-inference))*: Gemma 4 and gpt-oss keep their sliding-window layers at the window those layers look back over, not the whole conversation — llama-server's default. At the 32K default Gemma 4 31B's cache went from 14.6 GiB to 2.0, and a four-turn chat's peak memory from 16.8 GiB to 4.2. A cache like that cannot be cut back past its window, so 25c's checkpoints now cover these models, and every cut is checked: one that would leave the window short restores a checkpoint instead. On gpt-oss-20b a cut 1,400 tokens back was refused and a checkpoint restored, and the answers matched the full-length cache's. `models info` states the new sizes, to the MiB of llama.cpp's own.
- [x] **Base models said, and stopped** *(2026-09-28, a fix, [Milestone J](MILESTONES.md#milestone-j--local-inference))*: a Gemma 4 12B and a Llama 3.1 8B pulled from their base (pretrained) releases were used for chat, and ran on into invented transcripts or loops under a warning that only mentioned tools. A model file with no chat template is now said to be what it almost always is -- a base model, with its instruction-tuned release named as the way to chat -- once a conversation and in `models info`; a guessed format's turn markers end the reply instead of spilling onto the screen; and a stop's last token is no longer claimed by the cache, a latent gap the scripted runtime now refuses.
- [x] **Helper-model roles** — backlog item 26b, shipped 2026-09-28 *([Milestone N](MILESTONES.md#milestone-n--model-operations))*: a small model can now do the chores beside a large one. Three roles join chat, embedding and extraction in the one resolver — `vision`, `transcription` and `utility` — each set with `config set-default-<role>` or its admin twin, and each falling back to the chat's own backend when unset, so nothing changes until one is set. The utility model titles chats, compacts them, restates a follow-up as a standalone search query before retrieval, judges `rerank: on`, and summarises a tool result over 8 KiB before a local chat model has to read it. Every one is a side request, so the chat model's cache is never touched: with Qwen3-VL-8B as the utility model and Qwen3.8-27B as the chat, a 35 KB file came to the 27B as 413 new tokens, the rest of its prompt from its cache. `models status` lists the six roles and what a local helper costs to load, and `check` warns when a vision or transcription role points at a backend that cannot read an image or audio.
- [x] **A per-turn context budget** — backlog item 26c, shipped 2026-09-28 *([Milestone F](MILESTONES.md#milestone-f--the-shared-agent-loop))*: every request is now assembled against the model's real window, for every surface, in the one shared loop. A tool result from an earlier turn is sent as a one-line stub naming the call and its size — the saved transcript keeps it whole, and the model can call the tool again — so a chat that read a 58 KB file on its first turn sent 4,235 tokens on its fifth instead of 19,005, with the same answers. Retrieval takes only the chunks that fit its share (20% of the window after the answer's reserve): `--rag-limit 12` against a 4K window injected 5, and said "5 of 12 chunks fit the context budget". A request that would still overflow is trimmed in reverse priority — earlier exchanges, then this turn's older tool results, then retrieved context — and every trim is said. An unknown window is never taken as room: nothing is sized by it. A conversation is measured, and compacted, as it is sent.
- [x] **Document attachments** — backlog item 26d, shipped 2026-09-29 *([Milestone H](MILESTONES.md#milestone-h--apogee-chat))*: attach a file, a folder or a glob to a chat — `--attach`, `/attach`, `@path` in a message, `complete --attach`, or a machine-mode `attach` line — and Apogee reads it (text, code, Markdown, PDF through `pdftotext`, HTML), indexes it with the embedding model into the chat's own private index, and hands the model what bears on each question, cited by page or line. A file that fits the window is inlined whole on the message it was attached with; the rest is retrieved per turn. On Qwen3.8-27B at its 32K default, a question about one detail in a 300-page PDF was answered from page 187 and cited it, from a 750-token prompt; a folder of 30 source files gave a function's file and line. The index is kept with the chat and deleted with it, and a file attached in another chat is copied from that chat's index rather than embedded again. Word, Excel and PowerPoint are refused by name for now.
- [x] **Images, audio and video attachments** — backlog item 26e, shipped 2026-09-30 *([Milestone H](MILESTONES.md#milestone-h--apogee-chat))*: the same `/attach` (and `--attach`, `@path`, `--image`, a machine-mode `attach` line) takes a picture, a recording or a video. A chat model that can read it gets it as it is with the next message: an image on a vision model, a sound on one whose projector hears, a clip up to a minute as its frames. From then on, and for a model that cannot read it, it reaches the model as text, indexed with the chat's documents: a description by the `vision` role, a transcript by the `transcription` role in 30-second windows, or for a video a timeline of what was on screen (every five seconds and at each scene change) and what was said, searchable by moment. With no helper set, the chat model reads its own media when it can. `ffmpeg` decodes audio and video, run so its output never reaches the terminal; `check` says whether it is installed and which models read what.
- [x] **Structured output by grammar** — backlog item 26f, shipped 2026-10-03 *([Milestone X](MILESTONES.md#milestone-x--agents-as-data))*: when a local model is asked for JSON in a given shape — the knowledge clerk, graph extraction, an `analyze` agent's report — its own chat template's grammar now holds the answer to that shape token by token, after any reasoning, so the JSON always parses and has every field the schema asks for. A template that cannot hold a schema falls back to stating it in the prompt, says so once, and the answer is still checked. On Llama 3.2 3B, captures valid on the first try went from 17 of 20 to 20 of 20, and graph extraction from 8 failed calls in 24 to none in 20; Qwen3-VL-8B stayed at 20 of 20 and no retries. The schema keeps the order its author wrote the fields in.
- [x] **Tool selection by relevance** — backlog item 26g, shipped 2026-10-03 *([Milestone F](MILESTONES.md#milestone-f--the-shared-agent-loop))*: past 16 registered tools, a turn now offers the tools its question needs instead of every one — `read_file`, `list_directory` and `run_command`, the eight tools the question ranks highest, and `find_tools`, which searches the rest. The ranking is by meaning when the embedding model costs nothing to call, its vectors cached per tool, and by matching words when not. An MCP server's tools come together, since they need each other's ids (the user's call). With the native tools and two 12-tool servers, the prompt on every step was about half the size on all four model families, and the eight-task battery passed as it did with every tool. A changed tool list makes a local model read its prompt again, so a new turn keeps the last turn's tools while they still fit its question. `--verbose` says what each turn offers and why.
- [ ] **Side calls in the thinking block** *(asked for 2026-09-30 — [backlog item 26n](../backlog/v0.1.3/thinking-side-calls.md), the release's end)*: a turn's other model calls — the embedder, the utility role's rewrites and summaries, the rerank judge, in-turn vision/transcription, the `/capture` clerk — narrated as dim labeled lines inside the thinking block, interleaved with reasoning in arrival order, completing in place with elapsed and tokens when truly known, collapsing with the block. Thinking-shaped by rule: never persisted, never in the answer, and the wire untouched — machine mode maps the narration onto its existing display-prose event, so the protocol vocabulary does not move. One new Reporter event, defaulted no-op; the busy line (M1) keeps the outside-a-turn case.
- [ ] **Session permission presets** *(asked for 2026-09-30 — [backlog item 26o](../backlog/v0.1.3/session-permission-presets.md), the release's end)*: launch the CLI with permissions preset, the claude-CLI shape — `--allow run_command --allow-host docs.python.org --deny write_file` on `chat` and `complete` — and change them mid-chat with `/allow`, `/deny`, `/revoke` and `/permissions`, each completable through the one command table like `/model`. The design principle that keeps it safe: **a preset is the prompt's `session` answer given early** — it seeds the same `SessionApprovals` the `s` key fills, the ladder stays config-first so a config `deny` is never loosened, tightening always wins, grants die with the process, and nothing writes config. The one new reach is deliberate: `complete --allow` lets a one-shot script use a destructive tool, the user having answered at invocation. The unattended grant ceiling stays on 27i's [user] calls — this is the attended sibling.
- [ ] **The tool-use policy** *(asked for 2026-10-03 — [backlog item 26p](../backlog/v0.1.3/tool-use-policy.md), the release's end)*: a model with tools uses them when told and refuses when not — the motivating transcript asked for the weather, was refused "real-time information", then searched perfectly once instructed. The generic fix, two levers at shared seams: the pinned environment note gains a **registry-composed policy paragraph** (reach for the matching tool on anything you cannot know; never claim you lack access to what a listed tool provides — composed only from tools actually present, so the note never promises an absent capability), and `web_search`/`fetch_url` descriptions lead with their **trigger cases** rather than their output shape. No per-model code, no refusal heuristics, no protocol change; the note's prefix-cache stability is pinned by test, and the transcript's weather question on Qwen3-VL-8B is the live acceptance case — first ask, one search, while small talk still triggers nothing.
- [ ] **The attachment map card** *(from the attachment-representation spike, 2026-10-03 — [backlog item 26q](../backlog/v0.1.3/attachment-map-card.md), the release's end)*: a folder attach gives the model content but no map — the stress-test model attached this repository, invented `lib/src/core/`, failed, re-guessed, and cycled its thinking until the turn died. The fix needs no graph and no models: a one-time structural card (shallow tree, per-directory counts, language mix) rendered from the walk the attach already did, riding the attaching message the way an inlined file does, capped small, persisted with history; after compaction it rides once more. ## Maintenance

The standing upkeep queue *(created 2026-10-03, the user's call)* — release-agnostic polish, performance and ergonomics, claimable at any time by name; it lives above the release tables in the [backlog index](../backlog/README.md#index), numbered `M1, M2, …` outside the release ascent. - [x] **The busy line** — maintenance item M1, shipped 2026-10-03 *([Milestone G](MILESTONES.md#milestone-g--the-terminal-ux-layer))*: a slow command now says what it is doing on one repainted stderr line, the way a chat does while it thinks, and clears it before printing its results. `models list` counts its reads as it goes (`reading model headers: gemma-4-31B-it-F16.gguf (6/31 · 7s)`), and so do `check`, `graph build`, `graph communities` and `embed ingest`; `models info` and `models status` name the file they read. The line appears only after 150 ms, so a fast command never flickers, and never reaches the terminal's last column. Nothing changes on a pipe, under `--quiet` (new on each of these commands) or with JSON output: piped, `models list` prints exactly the bytes it did. It is chat's own status line extended, not a second painter.
- [x] **Fast model listings** — maintenance item M2, shipped 2026-10-03 *([Milestone N](MILESTONES.md#milestone-n--model-operations))*: `models list` took 14 seconds on a store of 31 models and `check` 33, and the cause was not the number of models: reading a model file's header stepped over its vocabulary one string at a time, each step a separate request to the operating system. It now reads past them in blocks, and the same store lists in a third of a second (`check` in 0.7 s, `models status` in 0.03 s) with exactly the same output. M2 was specced as a cache of what the headers say; measured, the fix made it unnecessary, so no cache was built (the user's call): nothing is stored, and a listing can never be out of date.
- [x] **Pull to runnable in one command** — maintenance item M3, shipped 2026-10-03 *([Milestone N](MILESTONES.md#milestone-n--model-operations))*: `apogee models pull <owner/repo> --safetensors --register-with Q4_K_M` now does what took four commands: it downloads the full weights, converts them to F16 (with the image projector when the model has one), makes each quantized copy you list, and adds a backend for every file (`<model>-F16`, `<model>-Q4_K_M`), ready for `apogee chat -m`. `--register` alone stops at the F16, and `models convert` takes the same flags for weights already pulled. Each step reports as it runs; if one fails, everything before it stays and the chain prints the one command that resumes it, offline, without redoing anything. `models quantize` no longer prints llama.cpp's own log, which ran to hundreds of lines on a real model, and shows its progress on one line instead. Built without downloading a model: the live pull-to-chat check is the user's to run. After that first live run, the backends it registers are named the way the user names them — `Gemma4-E2B-F16`, `Gemma4-E2B-Q4KM` — with `--base-name` setting the part before the level.
- [x] **Model lineage** — maintenance item M4, shipped 2026-10-03 *([Milestone N](MILESTONES.md#milestone-n--model-operations))*: `models list` opened with eleven `(not configured)` SafeTensors rows whose job was already done — each had been converted into the GGUFs registered below it. Now a snapshot a conversion consumed leaves the default listing, one line under the table counts what was folded, and `models list --all` shows everything; a snapshot never converted stays. What was made from a snapshot reads `converted`, and `models info` — which now takes stored weights as well as a backend — prints a model's chain back to where it came from: quantized from its F16, converted from its snapshot, pulled from Hugging Face. The lineage was already in the records beside every conversion and quantization, so nothing new is written; where no record says, the model's one snapshot is inferred and the answer says *(inferred)*, and a link that has been deleted is named as gone. On the user's store, 12 snapshot rows folded to one line.
- [x] **A backend's name is enough** — maintenance item M7, shipped 2026-10-03 *([Milestone N](MILESTONES.md#milestone-n--model-operations))*: `models delete gemma-4-E2B-F16` used to refuse the backend's own name while its warning named the mapping, and the store path had to be hunted by hand. Now a backend's name deletes the stored model it points at, with the very confirmation the store path gets; `config add-backend <name>` with a stored model's name fills in its type, path and projector and says what it filled; and tab completion offers both — backends for `delete`, the store's unregistered models for `add-backend` — through the completion Apogee already installs (the user's call: no new `completion` command).
