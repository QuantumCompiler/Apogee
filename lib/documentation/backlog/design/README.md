# Apogee design — Backlog

**The work queue for the design prototype: one document per work item.** The design (`lib/design/`) is the reference every Apogee GUI app is built from. This queue holds its work that has been specced but **not yet built**. It is the layer between [ROADMAP.md](../../assistant/design/ROADMAP.md) and the shipped record in [MILESTONES.md](../../assistant/design/MILESTONES.md). An agent takes an item from the index below and **implements it straight from its document**. The release-by-release view across every product is the [backlog overview](../README.md); this index is the authority on its rows, and every change to it reaches the overview in the same pass ([Keeping this page true](../README.md#keeping-this-page-true)).

An item that needs an app or the CLI to change gets a sibling in that queue ([the router](../../CLAUDE.md)), gated both ways. A cross-queue gate is written with the queue's name: `darwin 10a` here, `design 1e` there. On the [backlog overview](../README.md#keeping-this-page-true), the waiting row's "Waits on" names it the same way, and a tie into a later release is listed under its "Ties to later releases".

## Lifecycle

1. A change is **discussed in chat** and gets a line on [ROADMAP.md](../../assistant/design/ROADMAP.md).
2. Once specced, it gets **its own document here**: a kebab-case filename in its table's folder, listed in the index in build order. The same pass adds it to the [backlog overview](../README.md#keeping-this-page-true).
3. When an agent **takes** it, the document **is** the working spec:
   - confirm scope with the user first (its **Open calls**);
   - mark its row 🚧;
   - build. One item at a time.
4. When it **ships**, it is recorded in [MILESTONES.md](../../assistant/design/MILESTONES.md). The document and its row are **deleted**, and any gate it satisfied is updated in the same pass. Its row leaves the [backlog overview](../README.md#keeping-this-page-true) too, with the counts, "can start today" and any "Waits on" it satisfied updated.

**The standing invariant:** every document here is pending work.

**Tags, gates and numbering** follow the Apple apps' queue ([its README](../darwin/README.md)):
- Open calls are tagged `[user]` (blocks the build), `[default: …]` (agent-decidable, recommendation recorded) or `(consumed decision)` (owned by another item).
- A row's Status is 🟢 workable, 🔒 gated on named real items (no cycles), or 🚧 in progress. Items marked **split first** are groomed into their listed sub-documents before anyone builds them. A changed gate, a split, or a row moved to another table changes the [backlog overview](../README.md#keeping-this-page-true) in the same pass.
- Ids are a track number and a letter (`1a`), ever-assigned.

## Document format

The Apple apps' format ([its README → Document format](../darwin/README.md#document-format)), with a **Reference.** section after **Seam + files** when there are precedents to cite.

## Index

Build order: the topmost item whose gate is satisfied is the next one to build.

### v0.2.1

**Track 1, the design prototype in React**, opened 2026-11-14 (the user's idea and calls, from that day's brainstorm). Today the design is one Design Component file, `lib/design/spec/html/main.html` (7,604 lines when measured that morning, 7,780 by the evening), with every screen's sample data in one constructor, one function feeding 28 screen sections and one clock. The 59 screen boards mount that file, and the claude.ai design canvas mirrors it, though the canvas was last published 2026-10-26 and is 6 boards behind. The user's calls: rebuild it in a compiled web framework with the **same layered architecture as the production GUIs**, so a new app in a new framework ports straight from it; **React, TypeScript and Vite**; the canvas **view-only**, and since a Design canvas cannot run a React build, the review surface becomes **one self-contained `lib/design/main.html` that opens by double-click**; this **queue of its own**; **v0.2.1**; and **Playwright** for the screenshots that check the port. Measured the same day: every screen lines up with one of the Mac app's 16 feature modules; the prototype's data is invented (no CLI-shaped keys), while the Mac app holds 613 recordings of the real binary, so the new prototype reads those and is checked against the old one on layout, states and wording rather than pixels. The split: the law (1a, shipped 2026-11-18 as the design's [ADR 0001](../../adrs/design/react-design-prototype.md)), the scaffold and layering check (1b), the old prototype's baseline (1c), the CLI stand-in (1d), styles, shell and the first screen (1e), one item per place (1f–1p, **1f split first**), the gallery (1q), the build boards as pages (1r), the parity proof (1s) and retiring the old files and the canvas (1t). The old prototype is frozen from 1c, and new design is drawn in the React app from 1e (the Apple apps' 10a is gated on it). No [user] call blocks any item.
