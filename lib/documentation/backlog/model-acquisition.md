# Model acquisition: open pulls from Hugging Face and Ollama

**What / why.** `apogee models pull <ref>` fetches **any** model the user names, from **either** source — a direct Hugging Face download (models, GGUFs, SafeTensors snapshots, and datasets, resolving repo/file refs) or the user's local Ollama store — plus the lifecycle around it: `models delete`, `models repair`, in-process quantization, role-dedication flags, and the default-No end-of-install offer. This is the item that puts weights on the machine, which makes it the practical unblocker for every other local-model item.

**The policy divergence is the item's defining property.** Ommi shipped a curated `approved.yaml` allowlist of sha256-pinned models and **refused** anything not on it. Apogee's 2026-08-24 decision deletes that: **there are no forbidden local models.** What survives is Ommi's layered-verification machinery, repurposed from gatekeeping to **integrity protection** — stream to `.partial`, verify size, verify the digest *where the source provides one*, verify GGUF loadability, rename last. Nothing partial ever lands. A known-unrunnable architecture **warns before a multi-gigabyte download starts** but never refuses it. The user's choice always wins; verification only ever tells them the truth about what arrived.

That reframing has a consequence worth stating plainly: with no allowlist, **the digest is often absent**. Ommi could always compare against a pin because it chose the models. Apogee frequently cannot, so the verification ladder must degrade honestly — "size and loadability verified, no digest published by the source" is a real and common outcome, and reporting it as plain "verified" would be a lie.

**Core constraint(s).**
- **No refusal by policy.** Acquisition never blocks a ref. Warnings are advisory and fire *before* the bytes move, not after.
- **Copy → verify → commit atomicity.** Downloads stream to `.partial`; verification runs on the `.partial`; the rename is last and is the only step that makes a file visible. **Any failure lands nothing** — no partial file, no half-written sidecar.
- **Provenance and integrity are separate fields in the sidecar.** What the source *claimed* (ref, source URL, published digest, size) and what is *actually on disk* (post-transform digest and size) are different facts, and a transform makes them differ. Ommi learned this by shipping a transform after the sidecar existed and having to add `FileSHA256`/`FileSize` beside the original pin; Apogee writes both from the start.
- **A declared template is a hint, never auto-applied.** Ollama's store carries a chat-template layer per model; recording it is useful, applying it silently would override the resolution ladder in [model-profiles.md](model-profiles.md) from outside.
- **Never read a vendor CLI's credentials** ([SPEC.md](../assistant/SPEC.md) → Principles, *A vendor CLI is spawned, never opened*). The Ollama path reads the user's **model store**, not their auth. `cli.no_vendor_credentials` covers this automatically; assert this item is in its scope.
- **No bundled models, and installers download nothing unasked** ([SPEC.md](../assistant/SPEC.md) → Non-goals). The install-time offer is **default-No**, asked per role, and a decline is remembered per role.
- **The offer is one decision, not three.** Every install path — `install.sh`, `install.ps1`, `make install` — calls the same hidden subcommand, so "no means no on every path" is a single behaviour rather than three that drift. This is the [⚠ One layout declaration](../assistant/CLAUDE.md#-one-layout-declaration-and-every-install-path-reads-it) discipline applied to a prompt.
- **Mutating models actions ship before the admin plane exists**, so they go into the parity table's documented-skip list; this area owns their admin-twin backfill when [admin-plane-foundation.md](admin-plane-foundation.md) lands.
- The decline-marker file is a **runtime** file under `~/.apogee/`, exempt from install parity like the update-check marker — record the exemption where the layout is declared rather than letting `install_parity` discover it.

**Seam + files.** New: `lib/src/cli/source/models/acquire.h/.cpp` (the `.partial` → verify → rename discipline and the verification ladder, source-agnostic), `models/source_hf.h/.cpp` (Hugging Face ref resolution and download), `models/source_ollama.h/.cpp` (store read, blob copy, and the strip/repair transform), `models/sidecar.h/.cpp` (provenance/integrity record), `models/offer.h/.cpp` (the pure `plan_offers()` decision over injected inputs, plus decline-marker read/write), `commands/models_pull.h/.cpp` (the `pull` / `delete` / `repair` / `quantize` subcommands and the hidden `offer-defaults`). Extended: `commands/models.cpp` (shipped 2026-09-07, [MILESTONES.md](../assistant/MILESTONES.md) → Milestone N — the subcommands attach to its existing command), `harness/layout.h` (the decline marker, declared once), `lib/scripts/install.sh` + `install.ps1` + the `make install` target (each ends by calling the one offer subcommand). Tests: `lib/src/cli/tests/models/` with an **injectable downloader seam** and source-specific fixtures for both paths.

**Reference (Ommi).** `lib/cli/src/ollama/` (2,152 lines): `materialize.go` (453 — read the `Sidecar` struct first; its field comments *are* the provenance/integrity design, including why `ExpectedDigest()` falls back to the pin for sidecars written before transforms existed), `transform.go` (294 — `TransformVisionStripped` and `GGUFInfo`), `offer.go` (202 — `PlanOffers` as a pure function, the per-role decline marker, and the deliberate rule that a runtime `models pull` offer **ignores** a declined install-time Ollama offer: "the user just asked to pull; asking 'install Ollama first?' answers their request, not nags"), `pull.go`, `detect.go`, `store.go`, `install.go`. Also `lib/cli/src/cmd/ommi/models.go` → the `quantize` / `convert` subcommands.

**Deliberate divergences.**
- **`approved.yaml`, its exact-match refusal, and the curated end-of-install offer are not ported** (2026-08-24 user decision). The *mechanism* of the offer survives — default-No, per-role, decline-remembered — but what it offers cannot be a curated list, so it must offer something the user names or nothing at all. **This is an open call below**, because "offer nothing" and "offer a suggestion" are materially different products.
- **Hugging Face direct is entirely new.** Ommi had one source; Apogee has two, which is why acquisition is a source-agnostic core (`acquire.cpp`) with two adapters rather than an Ollama package with a second entry point bolted on.
- **Quantization runs in-process** via `llama_model_quantize`, not by spawning a tool.
- **The Ollama vision-strip transform may become unnecessary.** Ommi stripped multimodal tensors from Ollama's combined text+vision blobs to make them loadable. With [multimodal-vision.md](multimodal-vision.md) shipped, Apogee may be able to *use* those tensors instead of discarding them — so `repair` keeps the strip as a fallback, but the first question this item must answer is whether the blob loads as-is.

**Decisions made** (dated):
- 2026-08-24 — Open local-model policy and dual sources (Hugging Face direct **and** Ollama pulls), replacing the planned Ommi-style curated allowlist *(user decision)*. Verification survives as integrity protection only.
- 2026-09-06 — **Split out of the `model-profiles-and-management` guard document** as the third of four *(user call: four-way split)*, and made the largest of the four deliberately: this is the piece whose Ommi reference alone is ~2,150 lines and which adds a from-scratch second source on top.
- 2026-09-06 — Gated on model-operations rather than on [model-profiles.md](model-profiles.md) (**gate satisfied**: it shipped 2026-09-07, ([MILESTONES.md](../assistant/MILESTONES.md) → Milestone N)): what acquisition actually needs is the GGUF header inspection it verifies with, the sidecar reading `models list/info` defines, and the `models` command to hang subcommands off — all of which are operations, not profiles.
- 2026-09-06 — The verification ladder reports **which** checks ran, not a single boolean. With no allowlist a published digest is often unavailable, and collapsing "digest matched" and "no digest existed" into one word would misreport the common case.

**Open calls:**
- [user] **What the end-of-install offer offers.** Ommi offered two specific curated models (a 1B embedder, a 3B extractor) because it had an allowlist to draw from; the open-model policy removes that basis. The options are genuinely different products: offer nothing and let the install finish silently, offer to open the docs, or name a small default pair anyway as a *suggestion* the user can override. This is a product-shape call, not a technical one.
- [default: keep] Hugging Face SafeTensors → GGUF conversion (needs a Python script dependency). Kept because the confirmed training direction ([training-distillation.md](training-distillation.md)) needs HF snapshots anyway, and "primarily C++" governs the harness, not satellite scripts.
- [default: none beyond an optional config token key] Hugging Face auth for gated repos. No OAuth flow, no credential storage — the same line the vendor-CLI principle draws.
- [default: resume from `.partial` when the source supports ranged requests, restart otherwise] Whether an interrupted multi-gigabyte download resumes. Resuming must never weaken verification: a resumed file is verified end to end like any other.

**Guardrail(s).** An **injectable downloader seam** so every pull test is hermetic — no network, source-specific fixtures for both the HF and Ollama paths. A **failure-injection suite** at each rung of the ladder (truncated stream, wrong size, wrong digest, unparseable GGUF) each asserting that **nothing lands**: no visible file, no sidecar, no partial. `plan_offers()` tested as a pure function across the decline-marker matrix, including the deliberate asymmetry where a runtime pull ignores an install-time Ollama decline. An assertion that all three install paths reach the same offer subcommand — the parity discipline that `install_parity` already applies to directories, applied to the prompt. `cli.no_vendor_credentials` asserted to cover the Ollama store reader. Every guardrail mutation-tested before it is trusted: delete the rename-last ordering and the failure-injection suite must fail.

**Acceptance criteria:**
- [ ] A pull of any user-named ref — Hugging Face or Ollama — verifies size, digest **where the source provides one**, and GGUF loadability on the `.partial`, then renames atomically
- [ ] Every injected failure lands nothing: no visible file, no sidecar, no `.partial` left behind
- [ ] **No ref is ever refused by policy**; a known-unrunnable architecture warns *before* the download starts and proceeds if the user says so
- [ ] The verification report names which checks ran, so "no digest published" is distinguishable from "digest matched"
- [ ] The sidecar records provenance and on-disk integrity as separate fields, and `repair` uses the on-disk pair
- [ ] `models delete` and `models repair` round-trip an Ollama-sourced combined multimodal blob
- [ ] `quantize` runs in-process
- [ ] The install-time offer is default-No, per-role, and declines are remembered — verified identical across `install.sh`, `install.ps1`, and `make install`
- [ ] The harness never touches a vendor CLI's credential storage (test-locked)

**Scope note.** Gated ring, local-model depth, **third of four**. Gate **satisfied**: model-operations shipped 2026-09-07 ([MILESTONES.md](../assistant/MILESTONES.md) → Milestone N), providing `models/gguf_inspect.h` (the header reader this item verifies `.partial` files with) and the `models` command these subcommands attach to. **Note one divergence it left behind:** the sidecar contract does NOT exist yet — `models list` has no verification-state column, because nothing writes a sidecar until this item does. Defining that record is this item's job, not a thing to inherit. Ring convention also assumes the complete v0.1.0 set. Out of scope: the profile registry ([model-profiles.md](model-profiles.md)); multimodal inference ([multimodal-vision.md](multimodal-vision.md)), though this item must determine whether Ollama's combined blobs still need stripping once that ships; the training/distillation stack ([training-distillation.md](training-distillation.md)); the admin-plane twins of the mutating routes, which land with [admin-plane-foundation.md](admin-plane-foundation.md).
