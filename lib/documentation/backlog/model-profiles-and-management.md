# Local-model depth: per-family profiles, filters, tool dialects + roles, models suite, open model sources (HF + Ollama)

**What / why.** The local-model quirk layer and the model-operations layer, designed in from the start instead of accreted through four separate gemma4 bug reports as Ommi did. MUST BE SPLIT into two backlog docs before an agent builds (profiles first, management second) — this entry guards the coverage and the shared invariants. The split grooming must also give local multimodal/vision (mtmd/mmproj) a recorded home if the llamacpp-backend open call lands it here, and this area owns the models-plane admin backfill (pull/repair/approved routes) once admin-plane-foundation exists. (1) Profiles: a ModelProfile registry keyed by family bundling chat-template selection (llama.cpp's embedded-template engine plus bespoke overrides, specific-before-family matching so gemma4 never renders gemma markers), stop markers, output-framing strip rules (streaming markup filter for control-token channel headers), reasoning wrappers (streaming ThinkFilter state machine with a hold-back buffer sized to the longest opener; nil = uncharacterised/permissive vs empty = verified-none), and tool-call dialect — the TOOL_CALL prose-injection protocol plus per-declared-dialect native control-token parsing merged in document order, with the agentloop streaming lookahead and the parser sharing one opener list; resolution ladder explicit config > declared > name auto-detect > generic. Cloud backends need none of this — the layer is local-only, consumed through harness ModelBehavior. (2) Management: the three role pointers resolved through ONE shared resolver used by CLI and HTTP (-m > per-feature backend > role pointer > default; CLI/HTTP disagreement was a real Ommi bug class), `apogee models list/info/status`, and **open model acquisition** (2026-08-24 policy: there are NO forbidden local models — Ommi's curated sha256-pinned allowlist and its refusal semantics are deliberately not ported): `apogee models pull` fetches any ref the user names from **both sources** — direct Hugging Face downloads (models, GGUFs, SafeTensors snapshots, and datasets, resolving repo/file refs) and the user's Ollama store — keeping Ommi's layered-verification materialization as integrity protection, never gatekeeping (stream to .partial, verify size + digest-where-the-source-provides-one + GGUF loadability, rename last — nothing partial ever lands; provenance vs integrity split in sidecars; a known-unrunnable architecture warns before a multi-GB download but never refuses), models delete/repair (Ollama-sourced combined multimodal blobs may still need Ommi's strip/repair transform), GGUF header inspection wired into check, in-process quantize via llama_model_quantize, role-dedication flags (--as-embedder/--as-extractor), and the default-No end-of-install offer with per-role decline memory.

**Core constraint(s).**
- A model's quirks live in its profile, never in package-level global token lists (marker sets differ by one character across families); specific-before-family matching; declared profile outranks filename guessing
- Filter markup at the source so display, history, tool parsing, and any cached prefix stay consistent; unknown = permissive
- Profiles are characterized from real weights, not specs; unverifiable profiles surfaced as such
- No forbidden local models (2026-08-24 divergence from Ommi): acquisition refuses nothing by policy — verification protects integrity, warnings about known-unrunnable architectures are advisory, and the user's choice always wins
- Copy→verify→commit atomicity: nothing partial ever lands; provenance separated from integrity in sidecars; unrunnable-architecture warnings fire before any multi-GB download — but never block it
- No bundled models; install offers default to No with per-role decline memory
- Mutating models CLI actions landing before the admin plane exist go into the parity table's documented-skip list; this area owns their admin-twin backfill

**Reference (Ommi).** src/backends model_profile.go / chat_template.go / think_filter.go / markup_filter.go / native_tool_calls.go + harness.ModelBehavior (OMMI-14, retrofitted after four independent gemma4 bugs); src/ollama (approved.yaml, Require/Detect/Materialize/Pull, transform, PlanOffers), src/gguf, cmd/ommi models.go, harness.ExtractionBackendKey discipline (OMMI-13).
