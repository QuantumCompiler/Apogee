# The code graph: deterministic extraction

**What / why.** Apogee's knowledge graph (Milestone Y) is built by a model: one structured-output call per chunk of ingested prose. That is the right tool for documents and decisions, and the wrong one for source code — code's structure is *in* the code, and a parser recovers it deterministically, locally, for free, with no hallucinated edges and no spend. This item adds a second extractor beside the first: parse a source tree with **tree-sitter** (pinned, read-only, in-process) into the **same graph database** — nodes for files, modules, classes and functions; edges for `calls`, `imports`, `inherits`, `references`, `defined_in` — each mention carrying `file:line` provenance, each edge tagged with its **origin**: `extracted` (stated in source, parsed) versus `inferred` (asserted by a model), with a confidence the origin implies. The external reference is [Graphify](https://github.com/Graphify-Labs/graphify) — codebases turned into queryable graphs, code parsed locally by AST ("deterministic, no LLM, nothing leaves your machine"), every edge tagged extracted-or-inferred — adopted here as a second extraction *source* for the one existing graph layer, not a second graph system. Incremental is part of the item: files are fingerprinted by content hash, and `apogee graph update` rescans only what changed — fast enough that a user's own post-commit hook can keep a repo's graph fresh.

**Model-free is the capability, not a side effect** *(the user's call, 2026-09-30)*: a code-only graph is created, resolved, clustered, walked and exported with **no LLM, no API key, no embedder, and no network** — Graphify's "a code-only corpus requires no API key", adopted as a test-locked guarantee across the whole track. That includes **entity resolution**: cross-file linking (a call site to the function it names elsewhere, an import to its module) is deterministic, by qualified name and the import edges themselves — never by vector agreement for code nodes. The model-touching steps that exist in the prose pipeline stay exactly where they are and stay optional here: community *summaries* are a paid extra a code graph can skip (clustering itself is deterministic), and their absence is reported, never silently required.

**Core constraint(s).**
- **One graph layer.** Code nodes and edges land in the existing `kg_*` tables of a named graph or a collection's database — the same communities, dedupe, retrieval-time expansion and admin reads apply to them with no second code path. The closed type set grows by the code kinds and relations, still enforced in host code.
- **Zero model calls by construction — end to end.** The code extractor never touches the Harness (generation arrives as a closure; this extractor takes none), and the guarantee covers the pipeline, not just the parse: build, `update`, cross-file resolution, `communities` clustering (summaries skipped and reported absent), dedupe over code nodes, and every downstream verb ([27l](graph-navigation.md)) and artifact ([27m](graph-artifacts.md)) succeed on a machine with zero backends, zero keys and no network. A mixed tree still sends prose through the LLM extractor under its existing metered-refusal rule; nothing about spend changes.
- **Resolution is deterministic for code.** Cross-file links resolve by qualified name and import edges; an unresolvable reference stays an *unresolved* edge to a name node (counted, never guessed). Vector-agreement dedupe remains the prose entities' mechanism and, absent an embedder, skips with a report — it never blocks a code-only build.
- **Third-party is read-only:** tree-sitter and each language grammar are pinned under `lib/src/cli/third_party/`, never edited in-tree; pin moves are deliberate events. The parse must degrade honestly — an unsupported language or a file that will not parse is *skipped and counted, by name*, never silently.
- **Origin is schema, not convention:** `kg_edges` gains `origin` and `confidence` columns (additive migration, the chunk-metadata-column precedent); every existing writer stamps `inferred`, the code extractor stamps `extracted`. A reader can always tell what was parsed from what a model asserted.
- **Local and private:** parsing reads the tree it is pointed at and nothing else; honors `.gitignore` inside a repository (the `git ls-files` pattern 26d set); no network, no new sockets, Windows per-platform skips recorded where POSIX mechanisms leak in.
- **Code style carries:** `.h`/`.cpp` pairs; the tree-sitter C API's handles wrapped in `unique_ptr` with custom deleters at the boundary class, raw handles never escaping it.

**Seam + files.**
- `graph/code_extract.h/.cpp` (new, in the guarded package): walk → parse → nodes/edges/mentions, pure over an injected file reader; per-language queries live beside it as data.
- `graph/code_resolve.h/.cpp` (new): the deterministic cross-file pass — qualified-name tables from the parse, import-edge resolution, call-site → definition linking, the unresolved-name accounting.
- `graph/build.h/.cpp`: a build whose member is a **source root** (not only a collection) — the fingerprint becomes per-file content hashes in `kg_state`, and `graph update` rescans changed files only.
- `embedstore/graph.h/.cpp`: the `origin`/`confidence` columns and the code node kinds; `graph_dedupe` keeps origin-aware unions (an `extracted` edge never merges *down* to `inferred`).
- `cli/graph.cpp`: `graph build --source <dir>` (and `--lang` filters), `graph update`, counts of parsed/skipped files in the human output.
- `third_party/tree-sitter/` + pinned grammars; `lib/src/cli/CMakeLists.txt` targets; lint scope excludes them as it does llama.cpp.
- Tests: `tests/business/graph/code_extract_test.cpp` over a fixture mini-repo (hermetic — committed source files, no network); golden node/edge sets per language; the update path asserted by touching one file.

**Reference (Ommi).** The existing graph layer is itself the Ommi-derived analog (knowledge track, Milestone Y); **code-AST extraction has no Ommi analog**. External prior art: Graphify (above). Deliberate divergences from it: Apogee **keeps** its lexical/vector retrieval beside the graph (Graphify is no-vector by design; Apogee's retrieval matrix is shipped and complementary); assistant-hook "strict modes" and instruction-file nudging are out of scope — Apogee's graph reaches models through its own toolsets ([27l](graph-navigation.md)) instead.

**Guardrail(s).**
- Golden extraction over the fixture mini-repo per language: exact node/edge/mention sets, `file:line` provenance included.
- `graph update` after touching one file re-parses exactly that file (asserted by parse counts) and converges to the full-build result byte-for-byte.
- The no-model-calls property: the code path compiles with no Harness reach (layering grep) and a build over a code-only tree succeeds with zero backends configured.
- Unsupported/unparseable files are named in the report line and counted; the build never fails on one.
- Origin column: every writer stamps it; a mixed graph's `graph stats` shows the extracted/inferred split.

**Acceptance criteria:**
- [ ] `apogee graph build --source lib/src/cli --graph apogee-code` over this repository completes with zero model calls and zero backends configured, and `graph stats` reports nodes, edges, and the extracted/inferred split.
- [ ] `graph show` on a function node lists its callers and callees with `file:line` mentions — **across files**: a call site in one file links to the definition node in another, and an unresolvable name is counted as unresolved, never invented.
- [ ] The full model-free pass on a keyless, backendless, offline machine: build → `update` → `communities` (clustering, summaries reported absent) → `dedupe` (code merges, prose skip reported) all succeed.
- [ ] Touch one file; `graph update` re-parses only it and the graph matches a fresh full build.
- [ ] A directory containing an unsupported language finishes the build, naming and counting the skipped files.
- [ ] Retrieval-time expansion over a code-bearing graph injects code entities under the existing transient budget, labelled with their provenance.
