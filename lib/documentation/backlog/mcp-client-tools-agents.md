# MCP client, in-process native tools + analyze/agents runner (split before build)

**What / why.** The complete tool-extensibility and agent story, guarded here as one coverage item that MUST BE SPLIT into three backlog docs before an agent builds: (a1) the native in-process toolsets — no MCP dependency, gated only on agentloop-core, the permission gate's first real consumer, and where the permissions config schema lands; (a2) the MCP stdio client + mcp CLI + ServeStdio; (b) analyze/agents. (a2): a from-scratch MCP client for stdio servers — JSON-RPC 2.0 framing, initialize handshake, tools/list cached and namespaced mcp__<server>__<tool> (double underscore; tool names contain single ones), tools/call, background read-loop demuxing by id — with disciplined subprocess lifecycle: stderr captured never inherited (8-line tail folded into connect-failure messages), mid-handshake death failing immediately from the read-loop error path rather than waiting out the connect timeout, failed servers logged and skipped never fatal; `apogee mcp create|list|test|enable|disable` with compiled-in scaffolding templates and config-driven registration requiring zero code changes; the in-binary ServeStdio pattern (hidden subcommand) for zero-distribution tools. (a1): Ommi's five bundled Python servers are reimplemented as in-process native C++ toolsets (fs read/write with permission gating, shell, git, notes, plus a native embed/RAG-query tool — the fifth server's role — conditional on embedstore-lexical-rag) registered in the same dispatch chain — a stronger single-binary story with no Python runtime; the MCP client is reserved for genuinely third-party servers. (b): agents as data (prompt files + optional JSON schema + tool policy + model override + optional auto-RAG collection (conditional on embedstore-lexical-rag) + questions opt-in) executed by the shared loop; `apogee analyze --agent <name>` one-shot/interactive with in-process JSON→Markdown rendering (fields alphabetized, human_summary reserved last), quiet auto-save with per-agent subdirs, deterministic branch-review resolution (--branch/--base/--remote/--fetch → three-dot merge-base diffs — plumbing shared with chat's review-context flags, wired into chat when this lands, as in Ommi, plain parameter passing to in-process git tools — simpler than Ommi's env-var side-channel); `apogee agents create|list|edit|delete` through a shared TTY-free scaffold core (the mechanism behind CLI↔HTTP parity for resource creation); bundled agents (security-review, release-notes, merge-request) re-authored for the owned loop with provider-native structured output on any provider and per-agent read-only tool policies replacing claude-CLI permission_mode/--mcp-config forwarding entirely.

**Core constraint(s).**
- No subprocess ever inherits the terminal's stderr on interactive paths; a bounded tail is kept for failure diagnostics (serve mode keeps stderr as the daemon log)
- done/completion signals close from the read-loop error path, not only Close()
- Ref selection is deterministic from flags; free text only focuses attention (reproducible reviews)
- Read-only agents never block on permission prompts; per-agent tool policy IS the permission model; structured callers always strip reasoning
- Bundled prompts/schemas install skip-if-present so user edits survive updates
- Resource creation goes through the shared scaffold core so CLI- and HTTP-made artifacts are byte-identical
- Mutating mcp/agents CLI actions landing before the admin plane exist go into the parity table's documented-skip list; this area owns the agents/MCP CRUD admin backfill

**Seam + files.** lib/src/cli/source/mcp/types.h (JSON-RPC + MCP payloads), lib/src/cli/source/mcp/transport_stdio.cpp (spawn, pipes, stderr sink), lib/src/cli/source/mcp/client.cpp (readLoop, pending-map demux, done-closed-from-error-path), lib/src/cli/source/mcp/registry.cpp (multi-server, Status, ExecuteTool handled=false fallthrough), lib/src/cli/source/mcp/serve_stdio.cpp, lib/src/cli/source/tools/builtin_fs.cpp/_shell.cpp/_git.cpp/_notes.cpp, lib/src/cli/source/commands/mcp_cmd.cpp; lib/src/cli/source/commands/analyze.cpp + agents.cpp, lib/src/cli/source/scaffold/agent.cpp (CreateAgent shared core), lib/src/cli/source/render/json_report.cpp, branch-resolution glue into the native git toolset, bundled prompts/ + schemas/ as skip-if-present install assets; lib/src/cli/tests/mcp/ (fake stdio server fleet: chatty, slow, dying, malformed), lib/src/cli/tests/commands/ (fixture-repo branch tests, schema-conformance tests).

**Reference (Ommi).** src/mcp (Transport interface, Client done-channel fix, Registry stderr-tail, namespacing, ServeStdio), tools/mcp bundled Python servers, cmd/ommi mcp.go/analyze.go/agents.go, src/scaffold CreateAgent, bundled prompts/schemas (Milestones D + E + P stderr lessons, REVIEW.md). **Acceptance criteria:**
- [ ] A scripted stdio MCP server's tools appear namespaced in the loop and dispatch end-to-end; ExecuteTool falls through to built-ins when unhandled; built-ins always work regardless of MCP config
- [ ] A server dying mid-handshake fails in <1s with its stderr tail in the message, not after the connect timeout; a deliberately noisy server's stderr never reaches the terminal and the status line survives (PTY test); connect failures skip-and-log, never fatal
- [ ] Built-in write/delete file tools respect the ask/allow/deny gate; non-interactive ask resolves to deny; mcp create scaffolds a runnable server and mcp test invokes through the production dispatch path
- [ ] analyze runs a named agent end to end (prompt + schema + tools + optional RAG collection), rendering Markdown with human_summary last; saved runs are quiet on TTY, always printed when piped/--json/no target
- [ ] Branch review of an un-checked-out ref produces the correct three-dot diff deterministically from flags; security-review and release-notes run fully local; merge-request runs on any cloud provider
- [ ] 'Nothing found' is a valid complete agent result
