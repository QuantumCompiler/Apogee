# Every place works against a server

**What / why.** The user's vision, 2026-11-07: Apogee is a private, self-hosted harness that feels like Claude on every device the person owns, with one strong machine serving their desktops and phones. 7a gives the app a second way to reach the CLI, the person's own `apogee serve`. This item closes **W4 on the app's side**: every place reads and acts through the **active connection**. Sessions, Models, Suites, Tasks, Training, Knowledge, the Code graph, Video, Voice, Library, Review, Settings, the monitor and the console each run their reads and commands over that connection. A place whose data lives on one machine shows the server's records when it is remote, and a place the server cannot offer says why. iPhone and iPad have no local CLI (8a, 9a), so whatever does not work here does not work on them at all.

Measured 2026-11-07 at `4f92316d`. Each finding is what keeps a place tied to the local binary and the local disk:

1. **Every read and command is "run this binary".** `CommandRunning` (`lib/src/darwin/source/business/reads/CommandRunning.swift:7-22`) takes `binary: URL` in all five of its calls, and `JobStarting` (`business/jobs/SupervisedJob.swift:169-172`) does the same for every long run. 138 single-line call sites in 27 files under `source/` pass a binary (`grep -rnE '(read|command|report|readKeepingStderr|startJob)\(binary:'`, declarations excluded; calls split over lines come on top). The biggest are `SessionLibraryViewModel` and `TrainingViewModel` (14 each), `LibraryViewModels` (12), `SettingsViewModel` (11) and `ModelsViewModel` (10).
2. **Places get a binary, not a connection.** The composition hands each place `sessions.binaryURL` through 18 single-line `connect(binary:)`/`use(binary:)` calls (`presentation/app/ViewModels/AppViewModel.swift:296-313`) and Settings' `connect(binary:version:skippedOverride:)` (`:314-315`). One `JobStarter` is built at `:80` and shared by every place. Each place gets its own `runner ?? ReadRunner()` (20 of them, `:84-176`).
3. **The media places read this Mac's disk, not the CLI.** `MediaLibrary.scan` (`business/media/MediaRecords.swift:175-206`) walks `~/Movies/Apogee`, `~/Music/Apogee` and added folders with `FileManager`. Video (`VideoViewModel.swift:122`), Voice (`VoiceViewModel.swift:90`) and Compose (`ComposeViewModel.swift:120`) draw their libraries from it. A composition's progress is its project file read off disk (`Projects.swift:95-100`). An output name is checked free against the local disk (`MediaRecords.swift:218-241`). Playback is `AVPlayer(url:)` on a local file (`styles/Components/MediaPlayer.swift:21`), and a speech's is `AVAudioPlayer(contentsOf:)` on one (`voice/Views/VoiceScreen.swift:201`). Compose offers a finished composition only once its file exists here (`compose/Views/ComposeView.swift:161`). The CLI has no read for these records. Probe, temp `APOGEE_HOME`: `apogee __complete video ""` answers `generate compose` and `apogee __complete voice ""` answers `say`, with no list verb. The admin plane's routes include none for media either (`reference/cli/http-api.md`, `## Routes`).
4. **Paths come from this device.** 13 `.fileImporter` pickers hand the CLI a path on this Mac: the execute door's folder, a task's folder, an attachment, a graph's folder, an ingest source, a dataset to prepare, an adapter, Video's seed image and added folder, Compose's assets and music, Voice's added folder, and Settings' binary. The other local-path affordances are 5 `NSWorkspace` "Show in Finder" buttons (Video, Compose, Voice, Store, Models), 3 `NSSavePanel`s (graph export and report, knowledge export), `@` completion from the local disk (`business/session/Mentions.swift:16`) and Suites' adapter footprint summed from local files (`SuitesViewModel.swift:167-186`). Library's editor opens and saves the person's own agent and symphony files straight off this Mac's disk (`library/ViewModels/LibraryViewModels.swift:169`, `:185`, `:339`, `:352`), not through the CLI. Probe, temp `APOGEE_HOME`: `apogee __complete agents ""` answers `create list edit delete` and `symphonies` answers `list show create edit delete play`, with no verb that hands a definition's text back or takes it in.
5. **The monitor is this Mac's.** It reads `system` (`monitor/ViewModels/MonitorViewModel.swift:73`) and the app's live children the composition lists (`:81`), with their resident memory from `ProcessMemory` (`:32`).
6. **The parity table has no remote column.** `ParityTable.places` (`presentation/shell/ViewModels/Parity.swift:52-90`, 32 rows: 24 screens, 2 console, 3 carve-outs, 3 plumbing) classifies each command once, for a local binary. Nothing says what `auth`, `bootstrap`, `reset` or `video` mean on a server. Probe, temp `APOGEE_HOME`: the binary at HEAD answers 30 top-level words to `apogee __complete ""`, `acp` among them (5a classifies it). The recorded fixture `tests/presentation/shell/Fixtures/command-words.txt` holds 29, without `acp`.
7. **The server has its own rules, and the app must state them.** Vendor-CLI backends are "never served" (`reference/cli/http-api.md:26`). A key is stored from "loopback peers only" (`:1449`). Nobody answers a permission prompt on a served request today (`:27`), which the CLI's 59b changes for paired devices.

It delivers: every place runs its reads, commands and jobs through the active connection, drawn the same on both connections; the media places show the server's records and play them on this device; each command's remote meaning classified in the parity table; and a place, sheet or button the server cannot serve says so in words, not by failing.

**Core constraint(s).**
- **The anti-goal: nothing here may make standalone use need a server** (GUI SPEC → Non-goals, *No server requirement*; the user's call, 2026-11-07). On the local connection every place runs **the argv it runs today, byte for byte**, against the local binary, and still reads the local disk where it reads it today. The existing suite stays green with no test edited except where it is handed the connection. A Mac with no server configured never shows a remote-only control.
- **Never-listens; serving is the server's** (CLI SPEC → *Interactive = pipes, serving = server*, clarified 2026-11-07). The app opens no socket of its own, and on a Mac with Apogee installed it never connects to a server on its own machine (GUI SPEC → *No HTTP path for local work*).
- **The GUI is a machine-mode client, amended 2026-11-07** (GUI `CLAUDE.md` → *The GUI is a machine-mode client*). A remote place speaks the same protocol over 7a's transport, decodes it as tolerantly and keeps the same honesty. No place gets a second path to a provider, and none reimplements on the device a read the server does not offer.
- **Secrets stay unleakable.** No key travels in a URL, a log or a document. A key is added at the server, as the admin plane already requires (`http-api.md:1449`). The connection's own credential is 7a's and never reaches a view-model.
- **Additive protocol** (the CLI's [ADR 0006](../../../adrs/cli/backwards-compatibility.md)). An older server lacking a read or verb is a stated state of the place, never a failure. The app decides it from what the server says it speaks at connect (its schema, as 4k reads the local binary's), never from a call's failure alone.
- **Parity** (the CLI's [ADR 0002](../../../adrs/cli/mode-parity.md); the GUI's [ADR 0003](../../../adrs/gui/parity.md)). Every command keeps one classified place, and now also a classified remote meaning, held by test. A place drops nothing because it is remote unless the table names why.
- **The layers** ([ADR 0001](../../../adrs/gui/layer-enforcement.md), [ADR 0002](../../../adrs/darwin/presentation-mvvm.md)). The remote-or-local decision for a place lives in its view-model (SwiftUI-free), so the iPad and iPhone apps (8b, 9a) reuse it unchanged. Where the media records come from is Business (`media`). Nothing below Presentation imports AppKit, so 8a's iOS build is not made harder.
- **The dev channel** (GUI `CLAUDE.md` → *Development runs on the dev channel*; M18). A live pass runs a development app against `apogee-dev serve` over a temp `APOGEE_HOME` with a mock backend, never the release `apogee` or `~/.apogee`. Until M18 ships, there is no live pass of a development build on the user's machine.

**Seam + files.** Planned. The connection type and its transport are 7a's; this item makes every place use them.
- `source/business/reads/CommandRunning.swift`, `source/business/jobs/SupervisedJob.swift` — reads, commands and jobs addressed to the active connection, not a `binary: URL`. On the local connection this is today's `ReadRunner` and `JobStarter`, unchanged. On a remote one it is 7a's runner over the server's reads and commands (CLI 59d).
- `source/presentation/app/ViewModels/AppViewModel.swift` — `connect(binary:)` becomes `connect(_ connection:)` at `:296-315`. A change of connection re-reads every place, as a changed binary is re-asked today (GUI 4k, `:215-217`).
- Every place's view-model under `source/presentation/<place>/ViewModels/` — sessions, session, models (Models, Store, Downloads, DeletePlan), suites, tasks, training, knowledge (Records, Collections), graph, library, review, video, compose, voice, settings, monitor, console. Each gains its remote state: which acts it offers there and the reason for any it does not.
- `source/business/media/MediaRecords.swift`, `Projects.swift` — `MediaLibrary`'s records from one of two sources. Locally, the folders, as today. Remotely, the server's read (open call below). Playback and Show in Finder take what the record's source can give.
- `source/presentation/library/ViewModels/LibraryViewModels.swift` — the editor reads and writes a definition's file only on the local connection. Remotely it goes through the server's read and write, or is not offered (open call below).
- `source/presentation/shell/ViewModels/Parity.swift` — `CommandPlace` gains its remote meaning (open call below). The console's refusals are drawn from it for a remote connection.
- `source/presentation/styles/Components/` — one shared "not on this server" state (the reason, and the server's version where that is the reason), promoted on its second use (ADR 0002).
- Tests, hermetic (scripted connection fakes and recorded documents; no binary, no server, no network): each place's suite under `tests/presentation/<place>/` gains remote cases over the existing `ScriptedRunner`/`ScriptedJobs` fakes keyed by connection. Media gains `tests/business/media/` source cases. `tests/presentation/shell/ParityTests.swift` gains the remote column's law. Recorded server documents go in each place's `Fixtures/`, captured by a planned `scripts/capture-server-fixture.sh` (modelled on `scripts/capture-fixture.sh`): `apogee-dev serve` over a temp `APOGEE_HOME` and the mock backend, run deliberately, never by a test.
- Docs: GUI `DEVELOPER.md` (each place's remote behavior), the `CLAUDE.md` Codebase Map, and ADR 0003's addendum for the remote column.

**Decisions made** (dated):
- 2026-11-07: Specced from the Apple-platforms spike and brainstorm. The user's calls:
  - The vision: a private, self-hosted harness that feels like Claude on every device the person owns, served by their own strong machine (e.g. 512 GB of RAM and a finely tuned large model). Apogee mimics frontier harnesses (Claude Code, Codex, Gemini CLI, Ollama, vLLM) with local models. Paid features are a someday, not now. No customer accounts, billing or metering; the server admits the person and their devices only.
  - Where the work happens is C: server tools by default, and a connected desktop offers its own files and shell, like Claude Code. When the Mac points at a server and is asked to change a project on the Mac, the Mac's files are the ones touched. That is 7b's, through a session's device tools on the Mac. This item's place commands act on the server's data, and no place sends a path on this Mac to the server as if it were the server's.
  - Remote is an add-on, never the only way the app runs. The CLI alone, and the Mac app over pipes to a local CLI, stay complete and the default.
  - The SPEC amendment is approved and written: the GUI reaches the CLI over stdio, or over an authenticated connection to the person's own `apogee serve`.
  - iPhone and iPad are clients of the server only, with no on-device core. The Mac and the CLI stay standalone.
  - v0.3.0 is the target for macOS, iPadOS and iOS (the iPhone, and the foldable iPhone in both its folded and unfolded screens) working fully, reached in successive versions. Windows and Android follow v0.3.0 (a recorded default).
- 2026-11-07: In v0.2.4, track 7, beside 7a and 7b. It needs 7a's connection, and 7a needs the CLI's network reads and sessions (59b, 59d, v0.2.3). It must land before 8a/8b (v0.2.5): the iPad and iPhone apps are remote-only, so a place that does not work remotely is a place they do not have.
- 2026-11-07: Gated on CLI 59e as well as 7a. Tasks is the place a connection's loss hurts most: a remote run must be found and followed again after reconnecting or from another device, and only 59e makes a server task outlive its connection.

**Open calls:**
- (consumed decision) 7a: the connection's type, its transport, pairing, how the person picks local or a server, and the runner and job starter over it. This item takes them as 7a defines them.
- (consumed decision) CLI 59d: which reads and commands the server carries and refuses, and how a server job is listed. This item draws the server's word, never its own guess.
- (consumed decision) 7b: on the Mac, a remote session's `@`, attachments and folder can be the Mac's own, through device tools.
- [default: **the parity table's remote column.** Each `CommandPlace` gains one remote meaning:
  - `onServer`: it runs on the server, against the server's data.
  - `onServer(here:)`: it runs on the server, and a named part happens on this device (an export saved here, a clip played here).
  - `notRemote(reason:)`: not offered on a server, said with the reason.

  The carve-outs stay carve-outs, their reasons naming the server. Proposed classification: chat, chats, execute, models, config, check, providers, system, task, bootstrap (said as installing on the server), knowledge, embed, train, datasets, agents, mcp, symphonies, review, analyze and complete are `onServer`. graph, video and voice are `onServer(here:)`. version is both (the app's, a local binary's if any, and the server's). auth is `onServer` for its list and clear, while adding a key is `notRemote` ("a key is added at the server itself", as `PUT /v1/admin/auth` already requires). acp is `notRemote` (a host on this machine spawns it over stdio). tui is the window on either connection (`onServer`). serve, reset and uninstall are `notRemote`, their reasons naming the server ("run it at the server's own prompt"). Of the plumbing, `__machine-schema` and `__complete` are `onServer` (the server's schema read at connect, its completion asked by the console's Tab and the path fields), and `__mcp-tools` is `notRemote` (a stdio server a client spawns on its own machine). Held by test: every row has a remote meaning, every `notRemote` has a reason, and the column agrees with the server's command list from a recorded fixture.]
- [default: **media records when remote** come from the server through a read of its records: `video.generation`, `voice.speech` and `video.project` documents, the same objects `MediaLibrary.scan` reads today. That needs a CLI read, which does not exist (finding 3). If 59d does not carry it when this item is taken, a CLI sibling is queued, gated both ways. Until it lands, the remote Video and Voice places say "this server doesn't list its media yet" and still run generate, compose and say as jobs on the server. Added folders are this device's and are not offered remotely.]
- [default: **remote playback** fetches the output through the connection into the app's own cache, plays it there, and clears the cache when the connection changes. Show in Finder is not offered for a server's record; Save to this device… is. If the transport carries no file fetch, the record shows its details and says playback needs the file here.]
- [default: **paths when remote.** A sheet that names a path for a command (a graph's folder, an ingest source, a dataset, an adapter, Compose's assets and music, a seed image) takes a path **on the server**: typed, with path completion through the server's `__complete` where it completes one, not this device's open panel. The three save panels save, on this device, the document the server returned. Settings' binary picker is the local connection's alone. The execute door's folder on this Mac is 7b's (a server session opened in a granted folder). A remote task's folder is a path on the server. A folder on this Mac is not offered to a remote task, since a task outlives the connection and the Mac's files are reached only while a session holds 7b's grant; the sheet says so and names the two ways it can be done: a server session opened in that folder (7b), or the task on the local connection.]
- [default: **Library's editor when remote** reads and writes a definition's text through the server, where the server carries such a read and write (59d, or a CLI sibling queued beside the media read). Until then, editing is not offered for a server's agents and symphonies, said in one line; list, create, delete, show and play still run on the server. It never opens a server path on this device's disk.]
- [default: **Settings splits by owner.** The app's own settings (appearance, text size, the connection, the binary override) are always this device's. Every pane over `config`, `check`, `providers`, `auth` and `bootstrap` reads and writes the server's when remote, its header naming the server.]
- [default: **the monitor when remote** reads the server's `system`. It lists the jobs this device started over the connection, and the server's running jobs where 59d lists them. Resident memory per child is shown only for local children.]
- [default: **a connection change** re-reads every place before it acts (4k's rule) and stops nothing on the server. A remote job or task keeps running and is found again on return. A local child is still ended only by the person's Stop or by quit, as today.]
- [default: **Sessions' backends when remote** are the server's `models list`. An entry the server will not serve (a vendor CLI, `http-api.md:26`) is drawn in the server's words and not offered to chat.]
- [default: **an older server** missing a read or verb shows the shared "not on this server" state, naming the server's version, decided from what it said it speaks at connect.]

**Guardrail(s).**
- The local connection is byte-identical: each place's existing recorded argv and documents pass unchanged, held by the current suites run on the local connection.
- Each place has remote cases over a scripted connection and recorded server documents: its reads, one command, one job, a `notRemote` act's reason, and an older server's state.
- The parity law gains the remote column: every row classified, every `notRemote` with a reason, and the column checked against a recorded server command list.
- `MediaLibrary`'s two sources are pinned: folders locally, the server's documents remotely. A remote record never calls `FileManager`.
- No remote view-model touches `FileManager`, `NSWorkspace` or an open panel, Library's editor and Suites' footprint included. The layering check stays green, and Business and Data stay free of AppKit.
- No key field appears in any remote document, log or URL in the tests.

**Acceptance criteria:**
- [ ] Pointed at a server, each place (Sessions, Models, Suites, Tasks, Training, Knowledge, Code graph, Video, Voice, Library, Review, Settings, the monitor, the console) shows the server's data and runs its acts there, each act's result read back from the server.
- [ ] Video and Voice list the server's clips, compositions and speeches and play them on this device. Without the server's media read, they say why and still generate.
- [ ] A task started remotely is followed again after the connection drops and returns (59e).
- [ ] Each act the server cannot do (adding a key, Show in Finder, a remote task in a folder on this Mac, editing a definition before the server carries it, an older server's missing verb) says why in words, and none of them fails silently.
- [ ] The console run against a server runs and completes there, refusing by the table's remote column.
- [ ] With no server configured, the Mac app behaves exactly as before: the full suite is green with every local test unedited beyond the connection hand-off.
