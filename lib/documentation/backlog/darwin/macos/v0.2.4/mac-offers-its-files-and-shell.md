# The Mac offers its own files and shell to a server session

**What / why.** The user's vision, 2026-11-07: Apogee as a private, self-hosted harness that feels like Claude on every device the person owns, with one strong machine serving the person's own desktops and phones. The user's call on where the work happens: **server tools by default, and a connected desktop offers its own files and shell**, as Claude Code's are. When the Mac points at the person's server and the person asks it to change a project on the Mac, the files that change are the Mac's. The CLI's [60b](../../../cli/v0.2.4/device-tools.md) makes that a protocol: a server session may call tools that a connected device runs. This item is the Mac's side of it. The person grants a folder per project, the Mac runs the server's calls there, and the Mac asks about each one in the session window on the permission card a local session already uses.

The wall, W6 (the app side of device tools), re-measured 2026-11-07 at `4f92316d` (the branch binary `apogee 0.2.0 (4f92316d, 2026-11-07, macos-arm64)`, a scratch `APOGEE_HOME`, the mock backend):

1. **No driver can run a tool today.** The schema the binary prints (`apogee __machine-schema`, schema `2026-11-01`) lists the lines a driver may write: `user`, `answer`, `attach`, `hello`, `cancel`, `detach`, `set` and `compact`. None of them returns a tool result. Every tool runs inside the child, in the child's working directory. The app sets that directory when it starts a session (`source/business/session/ApogeeClient.swift:78`, applied at `source/infrastructure/process/ProcessSpawner.swift:82-83`). `hello`'s `wants` list is sent (`ApogeeClient.swift:83`), but it "changes nothing in this release" ([machine-mode.md](../../../../reference/cli/machine-mode.md), `:633-642`).
2. **The server refuses tools from a client.** The probe sent one `tools` entry to `serve` on the mock and got `{"error":{"message":"client-side tools are not supported: the server runs its own tool loop and returns only the final answer (tool_mode selects it)","type":"invalid_request_error"}}` (`presentation/httpserver/handler.cpp:648-652`; [http-api.md](../../../../reference/cli/http-api.md) `:86`). Served tools run on the server only, and "nobody can answer a permission prompt on a served request" (`:27`). So a Mac pointed at a server today cannot let the server's model touch the Mac's files.
3. **The card is already there; nothing feeds it from a server.** The `question` event's `kind`, `tool`, `target`, `outbound` and `detail` decode into `Question` (`source/data/protocol/ProtocolEvent.swift:270-294`). The transcript appends a `PermissionCard` (`source/presentation/session/ViewModels/Transcript.swift:465`, the type at `:691`). `PermissionCardView` draws the tool, its whole target, a diff for an edit, and "Leaves this machine: …" for outbound data (`source/presentation/session/Views/PermissionCardView.swift:10`, `:33`). The answers are `yes`, `session`, `always` and `no` (`source/business/session/MachineSession.swift:157-161`), with ⏎ and esc bound to them (`source/presentation/shell/ViewModels/KeyMap.swift:117-118`). Every one of these cards comes from the local child's own gate.
4. **The app has no grant.** A folder is picked with `fileImporter` and becomes a session's working directory (`source/presentation/sessions/Views/ExecuteDoor.swift:84`). Nothing records that a folder was offered to anyone. The app is not sandboxed: the project has no entitlements file and no `ENABLE_APP_SANDBOX` (`Apogee.xcodeproj/project.pbxproj`), so a granted path needs no security-scoped bookmark today.
5. **The CLI's shell takes any folder.** The filesystem tools resolve every path inside their root after following links, and compare by path components (`business/tools/fs.cpp:195-231`, `is_within` at `:34-43`). But `run_command` accepts any directory as its `cwd` (`business/tools/shell.cpp:237-243`), and any command can reach past any folder. A device shell therefore needs its `cwd` held inside the grant and every command asked. Holding the `cwd` is 60b's job, on the CLI side. Asking about every command is this item's.

It delivers: a grant per project, made in the session window when a session on a server opens in a folder on the Mac; the Mac's device tools offered only to a server session that holds a grant; each device call run by the Mac's own local `apogee` in that folder and asked about on the same card, marked **On this Mac**; the grants listed in Settings with Revoke, which takes effect at once; and nothing offered when the session is local.

**Core constraint(s).**
- **The anti-goal: nothing here may make standalone use need a server.** The server is an add-on (the user's call, 2026-11-07; [SPEC](../../../../assistant/gui/SPEC.md) → Non-goals, No server requirement). With no server configured, the app, its sessions and its tests stay byte-identical. **Device tools are never offered while connected locally**: a local session's child already runs in its folder (`ApogeeClient.swift:78`) and already has the files.
- **The GUI is a machine-mode client** (GUI [CLAUDE.md](../../../../assistant/darwin/CLAUDE.md) → The GUI is a machine-mode client, as amended 2026-11-07). The Mac implements no tool. A device call runs on the Mac's own `apogee` binary, as a child over stdio. That child reads, edits, diffs and runs commands with the CLI's code, under the CLI's gate. The app relays the call and the answer, and draws the card.
- **The Mac decides; the server asks.** Serving is the server's job and the files are the Mac's. The server's say is never consent. Each card is raised by the Mac's own device child, which the app spawned, and is answered on the Mac. A call that arrives without a grant, or on a local session, is refused unrun.
- **The Mac never listens** (the CLI's Interactive turns never open a listening socket; SPEC → No HTTP path for local work). Device calls arrive over the Mac's outbound connection to the server, which is 7a's. The device child is a pipe child of `ProcessSpawner`, which spawns every `apogee` child (`source/infrastructure/process/ProcessSpawner.swift`; the app's only other spawn is `LoginShell`'s one bounded ask for the login shell's `PATH`, M6, `source/infrastructure/process/LoginShell.swift:122-141`).
- **What leaves the machine is asked about** (the CLI CLAUDE.md's egress invariant). A device read sends the file's bytes to the server, so a read is asked about as well. The card's existing "Leaves this machine" line names what would leave and where it goes.
- **Secrets are unleakable** (the CLI CLAUDE.md). A grant can never cover the Apogee homes (`~/.apogee`, `~/.apogee-dev`), their `secrets/`, or the app's own preferences. The protocol carries no key field.
- **Additive** (the CLI's [ADR 0006](../../../../adrs/cli/backwards-compatibility.md)). The Mac offers device tools only to a server whose `capabilities` announce them (60b's word, read as `MachineSchema` reads `accepts`: `source/data/protocol/MachineSchema.swift:19-22`, `:43`). An older server sees no new line. An older app ignores device events through its tolerant decoding. The server never depends on an offer.
- **Parity** (the CLI's [ADR 0002](../../../../adrs/cli/mode-parity.md), the GUI's [ADR 0003](../../../../adrs/gui/parity.md)). The Mac offers exactly the tool set a terminal client offers under 60b, built from [60a](../../../cli/v0.2.4/one-tool-definition.md)'s one definition, in the same words. The device child's verb gets its row in the `ParityTable`.
- **The layers** ([ADR 0001](../../../../adrs/gui/layer-enforcement.md), [ADR 0002](../../../../adrs/darwin/presentation-mvvm.md), [ADR 0004](../../../../adrs/darwin/module-schemes-and-previews.md)). Grants live in Data, the relay in Business and the views in Presentation. Every state a person sees differently gets a named preview.
- **The dev channel** (GUI CLAUDE.md → Development runs on the dev channel; [M18](../maintenance/app-dev-channel.md)). A development build keeps its grants in its own settings domain, runs `apogee-dev` as its device child, and makes its live passes against an `apogee-dev serve`, never the release `apogee` or `~/.apogee`.

**Seam + files.**
- `source/data/protocol/` — `ProtocolEvent.swift`, `EventDecoder.swift`: a device call decoded as 60b's wire states it (its id, the tool, its arguments, the session it belongs to). `DriverLine.swift`: the device-tools offer (its folder name, never its absolute path, unless 60b asks for one) and the result, error or withdrawal sent back.
- `source/data/preferences/Preferences.swift` — `DeviceGrants`: one grant per server and folder (the server's paired identity from [CLI 59a](../../../cli/v0.2.3/paired-devices.md), the folder's path, when it was granted). Kept one per line, as the other path lists are (`Preferences.swift:115-123`).
- `source/business/device/` (new module `BusinessDevice`, with its line on the Business layer card) — `DeviceToolHost`: for each server session that holds a grant, it starts one device child of the local binary in the granted folder (60b's verb), registered with `ChildRegistry` (`source/business/jobs/ChildRegistry.swift:14`). It relays each device call to the child and the child's `question` events to the session window, sends the child's result back over 7a's connection, and stops the child when the session ends, when the grant is revoked, or when the app quits. It refuses a call when the session is local, when no grant is held, or when the server's capabilities never announced device tools.
- `source/business/session/` — the session's start: when the session is on a server and opened in a folder, it asks for the grant or uses one already held, then sends the offer. A local session never reaches this code.
- `source/presentation/session/` — the grant sheet at a session's start ("Let <server> work in <folder> on this Mac"), the card labelled **On this Mac** (`PermissionCardView` reused; `always` hidden on a device card), and device tool lines marked "on this Mac" in the transcript.
- `source/presentation/settings/` — a **This Mac** pane listing each grant (server, folder, date) with Revoke.
- `source/presentation/shell/ViewModels/Parity.swift` — the device child's verb classified as a carve-out ("run by the app for a server session, not a person's command").
- Tests (hermetic: scripted fakes, recorded documents, no binary, no network, no window): `tests/business/device/` (a scripted server connection from 7a's fake transport and a scripted device child, in the style of `tests/business/session/FakeApogee.swift`); `tests/data/protocol/` (the device events and lines against a recording of the real device child, captured by `scripts/capture-fixture.sh` as 1b's `mock-actor.jsonl` was); `tests/data/preferences/` (grants kept, keyed and revoked, on the dev domain); `tests/presentation/session/` and `tests/presentation/settings/` (view-model tests for the sheet, the card and Revoke); `tests/architecture/layering` (the new module).
- Docs: the GUI `CLAUDE.md` (the machine-mode rule's state of play: device tools are relayed, never implemented), `DEVELOPER.md` (trying device tools on the dev channel), the Business layer card.

**Decisions made** (dated):
- 2026-11-07: Specced from the Apple-platforms spike and brainstorm (the user's calls: Apogee a private, self-hosted harness that feels like Claude on every device the person owns, a strong machine serving the person's own desktops and phones, mimicking frontier harnesses with local models; **C**, server tools by default and a connected desktop offering its own files and shell, so a Mac pointed at a server and asked to change a project on the Mac touches the Mac's files; remote and server mode an add-on, never the only way the application runs, the CLI alone and the Mac app over pipes staying complete and the default; iPhone and iPad clients of the server only, the Mac and the CLI standalone; the approved SPEC amendment, already written: the GUI reaches the CLI over stdio locally, or over an authenticated connection to the person's own `apogee serve`, so device calls ride the Mac's outbound connection and the Mac never listens; no paid features now, so a grant is the person's own, with no account and nothing metered).
- 2026-11-07: In v0.2.4 (GUI track 7), gated on 7a and CLI 60b. It needs the Mac's connection to a server and the CLI's device-tool wire first. It lands before the iPad and iPhone work (v0.2.5, v0.3.0), because the Mac is the only one of the three platforms whose files a server session changes, and because v0.2.4 carries the one tool definition (60a), which the user placed before v0.3.0.

**Open calls:**
- (consumed decision) The wire — how a device call, its result and a withdrawal travel; the tool set offered; how the server's side gates and holds the root; the device child's verb — CLI [60b](../../../cli/v0.2.4/device-tools.md).
- (consumed decision) The connection, its transport, and how a session knows it is local or on a server — [7a](../../v0.2.4/app-connection-local-or-server.md). Which devices the server admits — CLI [59a](../../../cli/v0.2.3/paired-devices.md).
- [default: the Mac runs device tools only through its own local binary on its channel (`apogee`, or `apogee-dev` on the dev channel). With no local binary there is no offer, and the session says why, naming the install line.]
- [default: every device call is asked about, reads included, because a read sends the file to the server. The answers are `yes` (once), `session` (this tool, for the rest of this session) and `no`. `always` is not offered on a device card, because it would write `permissions.<tool>: allow` into a config ([machine-mode.md](../../../../reference/cli/machine-mode.md) `:923-926`), and the grant is the standing consent.]
- [default: the grant is made by the person when a server session opens in a folder: a sheet with Allow and Not now, remembered per server and folder. A server never prompts for one. A session without a grant still runs, on the server's tools.]
- [default: a grant is refused for `/`, the home folder itself, and any folder that is or contains `~/.apogee` or `~/.apogee-dev`, with the reason in one line.]
- [default: Revoke takes effect at once. The session's device child gets `cancel` and then the registry's stop, the server is sent the withdrawal, a standing card closes as unanswered, and a later call is refused with "this Mac no longer offers <folder>".]
- [default: one device child per server session that holds a grant, its working directory the granted folder, ended with the session and on quit.]
- [default: iPhone and iPad offer no device tools (no shell, and their files sit in the app's container). Their apps never show the grant sheet or the This Mac pane.]
- [default: a grant is kept as the folder's path. No security-scoped bookmark is needed while the app is unsandboxed; one is added if the app is ever sandboxed.]

**Guardrail(s).** The device host's table: a local session never offers and refuses a stray device call; a server session without a grant, or whose server never announced device tools, sends no offer; a granted session relays a call to the child, the card to the window and the result to the server. A denial reaches the server as a tool result. Revoke stops the child and withdraws the offer. The refused-folder cases (`/`, home, a folder holding `~/.apogee`). The recorded device-child stream pins the decoder. A no-server run of every existing session test passes unchanged. The layering check covers `BusinessDevice`. A named preview of the sheet, the card **On this Mac** (read, edit with its diff, command), the This Mac pane empty and full, and a revoked grant.

**Acceptance criteria:**
- [ ] Over a scripted server connection that announces device tools, a session opened in a granted folder asks before each device call on the **On this Mac** card. `yes` runs the call on the local device child in that folder and returns its result to the server; `no` returns a denial the model reads.
- [ ] A local session, a server session without a grant, and a server that never announced device tools each get no offer, and a device call that arrives anyway is refused unrun.
- [ ] Revoke in Settings → This Mac, during a session, ends that session's device child and withdraws the offer, and the next call is refused in one line.
- [ ] A grant of `/`, the home folder or a folder holding `~/.apogee` is refused, and says why.
- [ ] With no server configured, the app behaves as it does today: no new sheet, pane row or line. The full suite (`lib/scripts/cicd.sh --app darwin --test`) and the layering check are green.
- [ ] The user's live pass, optional and said: an Apogee Dev app, pointed at an `apogee-dev serve` on another machine of theirs, edits a file in a granted project on the Mac after a yes on the card, and the server's machine is left untouched.
