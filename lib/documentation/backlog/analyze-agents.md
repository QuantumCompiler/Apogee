# `apogee analyze` and agents as data: per-agent tool policy, structured output on every provider, and the bundled review agents

**What / why.** An **agent** is a named workflow the user runs with `apogee analyze --agent <name> [input]`: a system prompt assembled from prompt files, an optional JSON Schema its answer must satisfy, a **tool policy** that is also its permission model, an optional model override, an optional collection retrieved from on every turn (the `auto_rag` mechanism, read from the agent instead of the top-level key), and an opt-in to `ask_user`. Agents are **data** — entries under `agents:` in `config.yaml` plus files under `prompts/` and `schemas/` — executed by the **same shared loop** every other surface runs, so an agent behaves identically on every backend the loop drives. `analyze` runs one-shot (positional text, `--input <file>`, or stdin) or `--interactive` under the agent's persona; **structured output** is asked of the provider natively where the API has it and validated client-side always, with one corrective retry; a JSON answer is rendered to Markdown **in-process** (top-level fields alphabetised, the reserved `human_summary` last, no second model call); a saved run is quiet on a terminal (one `Saved: <path>` line, to stderr) and always printed when piped, `--json`, or unsaved, into `analyses/<agent>/` with a timestamp that has no colons. **Branch review is deterministic from flags**: `--branch`/`--base`/`--remote`/`--fetch|--no-fetch` become plain parameters the git toolset's `git_diff` uses as its defaults (a three-dot merge-base diff, fetching an absent ref on demand) plus a one-line system note, so a small local model never parses a ref out of a sentence and free text only focuses attention; `chat` gets the same flags and a `/branch` command, from the same plumbing. **`apogee agents create|list|edit|delete`** go through a TTY-free scaffold core that the admin plane's `/v1/admin/agents` routes call too, so an agent made over HTTP is byte-identical to one made on the command line. **Three bundled agents** — `security-review`, `release-notes`, `merge-request` — are re-authored for the owned loop: read-only tool policies (so a non-interactive run never blocks on a prompt), calibrated so that *"nothing notable found" is a complete, valid result*, installed **skip-if-present** so a user's edits survive updates, and runnable on any provider — including fully local for the first two. What Ommi could only do by forwarding `permission_mode`/`--mcp-config` to the `claude` CLI, Apogee does in its own loop for every backend.

**Core constraint(s).**
- **Per-agent tool policy IS the permission model.** `tools: read-only` registers only tools that declare no `writes` — nothing to prompt for, so a read-only agent never blocks, on any surface. `tools: all` puts the agent under the same gate as `chat` (config levels; `ask` denies where nobody can answer). A policy is enforced by **what is registered**, never by asking the model to behave.
- **Structured callers always strip reasoning.** The answer handed to the validator and renderer is the loop's final answer with every reasoning block removed by the profile filter — the rule Apogee already keeps for persisted history, restated for the parse path.
- **Ref selection is deterministic from flags; free text only focuses attention.** The refs reach the tool as parameters and the model as a note; the model cannot change which diff is reviewed.
- **One config mutation path** (`agents:` entries through new `config_edit` transforms), **one layout declaration** (`prompts/`, `schemas/`, `analyses/` are rows; bundled prompts and schemas are compiled in and materialised skip-if-present by the one seeding path, `apogee check --fix`, so both installers get them for free), **parity is the product** (every mutating `agents` subcommand has its twin in the same item; `analyze` and `agents list` are read-only rows).
- **Resource creation goes through the shared scaffold core**, so CLI- and HTTP-made agents are byte-identical — the config entry and the files.
- **Nothing links `apogee`; the harness never includes backends.** The structured-output request field is plain IR in `harness/types.h`; each wire translates it; `agentloop/` and the new `render/` and `scaffold/` packages include no backend.
- **Secrets hygiene.** A saved report is derived data, never a secret; nothing here logs a key. Forge credentials are out of scope with the forge itself.
- Code Style: `.h`/`.cpp` pairs, smart pointers only.

Divergences: **the tool policy lives in the owned loop for every backend** — Ommi's `access_internet`/`access_local_mcp`/`only_native` were inert on its Claude backend and its only per-agent lever there was `permission_mode`/`dangerously_skip_permissions` forwarded to the CLI, both of which Apogee drops entirely; **structured output is provider-native and client-validated** where Ommi's `analyze` never used its `--json-schema` seam and trusted the prompt; refs are **parameters**, not environment; the `merge-request` agent ships in **branch mode** (diff + ADRs from a collection) with its forge mode deferred; the `qa-plan`/`state-diagram`/`exterminator` agents ride the connector decision and are not ported; the save filename carries no colon; `save_subdir` is settable by `agents create`; `check` validates every bundled asset, not three of six; bundled schemas are validated as JSON Schema, not by substring.

**Decisions made** (dated):
- 2026-08-24 — Planned from Ommi's documentation; agents are authoring on top of the tool story, so they come after it.
- 2026-09-13 — **Split out of `mcp-client-tools-agents` at grooming** as the third of three, gated on the native toolsets and the MCP client: a read-only policy is a filter over registered tools, so the tools have to exist; the bundled agents use the git and fs toolsets and, optionally, a collection.
- 2026-09-13 — **The forge-backed mode of `merge-request` is deferred**, with the forge credential slots the credential store deferred here. The forge target (GitHub, GitLab, or both) is the user's call and gates a follow-on item recorded on the roadmap; the branch-review mode in this item does not wait on it.
- 2026-09-13 — **The renderer is in-process.** Ommi's reason holds: a second model call to prettify a report costs money, time and fidelity for a transformation a hundred lines of code do deterministically.
- 2026-09-13 — **Structured output is validated client-side, always, with one corrective retry.** Provider-native modes reduce the retry rate; they do not replace the check, and a report that still does not conform is delivered raw and flagged rather than dropped.

**Open calls:**
- [user] Whether `analyze` may run on a vendor-CLI backend (`claude-cli`, `codex-cli`, `gemini-cli`, `ollama-cli`). Those CLIs run their own tools outside Apogee's gate, so a `read-only` policy cannot be enforced there and the loop sees no tool calls; the plan's default is to **refuse them by type with the reason**, as `serve` does — which keeps review agents off the subscription plans. The alternative is allowing them under `tools: none` only, with the CLI's own tool restrictions as the safety, which is exactly the forwarding this item set out to retire.
- [default: JSON Schema validation via the nlohmann-family validator, fetched and pinned] *(the guard document's recorded default, taken)* `pboettch/json-schema-validator` sits on nlohmann/json, which is already the project's JSON library; a hand-rolled validator would be a second implementation of draft-07.
- [default: local models get prompt-level JSON, not a grammar] The pinned llama.cpp subtree carries no JSON-Schema-to-grammar converter (it lives in `common/`, which Apogee does not build); the validator and retry cover it, and a grammar-constrained mode is a later upgrade behind the same request field.
- [default: Anthropic uses the structured-outputs request field where the model supports it, else a forced tool] The forced-tool pattern is universal on the Messages API and the fixture can prove both paths.
- [default: filenames are `<base>-YYYYMMDD-HHMMSS.<ext>`] Ommi's `15-04-05:01-02-2006` put a colon in a filename; Windows is a target.
- [default: `analyses/` is a layout row, not lazily created derived data] A declared directory is seeded and doctor-checked like every other; Ommi's lazy `reviews/` was the one directory outside its install-parity check.

**Guardrail(s).** The renderer: `human_summary` last and everything else alphabetical, nested depth, arrays of objects, and raw passthrough on unparseable input. Structured output on each cloud wire fixture (the schema on the wire, the forced-tool fallback's arguments taken as the answer) and the validator's retry path (a non-conforming first answer, a conforming second; two non-conforming answers delivered raw with `conforms: false`). The policy filter: a `read-only` agent's registry contains no `writes` tool and the loop advertises exactly that set; `none` advertises nothing; an agent with `questions: false` never sees `ask_user`. Branch review against the fixture repo: two non-HEAD branches, the default base, a remote-only branch fetched under `auto`, `never` refusing with the reason, and the model's own `target` argument losing to the flags' defaults only where the prompt says to call with none. The quiet-save truth table. The scaffold: byte-identical config from CLI and route, files left on disk when the config write fails (with the error surfaced), duplicates refused without `--force`, `--purge` removing files. Bundled assets: compiled-in texts byte-equal to the shipped files; every schema valid draft-07 with `additionalProperties: false` and a trailing required `human_summary`; skip-if-present proven by editing a prompt, re-seeding, and reading the edit back. `cli.install_parity` sees the three new rows. `cli.analyze_lifecycle` on the real binary, on the mock backend, end to end. `cli.machine_schema_conformance` pins any new machine-mode event; `cli.http_api_conformance` the new routes. All mutation-tested.

**Acceptance criteria:**
- [ ] `apogee analyze --agent <name>` runs a named agent end to end — prompt files, schema, tool policy, optional collection — on any API-billing or local backend, rendering Markdown with `human_summary` last; the saved run is quiet on a TTY and always printed when piped, `--json`, or unsaved
- [ ] A `read-only` agent never prompts and never blocks on any surface; an `all` agent is gated exactly like `chat`
- [ ] A schema-bound answer is provider-native where the API has it and client-validated always; a non-conforming answer gets one corrective retry and is otherwise delivered raw and flagged
- [ ] `--branch`/`--base`/`--remote`/`--fetch` review an un-checked-out ref as the correct three-dot diff, deterministically from the flags, on `analyze` and `chat`; free text changes nothing about which refs are compared
- [ ] `agents create|list|edit|delete` work through the shared scaffold core, and `POST /v1/admin/agents` produces byte-identical files and config
- [ ] `security-review` and `release-notes` run fully local; `merge-request` runs in branch mode on any cloud provider; "nothing found" is a valid, complete result for all three; user edits to a bundled prompt survive a re-seed
- [ ] `prompts/`, `schemas/` and `analyses/` are declared once in the layout; `check` reports the `Agents` section; every mutating `agents` subcommand is a twin in the parity table

**Scope note.** Gated ring; its gates are satisfied: the native toolsets shipped 2026-09-13 ([MILESTONES.md](../assistant/MILESTONES.md) → Milestone V) and the MCP stdio client the same day (Milestone W). Everything else it needs has shipped too: the shared loop and `ask_user` (Milestone F), model profiles and the reasoning filter (Milestone P), `auto_rag` and collections (Milestones Q–S), the admin plane (Milestone U), the config editor and the layout declaration. Out of scope: the forge-backed `merge-request` mode, ticket lookup, and the forge credential slots (a follow-on item gated on the user's forge-target decision, on the roadmap); the connector-driven `qa-plan`/`state-diagram`/`exterminator` agents (they ride remote MCP transports and OAuth, also on the roadmap); an `agent-creator` conversational agent; grammar-constrained local output; a second model call for rendering (never).
