# /v1/admin foundation: bearer auth, events bus, jobs, first CRUD, parity test + provider credential store

**What / why.** The control-plane substrate for **remote clients in server deployments** (revised 2026-08-24: the local GUI does NOT use this plane — it powers the CLI over stdin/stdout per the [machine-mode protocol](../reference/machine-mode.md), shipped 2026-09-06; serve/admin apply only when the executable runs on a server and mobile/desktop clients make REST calls to it), plus the provider credential store Apogee's direct-API design makes central (Ommi delegated Claude auth to the CLI; Apogee must own it). Admin plane: lazily-created 0600 admin token with constant-time bearer comparison (header-only, never query string) and fail-closed non-loopback bind (refuse to start without --allow-remote-admin), a process-wide pub/sub events bus (bounded queues, drop-on-slow) feeding a /v1/admin/events SSE stream with heartbeat, an in-memory async job registry (202+job_id, poll, cancel via std::stop_token, finish/fail no-ops after leaving running), and the first CRUD slices — backends and role-pointer setters routed through the exact config-engine helpers the CLI uses so an HTTP edit is byte-identical to a CLI edit — landing the table-driven CLI↔HTTP parity test that makes the invariant machine-checked from the first mutating route. Credential store: a 0600 JSON slot file beside the config with per-provider slots (Anthropic/OpenAI/Google keys — **API-billing providers only**: CLI-type backends authenticate through their own vendor CLIs, and their credentials are never stored, read, or proxied by Apogee), a metadata view type that structurally has no key field (leak impossible by construction), env-override precedence snapshotted once at process init, an `apogee auth add|list|clear` CLI (hidden prompt/--stdin/--from-env; list shows metadata only), one shared key resolver — decision (2026-08-24): config api_key (which may itself be ${ENV}-expanded) > stored slot > ambient conventional env (ANTHROPIC_API_KEY etc.), snapshotted once at init. This deliberately diverges from Ommi's git-token env-always-wins convention: a multi-backend config can point different backends at different keys, and ${ENV} expansion already covers env-driven config; revisit if it surprises, and the loopback-peer rule (getpeername, never a forwarded header) on any secret-accepting HTTP route. MUST be split into two backlog docs at grooming — doc A: the admin plane (auth/bind, events bus, jobs, first CRUD, the parity table); doc B (gated on doc A, since secret-accepting routes need the auth/bind machinery): the provider credential store, including the key-resolution retrofit into the three cloud backends built earlier. Both halves' invariants are recorded here. Follow-on admin slices are owned by the feature areas that own their CLI actions and land as backfills once doc A exists: the embeddings data plane (embedstore area), the models plane (shipped 2026-09-07; `models pull`/`delete`/`repair`/`quantize` are the mutating routes needing twins), agents/MCP CRUD (mcp area), and the datasets plane (training area). Until each backfill lands, those actions sit in the parity table's documented-skip list — the parity test must enumerate them, never skip them silently.

**Core constraint(s).**
- Once this foundation exists, every mutating CLI action ships an admin twin in the same PR through the same shared cores/helpers; mutating surfaces that landed earlier are enumerated backfills in the parity table's documented-skip list (documented carve-out: expensive/destructive ops like future training control stay CLI-only); new mutating CLI actions are designed with clean request/response shapes so the endpoint is a thin wrapper (Ommi's v0.2.0 standing rule, adopted from day one)
- Secrets are unleakable by type construction, not discipline: serialized metadata types have no secret field; body-only intake; never in any response, event, or log
- Env credential precedence snapshotted once at process init (two env writers on one process race)
- Loopback-peer judged from the socket address (getpeername), never a forwarded header, on any secret-accepting route
- Admin bearer token: header-only, constant-time compare, 0600 on disk; config reloaded fresh from disk per admin request so CLI and API always agree
- Per-install secrets are install-parity-exempt but presence+mode checked by the doctor

**Seam + files.** lib/src/cli/source/httpserver/auth.cpp (token create/compare, bind policy), lib/src/cli/source/events/bus.h/.cpp, lib/src/cli/source/httpserver/jobs.cpp (registry + cancellation), lib/src/cli/source/httpserver/events.cpp (SSE fan-out + heartbeat), lib/src/cli/source/httpserver/admin_config.cpp (backends CRUD + default setters), lib/src/cli/source/secrets/store.h/.cpp (per-provider slots, 0600 file, Metadata type, env snapshot at init), lib/src/cli/source/commands/auth_cmd.cpp, key-resolution integration in lib/src/cli/source/commands/helpers.cpp, lib/src/cli/tests/httpserver/parity_test.cpp (the CLI↔HTTP table), admin_auth_test.cpp (bind matrix), lib/src/cli/tests/secrets/ (leak-grep tests).

**Reference (Ommi).** src/httpserver auth.go/admin.go/jobs.go/events.go, src/events, src/scaffold, test/cmd/parity_test.go, and src/gitlab (two-slot 0600 store, token-free Metadata by construction, requireLoopbackPeer, env-snapshot-at-init — OMMI-9's race lesson). **Acceptance criteria:**
- [ ] Requests without/with-invalid bearer get 401; token compare is constant-time; token file is 0600; non-loopback bind without the flag refuses startup (full bind×flag matrix tested)
- [ ] An HTTP add-backend produces a config file byte-identical to the CLI's on the same starting file — the parity invariant's first end-to-end proof
- [ ] An async job streams admin.job.* events over SSE and cancels cleanly; a cancelled job can never be overwritten to failed
- [ ] parity_test enumerates every mutating CLI action and asserts its admin route exists or is a documented carve-out
- [ ] Keys stored via `apogee auth add` are used by backends without appearing in config; `auth list` and every error/log/response path show metadata only (grep test across surfaces); env precedence is snapshotted once — mutating env mid-process cannot change resolution; secret-accepting routes 403 non-loopback peers regardless of bind
- [ ] Key-resolution retrofit (doc B): the anthropic/openai/google backends resolve keys through the shared resolver under the decided precedence, covered by the existing backend fixtures
