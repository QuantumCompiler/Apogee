# Fine-tuning runs: train, eval, promote, and rollback

**What / why.** The run itself — the piece the placeholder says "does not port": a LoRA/QLoRA fine-tune of a full-weight SafeTensors snapshot executed by a **Python trainer subprocess** (`mlx_lm` on Apple Silicon, `transformers`/`peft`/`trl`/`bitsandbytes` on CUDA) under a **C++ orchestrator** that owns everything around it. `apogee train run <student> --dataset <name|path> [--method lora|qlora] [--iters 1000] [--batch-size 4] [--num-layers 16] [--grad-checkpoint] [--mask-prompt] [--trainer auto|mlx|peft|mock]` takes a SafeTensors snapshot (a directory under `paths.hf_dir` or `models/`, or a path holding `config.json` and `*.safetensors`; a GGUF or a backend name is refused naming `models pull --safetensors` — **only full-precision weights are trainable**), picks the trainer (`auto`: macOS/arm64 → `mlx`, `nvidia-smi` on PATH → `peft`, else a refusal naming both), spawns the driver under the venv, and turns its **JSONL progress protocol** into the status line — `iter n/N · loss · lr · it/s` — recording a manifest under `training/runs/<run-id>/` when it finishes: `run_id`, `trainer`, `base_model`, `dataset` and its sha256, the hyperparameters, `final_loss`, `adapter_dir`, `status` (`complete` | `failed` | `cancelled`) and timestamps. The protocol is a **tested contract on both sides**: the C++ parser against a golden fixture, and the shipped `train_mlx.py`/`train_peft.py` emitters run under stub `mlx_lm`/`transformers` modules so no ML stack is needed to prove they speak it. Three of Ommi's silent failures are closed by the contract: an `{"error"}` line is its own event rather than a blank progress tick, a non-JSON line is a message rather than dropped, and the child's exit code is carried, so **a crashed trainer is a failed run, never a silent success**. `apogee train eval <run-id> [--suite <path|name>] [--judge <backend>] [--force]` gates the adapter: a suite is `{prompt, expected?}` JSONL (a kit's inline eval, `datasets prepare --as-eval`, or hand-written under `training/suites/`); an item with `expected` is a deterministic **substring** check; one without is a **pairwise judge** comparison of the candidate against **its own untuned base** through the same adapter-only candidate runner (the question that matters — did the adapter help — rather than Ommi's comparison against `models.default`), the judge's `A`/`B`/`TIE` parsed with anything else a tie, and a judge or baseline failure a tie under the **never-fail contract** the rerank judge already keeps; without a judge such items `skip` and auto-pass — loudly, with the count. **The gate is 100%** (`score` reported, `passed` only when every item passed), and the results land in the manifest. `apogee train promote <run-id> --as <backend> [--force] [--quantize TYPE]` is the only path from a run to inference: the eval gate (hard by default; `training.gate_mode: soft` demotes it to a warning; `--force` skips it), **fuse** the adapter into the base (`runs/<id>/fused/`, SafeTensors), **convert** to GGUF with the vendored `convert_hf_to_gguf.py` under the venv's `convert` set into `training/versions/<backend>/v<N>.gguf` (F16; `--quantize` through the in-process quantizer when the binary links llama.cpp), **verify** the header with the GGUF reader before any config is touched, then **register** through the one config editor — a new `llamacpp` entry, or the existing entry's `model_path` replaced in place, comment-preserving and byte-exact — and append the **version ledger** entry (`training/versions/<backend>.json`: `active_version`, `{version, run_id, gguf_path, promoted_at, eval_score, eval_passed}`), with `retain_versions` pruning the oldest inactive GGUFs. Version numbers come from `max(version) + 1`, never from the count — Ommi derived them from `len(versions)`, so numbers regressed after the first prune and a later promote overwrote a live file. `apogee train rollback <backend>` repoints `model_path` to the previous version (which must still exist — a pruned one is refused by name) and deletes nothing; `train versions <backend>` and `train status` read the manifests and ledgers — the filesystem is the source of truth, nothing is cached. Over HTTP **training is read-only**: `GET /v1/admin/training/status|runs|runs/{id}|versions` under the admin bearer, and every control action is a documented parity **carve-out** — an expensive GPU job with live progress is not a control surface a remote client should be able to start.

**Core constraint(s).**
- **Only SafeTensors snapshots are trainable; GGUF is an inference-only promotion artifact.** A GGUF, a backend name, or a snapshot without `config.json` is refused naming the fix.
- **Training control is CLI-only over HTTP, forever.** `train run|eval|promote|rollback|setup` are carve-outs in the parity table with the reason; reads are served under `/v1/admin/training/*`. Nothing under `httpserver/` can start, promote or roll back a run.
- **A failing candidate never reaches inference.** Promote runs the gate first; the GGUF is written and its header verified before the config is touched; a failure at any step leaves the config and the ledger unchanged.
- **The JSONL progress protocol is a tested contract** — parser and both emitters — and `{"error"}`, non-JSON lines and the exit code are each distinct outcomes.
- **The drivers carry the environment guards verbatim**: `train_peft.py`'s Apple-Silicon hard-exit before any other import (bitsandbytes calls `abort()` inside C-extension init, which no `try` catches), the two `setdefault`s and the offline variables before the first ML import in both — grep-tested.
- **One config mutation path**: the appended entry and the in-place `model_path` replacement are `config_edit` transforms with byte-exact tests; nothing in `training/` writes the config.
- **The spend rule is inherited**: the judge is named explicitly (`--judge` or `training.judge_backend`) or absent — never the metered default silently; a vendor-CLI judge is refused by type. The trainer is local by nature.
- **No listening socket**: the drivers are children over pipes; nothing here opens a port (`cli.no_listen_symbols` unchanged).
- **One layout declaration**: `runs/`, `versions/`, `suites/` beneath the existing `training` row, created by first use; no new row.
- **Model-free domain core**: `training/` includes `harness/`, `platform/`, `agentloop/`, `agent/` and itself, with the two named allowances; the judge arrives as a closure; `commands/train.cpp` is the composition root that resolves backends and edits the config.
- Tests hermetic: the mock trainer for every orchestration test; the real scripts only under stub modules on bare `python3`, skipped by name where absent; the converter never run in a test.
- Code Style: `.h`/`.cpp` pairs, smart pointers only.

**Decisions made** (dated):
- 2026-09-19 — **Split out of `training-distillation` at grooming** as the second of three, gated on the datasets item for the venv, the script runner, the datasets and the kits' eval suites (all shipped 2026-09-19).
- 2026-09-19 — **The C++↔Python protocol is tested on both sides** with stub modules, and `{"error"}`, non-JSON lines and the exit code are distinct outcomes — the contract-level requirement the placeholder set, with Ommi's three silent gaps recorded as the reason.
- 2026-09-19 — **The converter is vendored from the pinned llama.cpp revision** and runs under the venv's `convert` set: the default build does not fetch llama.cpp, and a converter that exists only when the local backend is linked would make promotion a build-flag feature.
- 2026-09-19 — **The mock trainer ships in the binary** (`--trainer mock`), producing a minimal valid GGUF at promote, so the real binary's lifecycle test covers the whole chain without Python — the `mock` backend type's precedent.
- 2026-09-19 — **Promote registers a plain `llamacpp` entry; there is no `tuned` flag.**

**Open calls:**
- [default: the pairwise baseline is the untuned base through the same candidate runner] Ommi compared against `models.default`, an unrelated model; the adapter-versus-base question is the one promotion asks.
- [default: F16 GGUF; `--quantize TYPE` only when the binary links llama.cpp, else refused naming `apogee models quantize`] The in-process quantizer already exists behind that flag.
- [default: `retain_versions: 3`; `0` keeps all] Ommi defaulted to keep-all and documented 3; multi-gigabyte files argue for a bound the user can lift.
- [default: the fused checkpoint is removed after a successful conversion unless `--keep-fused`] A fused SafeTensors tree is as large as the base model and the GGUF is what promotion keeps.
- [default: promoted GGUFs under `training/versions/<backend>/v<N>.gguf`] Beside the ledger, inside the private row; `models list` shows them through their backend entries.
- [default: read routes under `/v1/admin/training/*`, bearer-gated] Ommi's were unauthenticated `/v1/training/*`; local training state belongs to the control plane.

**Guardrail(s).** Trainer contract: the mock emits exactly `iters` events with the total and a falling loss, cancel mid-stream terminates cleanly, a trainer error surfaces from `train`, capabilities. Protocol: the golden fixture parsed event by event; `{"error"}` an `Error`, a non-JSON line a `Message`, an empty line skipped, the exit code and stderr tail on the outcome; `train_mlx.py --mode train|fuse|infer` and `train_peft.py` likewise run under the stub modules emitting the fixture's shapes, `train_peft.py`'s missing-deps error and — on macOS arm64 — its hard-exit as the first line, the guard-before-import grep on both. Selection: `auto` on each host shape, an unknown name refused, a GGUF and a backend name refused naming `--safetensors`. Manifests and the store: round trip incl. `status`, newest first, an unknown id. Eval: contains pass/fail, judge pairwise with the tie semantics and the never-fail contract, `skip` auto-pass reported with the count, a candidate error aborting, `--force` re-running, a vendor-CLI judge refused, a named metered judge allowed. Promote: hard/soft/`--force` gate, fuse exactly once, the converter invoked with the venv interpreter (scripted runner), an unparseable GGUF leaving config and ledger untouched, append versus in-place `model_path` **byte-exact on two copies of the shipped template**, `max + 1` after a prune (Ommi's regression pinned), retention never pruning the active version, `--quantize` refused without llama.cpp, `--keep-fused`. Rollback: no history, one version, a pruned target, the repoint deleting nothing. `versions`/`status` rendering. HTTP: every read route with its `404`, `[]` not null, behind the gate; every control subcommand a carve-out whose route does not exist (a `POST` to any training path is not `200`); `cli.http_api_conformance`. `check` rows. `cli.train_lifecycle` on the real binary with `--trainer mock`: `datasets create` from the template, `train run` writing a manifest with the status line seen, `train eval --suite` with substring items passing against the mock's echo, `promote --as` registering the entry byte-exactly and writing `v1.gguf`, a second promote `v2` and `rollback` to `v1`, `versions`, `status`, `check` green throughout. All mutation-tested.

**Acceptance criteria:**
- [ ] `train run` fine-tunes a SafeTensors snapshot through the selected driver with live progress and a manifest; GGUF and backend names are refused; a crashed driver is a failed run
- [ ] The JSONL progress protocol is a contract tested against the parser and both shipped emitters; the environment guards are grep-tested
- [ ] `train eval` gates at 100% with substring and pairwise-judge items under the never-fail contract, recorded in the manifest
- [ ] `train promote` fuses, converts, verifies, registers through the one config editor and appends the ledger with `max + 1` versioning and retention; a failing candidate never reaches config; `rollback` repoints and deletes nothing
- [ ] Training reads are served under `/v1/admin/training/*`; every control action is a parity carve-out with its reason and no route
- [ ] `check` reports the trainer, the converter set and every ledger's consistency
