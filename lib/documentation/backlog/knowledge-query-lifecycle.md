# Knowledge query, lifecycle, export, and the HTTP draft → refine → store contract

**What / why.** The second slice of the knowledge layer: getting records back out, keeping them true over time, sharing them, and the review flow a GUI needs. `apogee knowledge query "<text>"` returns the records that best answer the question through the **one per-turn retriever resolver** (lexical with no model, vector, or hybrid — reported, never assumed), **defaulting to `--status shipped`** so a query never returns an abandoned idea's rationale as the reason something exists (`--status ""` searches every branch, `--status rejected` asks what was considered and dropped); status and discipline filter over metadata **before** the top-k cut so a filter never starves the result; `--rerank` judges records on the same immutable index text the retrievers matched, under the never-fail contract. `list` (newest first, filterable), `info <id> [--raw]`, `link <id> <ref>` and `status <id> <shipped|rejected|superseded>` (metadata edits in place — never a re-embed, because the index is built only from the immutable reasoning), `delete <id>` (the record and its raw archive), `export [--format json|markdown] [--anonymize] [--status] [--discipline] [--out FILE]` (a re-importable JSON array or a Markdown report grouped by status; `--anonymize` strips attribution AND the machine-local `raw_ref` while preserving `source`, `downstream_link` and `supersedes` — names off, chain on; raw conversations are never included), and `reindex [<id>]` (re-embed after an embedding-model change; vector-only by design — lexical needs nothing; warns on a mixed collection). Over HTTP the bearer-gated `/v1/admin/knowledge` family gains list/query, get, patch, delete and reindex, and — the part a GUI actually needs — a **stateless capture → review → store flow**: `POST /v1/admin/knowledge/capture` with `"draft": true` runs the clerk and returns the normalized, validated record with an empty `id`/`timestamp` and no `raw_ref` (the HTTP twin of `capture --dry-run`, nothing stored); `POST /v1/admin/knowledge/refine` `{record, instruction, raw, model}` runs **one bounded revision pass** under a dedicated compiled-in refine prompt — apply the instruction, change nothing else, stay grounded in `raw`, never invent — and returns a new draft in the same shape, never storing; the reviewed draft is then stored through the **existing** finished-record `POST /v1/admin/knowledge` with `raw` attached. The server holds no draft between calls; the draft lives with the client. Because the store step is the ordinary finished-record route, a draft → refine → store round trip lands a record **field-equivalent to a one-shot capture** — provable, not aspirational. The refine loop is HTTP/GUI-only by design: a CLI user re-runs `capture --dry-run` with different flags or input (Ommi's documented parity skip, kept).

**Core constraint(s).**
- **The refine loop is stateless server-side.** No draft is ever held by the server; refine touches nothing but the draft it was handed; the instruction is non-empty and at most 2000 codepoints (`400` otherwise — the source material belongs in `raw`, not the instruction); `supersedes` is not a clerk field and is carried through untouched; a `provenance.source` the clerk drops keeps the draft's value rather than a default.
- **One retriever per turn, resolved once, reported honestly** (consumed decision): `query` and the `GET ?q=` route resolve through `resolve_turn_retriever` with the collection's pin and the embedder's facts; an explicit `--retriever vector` that cannot run is a hard error naming lexical; every response carries the retriever that ran; rerank never costs results silently — `reranked` is set from the same place as the ordering.
- **Archive rich, surface thin** (consumed): `export` never includes raw conversations; `--anonymize` drops `raw_ref` too (it leaks the local username and is useless to a recipient); the index is never rebuilt by a metadata edit.
- **Parity is the product.** `link`, `status`, `delete`, `reindex` are mutating and get twins in this item (`PATCH`, `DELETE`, `POST …/reindex`); `query`, `list`, `info`, `export` are read-only rows; **refine is not a mutating action** (it stores nothing) and is recorded as an HTTP-only counterpart rather than a parity gap.
- **Capability gates are honest**: `501` for capture/refine on a server with no generation backend, `501` for a vector query or reindex with no embedding backend (with `?retriever=lexical` named as the way out), `502` for a clerk revision that is not a schema-conforming record.
- **Secrets hygiene**: `raw` travels in a request body only and is never echoed in an error; the raw archive is read by `info --raw` and never by a listing route.
- Code Style: `.h`/`.cpp` pairs, smart pointers only.

**Decisions made** (dated):
- 2026-09-13 — **Split out of `knowledge-graph-stack` at grooming** as the second of four, gated on `knowledge-records`: it reads the store and the clerk that item builds.
- 2026-09-13 — **The refine loop is stateless and HTTP-only** *(Ommi's recorded decision, kept)*: the draft is the client's; the store step is the existing finished-record route so the round-trip equivalence is a test, not a hope; the CLI's half is `--dry-run`, and a CLI user iterates by re-running it.
- 2026-09-13 — **`query` defaults to `--status shipped`** *(Ommi's, kept)*: the branch marker is the single most important guard in a brainstorm-based corpus.
- 2026-09-13 — **A metadata edit never re-embeds**: the vector's bytes are asserted unchanged across `link`/`status`; only `reindex` rewrites vectors, and only when asked.

**Open calls:**
- [default: `--top-k` 5 for `query`, the judge widening to the shared fetch limit] Ommi's terminal default; the HTTP route's 20 was a GUI page size and is the widened pool here.
- [default: `export --format markdown` groups by status in the order shipped, rejected, superseded, then any other] Ommi's `RenderMarkdown`.
- [default: `PATCH` takes exactly one of `link` or `status` per call] One edit, one intent, one audit line.

**Guardrail(s).** Query: the resolver table applied to records (lexical with no embedder, vector with a matching store, an explicit vector refusal, hybrid reported lexical without a vector half), the status filter defaulting to shipped and applied before the cut (a collection whose top hits are rejected still returns shipped ones), `--status ""` crossing every branch, discipline filtering, rerank applied and reported with `reranked` from the ordering. Lifecycle: `link`/`status` leave the vector bytes identical, `delete` removes the raw file, `reindex` rewrites vectors under a new model and leaves the archive, a mixed collection warns first. Export: `--anonymize` strips attribution and `raw_ref` and keeps `source`/`downstream_link`/`supersedes`; the raw conversation never appears in either format; Markdown groups by status. Refine: the prompt shares the schema and names the three sections; the user message carries exactly the six schema fields and calls out an absent raw; the instruction cap counts codepoints; the guards fire **before** any clerk call (a fake clerk counts its invocations); `supersedes` and a dropped `source` carry through; a bad revision is a `502`. **The round trip**: draft → refine(no-op instruction) → `POST /knowledge` lands a record field-equivalent to a one-shot capture of the same raw, with the clerk run exactly twice; the footprint helper reads unchanged after the draft and after the refine and changed once after the store. `501` on a mux with no generation backend for capture and refine; `401` without a token. Parity rows (`link`/`status`/`delete`/`reindex` twins; `query`/`list`/`info`/`export` read-only). `cli.knowledge_lifecycle` extended on the real binary: capture two records on different branches, `query` returns the shipped one by default and the rejected one on request, `status` flips without touching the vector, `export --anonymize` has no attribution and no `raw_ref`, `info --raw` prints the archive. All mutation-tested.

**Acceptance criteria:**
- [ ] `knowledge query` returns the best-matching records through the one retriever resolver, defaults to shipped, filters before the cut, reports the retriever, and reranks under the never-fail contract
- [ ] `list`, `info --raw`, `link`, `status`, `delete`, `export --anonymize`, `reindex` work; a metadata edit never re-embeds; an anonymized export keeps the provenance chain and never includes a raw conversation
- [ ] `POST …/capture {draft: true}` stores nothing and returns an id-less record; `POST …/refine` runs one bounded revision (instruction ≤ 2000, guards before the clerk) and never stores; a draft → refine → store round trip is field-equivalent to a one-shot capture
- [ ] `GET/PATCH/DELETE /v1/admin/knowledge/{id}`, `GET ?q=`, and `POST …/reindex` exist, honest `501`s for missing capabilities; every mutating subcommand is a twin in the parity table
