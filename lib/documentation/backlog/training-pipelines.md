# Pipelines, regimes, and the continuous cycle

**What / why.** The orchestration layer over runs — the part of Ommi's stack that is pure control flow and ports to C++ whole. **Pipelines** teach several skills in sequence without forgetting: `apogee train pipeline run --pipeline <path|name> [--continue-on-fail] [--judge] [--trainer]` runs a spec (a YAML file, or a `training.pipelines:` entry) of ordered stages, each a fresh LoRA on top of the previous stage's **fused** weights — stage 0 from the snapshot, every passing intermediate stage fused into a concrete SafeTensors checkpoint (`runs/<id>-s<N>/fused/`) the next stage trains from, never a stack of raw adapters, and the final stage left unfused for `promote` — gated by a **cumulative eval suite**, the union of every prior stage's suite plus its own, so a stage that improves its task but regresses an earlier one fails. A stage may rehearse (`rehearsal_fraction`: a deterministic sample of every prior dataset mixed into its own). The run's manifest under `training/pipelines/<id>/` is rewritten on every transition (`pending` → `training` → `evaluating` → `fusing` → `passed` | `failed`; the run `running` → `complete` | `aborted` | `failed`), the stage runs are ordinary runs `<id>-s<N>` carrying `parent_run` and `pipeline_run_id` so `train eval` and `promote` can target one directly, `pipeline resume <id>` continues from the first stage that has not passed (refusing a complete run or a spec whose stage count drifted), and `pipeline status <id>` prints the table with the promote command for the last passing stage. **Regimes** are the distillation workflow in one command: `apogee train regime run [<name>] [--teacher] [--student] [--kit …] [--all-kits] [--as] [--count] [--iters] [--temperature] [--max-tokens 4096] [--judge] [--no-promote] [--trainer] [--regime <file>]` — for each kit the teacher synthesises a dataset through the datasets item's core (parallel, rate-limited) into `training/regime/<id>/<kit>.jsonl` and the kit's inline eval is materialised beside it, the kits become one eval-gated pipeline (per-stage defaults from each kit's `train:` block, cumulative gates across skills), and the last passing stage is promoted as `--as` unless `--no-promote`; a regime is ad-hoc from flags, a `training.regimes:` entry, or a spec file, flags always overriding. **The cycle** is unattended, scheduler-invoked training: `apogee train cycle run [--source <dir>]` is one gated pass meant for launchd or cron (no daemon, no `--watch` — Ommi's rule kept), guarded by a PID lock and the **circuit breaker** (`halted`, or `consecutive_fails ≥ circuit_breaker_k`), collecting from the configured sources — a `directory` queue of `*.jsonl` (`training/cycle/queue/`, or `--source`), and `sessions`, the user's own persisted chats, **only with `log_consent: true`** and only sessions newer than the watermark the last cycle recorded, so a conversation is never trained on twice — merging them, running the named pipeline with every stage's dataset overridden and its own suite kept, then applying the **anchor-baseline dual gate**: the final stage's cumulative score must not regress beyond `regression_threshold` against the last passing cycle **and** against the pinned anchor (set automatically on the first passing cycle, or `anchor_version`), because per-cycle no-regression alone lets tiny regressions accumulate into drift. Pass promotes into `training.cycle.backend`, moves consumed queue files to `consumed/`, resets the fail count; fail discards the candidate — **nothing reaches inference** — and counts toward the breaker; no data records `skipped`. `cycle status` shows the history and the anchor, `cycle halt` sets the flag, and `cycle resume` clears it — the edit Ommi made by hand in `history.json`. `train status` grows the cycle and pipeline lines; over HTTP `GET /v1/admin/training/cycle` and the pipeline kind under `/runs` are the reads, and every control action is a carve-out.

**Core constraint(s).**
- **Cumulative gates are the pipeline's contract**: stage N is gated on the union of suites 0..N; a stage passes only at 100%; the final stage is never fused automatically.
- **No raw adapter stacking**: every intermediate stage trains from a fused checkpoint.
- **The cycle's dual gate and circuit breaker are the safety**: a candidate must clear both the last passing score and the anchor within the threshold; `k` consecutive failures halt the loop until `cycle resume`; a failing candidate never reaches inference (the promote item's gate runs again inside the cycle).
- **Session sources require explicit `log_consent: true`**, refuse otherwise naming the key and the two risks (privacy, self-reinforcement), and advance a watermark so no session is consumed twice.
- **Training control is CLI-only over HTTP**: `pipeline run|resume`, `regime run`, `cycle run|halt|resume` are carve-outs; the reads are served.
- **One lock, one state file**: `cycle/cycle.lock` (PID, `O_EXCL`) and `cycle/history.json` written atomically (`.tmp` + rename); the filesystem is the source of truth.
- **The spend rule is inherited**: the regime's teacher and every judge are named explicitly; a vendor-CLI entry is refused by type.
- **One layout declaration**: `pipelines/`, `regime/`, `cycle/` beneath the `training` row, created by first use; no new row.
- **Thin orchestration**: pipelines call the run item's trainer, eval and promote cores; regimes call the datasets item's synth core and the pipeline; the cycle calls the pipeline and promote. No second copy of any of them.
- Tests hermetic: the mock trainer and the `mock` backend as teacher and judge; no scheduler, no network.
- Code Style: `.h`/`.cpp` pairs, smart pointers only.

**Guardrail(s).** Pipeline: stage 0's base is the snapshot and stage 1's is `s0/fused`; a stage regressing on an earlier suite fails the cumulative gate leaving the run `aborted`, the stage `failed`, later stages `pending`; `soft` and `--continue-on-fail` complete with mixed statuses; `fuse` called exactly once for a two-stage run; resume runs only the unpassed stages and finishes `complete`, refuses a complete run and a drifted spec; rehearsal mixing deterministic across runs; stage manifests carry `parent_run` and `pipeline_run_id`; the manifest rewritten on every transition; cancellation leaves `aborted`. Regime: flag precedence over a named and a file spec, `--all-kits` alphabetical with `--kit` winning, every validation refusal (unknown teacher/student, no kits, a bad kit), synth wired through the core with the kit's eval materialised, one stage per kit with the kit's `train:` defaults, promote of the last passing stage and skipped under `--no-promote`, a vendor-CLI teacher refused. Cycle: the lock exclusive, released, re-acquirable; the breaker at `k`, on `halted`, disabled at `0`; the directory source ignoring non-`.jsonl`, creating a missing queue, empty cleanly; the sessions source refused without consent, honouring the watermark and the filters, skipping a blank side; no data recording `skipped` without counting a failure; merge skipping blank lines; **the six anchor-gate cases** (no data, pass, within threshold, fail-prev, fail-anchor, strict); pass promoting, consuming, setting the anchor on the first pass, resetting fails; fail counting and halting at `k`; `halt` and `resume`; the history atomic (a crash mid-save leaves the old file). Config: the three sections parsed, every load-time refusal. HTTP: the cycle route and its `404`, pipelines under `/runs`, every control subcommand a carve-out with no route; `cli.http_api_conformance`. `check` rows. `cli.train_lifecycle` extended with `--trainer mock`: a two-stage pipeline whose second suite regresses ending `aborted`, `resume` after the suite is fixed ending `complete`; a regime over two kits with the `mock` teacher and `--no-promote`; a cycle from a queue directory gating and promoting, a second run `skipped`, a forced failure tripping the breaker at `k=1` and `cycle resume` clearing it. All mutation-tested.

**Acceptance criteria:**
- [ ] `train pipeline run|resume|status` run ordered stages from fused checkpoints under cumulative 100% gates, leave the final stage unfused, and resume from the first unpassed stage
- [ ] `train regime run` distils a named teacher across kits into an eval-gated pipeline and promotes the last passing stage unless told not to
- [ ] `train cycle run` performs one locked, breaker-guarded, dual-gated pass from its sources; sessions need explicit consent and are consumed once; a failing candidate never reaches inference; `halt`/`resume` work
- [ ] Every control action is a parity carve-out with its reason; the cycle and pipeline reads are served; `check` validates the cycle configuration
- [ ] `train status` rolls up cycle, pipeline, runs and versions
