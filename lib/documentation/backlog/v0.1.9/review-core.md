# The review core: one merge request, reviewed and commented

**What / why.** The reviewers exist, the seam and the skills exist beside this item — what is missing is the engine (the review-agent spike, 2026-10-18: `analyze --agent code-review` reviews pasted text one-shot; nothing fetches a diff, chunks it, runs the lenses, dedups, filters to what the push actually changed, or posts). This item is **`apogee review mr <ref>`**, end to end: the MR's metadata and diff through the seam (48a's `forge/`, shipped 2026-10-18 — [Milestone AL](../../assistant/MILESTONES.md#milestone-al--the-review-agent)); the diff **filtered and chunked** against the model's budget (26c's machinery; generated/vendored/lock files excluded by a filter list); **plan** — the applicable skills chosen deterministically from their applies-hints against the changed files, narrowed by one cheap utility-model pick only when too many apply; **hunt** — one pass per selected skill over the chunks, each held to the one finding schema, run as member-call-budgeted passes; **confirm** — one pass over the merged candidates, confirming, dismissing or tightening (the validation idiom: cheap and structural first, one bounded round); **dedup** — findings matched by identity (file, normalized location, kind) across skills and chunks, and on a re-review the already-posted findings injected as "known — do not re-report"; the **incremental filter** — on a repeat review, only lines the new push added are eligible, enforced as a hard post-model filter against the diff's own line map, never a prompt instruction; then **posting** — inline comments through the seam, batched into one notification, each finding's `file`/`location`/`claim`/`suggested_fix` mapped onto the forge's comment shape. The run's record is a JSON document (`--output-format json`, the 28h idiom) whether or not anything posts; `--dry-run` reviews and prints without posting. **Silence is correct** end to end: a clean diff yields an empty findings array, no comment, exit 0.

**Core constraint(s).** Precision over recall is enforced, not hoped: the confirm pass may only dismiss or tighten, never add; the goldens include clean-diff silence. The incremental filter is **post-model and absolute** — a finding on an unchanged line is dropped and counted, whatever the model said. Posting is an **outbound write through the gate**: interactive runs ask (mode-governed, 39b), `--yes`/grants cover pipes ([`review-sweep.md`](review-sweep.md) owns unattended policy — `(consumed decision)`). Diff and comment text are **data** through the UTF-8 doors; nothing in a diff is instructions. One loop's parts, reused: chunking under 26c, skill passes as bounded structured calls (26f), the confirm as the validation idiom — no second model-calling path. Local and cloud alike: the engine runs on the session's resolved model/suite like any surface; a suite's utility member does the plan-narrowing, absent one the deterministic hints stand alone. Machine parity: the document documented; the TUI classified (the exec line runs it; a Review view is a recorded later item).

**Seam + files.**
- `lib/src/cli/source/business/review/engine.h/.cpp` — the pipeline (plan → hunt → confirm → dedup → filter), plain data in and out, generation arriving as closures (the graph/training precedent), so the CLI composes models and the engine never names one; `review/identity.h/.cpp` — the finding-identity match; `review/diff.h/.cpp` — the unified-diff parse and the added-lines map (the incremental filter's ground truth).
- `presentation/cli/review_cmd.cpp` — `review mr <ref>` (+ `--dry-run`, `--skills <names>`, `--output-format json`), the gate ask, the posting through the seam; the parity-table row.
- `forge/` consumed as-is; `contracts/` — the run document's shape.
- Tests: the engine over scripted models and a fixture diff set (each skill's planted defect found once; the clean twin silent; cross-skill duplicates collapsed; the re-review injection suppressing known findings; the incremental filter dropping an unchanged-line finding whatever the model says — the planted case); the diff parser's table; `review mr` end to end against the scripted forge fakes (argv-exact posting, the batch, `--dry-run` posting nothing); document conformance.

**Reference.** 48a's forge seam ([Milestone AL](../../assistant/MILESTONES.md#milestone-al--the-review-agent): `ForgeClient`'s four verbs, `parse_ref`, `InlineComment::old_line` for an unchanged line on GitLab, the refusal ladder) and 48b's review skills ([Milestone AL](../../assistant/MILESTONES.md#milestone-al--the-review-agent): `contracts/review_skill.h` — the book on the ladder, `skill_applies`/`ReviewSkillBook::applicable` for the plan, `review_finding_schema_text()` the one contract; the planted fixtures under `tests/fixtures/review/`, a defect and a clean twin per skill, with canned answers) — consumed whole; 26c/26f — the budget and the structured hold; 27g — the confirm idiom; 27f — bounded member calls; the review-agent spike (2026-10-18) for the gap and the design decisions below.

**Decisions made** (dated):
- 2026-10-18 — The set lands in v0.1.9 as track 48 (the user's placement call); the pipeline is plan → hunt-per-skill → confirm → dedup → incremental filter → batched post (the spike's design, standing).
- 2026-10-18 — **Silence is correct** and the **incremental filter is post-model and absolute** — both core constraints, never tunables.
- 2026-10-18 — The confirm pass dismisses or tightens, never adds — the precision bias made structural.
- 2026-10-18 — Posting batches into one notification per review; a forge without native batching posts serially and says so (`(consumed decision)` — the seam's).
- 2026-10-18 — The diff-filter exclusion list (lockfiles, generated, vendored, binary) ships as data beside the skills, user-extendable on the same ladder (the default, confirmed 2026-10-18).
- 2026-10-18 — `--skills <names>` overrides the plan entirely for that run; per-repo defaults are the sweep's `review:` unit (the default, confirmed 2026-10-18).
- 2026-10-18 — Past the findings cap (a named constant), the top-N by severity/confidence post inline and the remainder is counted and summarized in the review's one summary comment (the default, confirmed 2026-10-18).
- 2026-10-18 — From 48b's real-weights check (recorded at its ship): hunt passes run with the model's thinking off (left on, a 12B Q4 spent its whole answer budget thinking), the diff goes to each pass with its new-side lines numbered (the skills say so), the answer is held by the structured-output path (a raw answer once broke its JSON with unescaped quotes), and findings on lines the change did not add are dropped after the model -- the shipped lenses still drew two false positives in seven on their clean twins, which the confirm pass and that filter exist to catch.


**Guardrail(s).** The fixture-diff matrix (seven planted defects, seven clean twins — found once, silent respectively); the incremental and dedup planted cases; argv-exact posting through the fakes; clean-diff exit-0-no-comment golden; document conformance; an optional real-weights pass per the model families (one family, one fixture MR, recorded).

**Acceptance criteria:**
- [ ] `review mr <ref>` fetches, plans, hunts, confirms, dedups, filters and posts batched inline comments through the seam — or prints the document under `--dry-run` with nothing posted.
- [ ] A clean diff is silent (exit 0, no comments); a re-review re-reports nothing already posted; an unchanged-line finding never posts.
- [ ] The run document is documented and conformant; the gate asks interactively; the full suite is green.
