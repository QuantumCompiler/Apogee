# Completion namespaces: the map before the territory

**What / why.** Tab on `--model` dumps the whole world as one flat wall — measured on the user's install (2026-10-14, the completion-presentation spike): **~60 candidates** spanning backend keys, three vendors' rosters, role aliases and every local quant variant, in case-sensitive ASCII order (`Llama`/`Qwen` exiled behind lowercase), because the one completion core emits every source's union as bare strings and every surface shows it flat. This item is **Concept A, the user's pick (2026-10-14)**: *namespace-first candidate shaping* plus *the one ordering rule*, in the core — so every surface (bash, zsh, fish, PowerShell, the TUI exec line, chat's input) improves at once with **no wire or stub change**. The first Tab offers the map (~a dozen entries: the configured backend keys, then one drill-in prefix per vendor roster — `claude:`, `codex:`, `gemini:` — and `local:` for the store); Tab after a prefix offers only that shelf. The mechanics are shipped: item 34's `<backend>:<model>` spelling is the prefix grammar, and the bash stub already handles `:` word-breaks (the `COMP_WORDBREAKS` care in `completions/apogee.bash:9–14`). Closes the spike's W1 (the flat union) and W5 (accidental ordering).

**Core constraint(s).** **One core, every surface** ([ADR 0007](../../adrs/cli/tab-completion.md)): the shaping and ordering live where the candidates are made — never in a stub, never per surface. **The wire is untouched**: `__complete` keeps protocol v2's `:values` + bare lines exactly as measured (Concept B — groups and descriptions on the wire, per-shell stub renderings — is **out**, the user's call 2026-10-14, recorded so revisiting it is deliberate; the same for Concept C's curated tiers). A namespaced candidate is always a **valid insertion** — what Tab fills must be what the parser accepts (`claude:claude-opus-5-5` already runs, 34). The ordering rule is one function: configured backends first, then roster prefixes, then `local:`, then anything else, **case-insensitively** within each band — applied to every value kind, not just backends. Completion stays answered from live state, no new caching.

**Seam + files.**
- `cli/complete_sources.h/.cpp` — the Backend value kind reshaped: top level = configured keys + the vendor prefixes + `local:`; a word carrying a known prefix completes within its shelf only; the one ordering function applied to every kind's output.
- `cli/complete_protocol.cpp` — untouched on the wire; the candidates it emits arrive pre-shaped.
- **The per-kind treatment table** (this item's spec, built as data beside the sources): **models/backends** → the namespaces above; **chats** → most-recent-first (never alphabetical); **store entries** (`models info|delete`) → ordered by format then name; **suites, roles, kits, regimes, recipes, output formats and other small sets** → the ordering rule only, no namespaces (a six-entry list needs no map); **flags** → the parser's order kept (CLI11's own), untouched.
- Tests: `tests/presentation/cli/complete_test.cpp` (or the existing completion suites) — the shaping matrix per kind (top level ≤ the map's size with every source reachable behind its prefix; a prefix completing only its shelf; the insertion validity of every candidate asserted by running it), the ordering goldens (configured-first, case-insensitive — a `Llama` beside a `glm` ordered by letter, not by case), and the stub-facing bytes unchanged in shape (`:values` + lines).

**Reference.** [ADR 0007](../../adrs/cli/tab-completion.md) — the one answerer this shapes inside; item 34 — the `<backend>:<model>` grammar reused as the namespace spelling; M7/M13/35 — the sources whose union this organizes; `completions/apogee.bash:9–14` — the `:` word-break handling already in place; the completion-presentation spike (2026-10-14) for the measurements.

**Decisions made** (dated):
- 2026-10-14 — The set lands in v0.1.8 as track 45 (the user's placement call); **Concepts A + D are the pick, B and C are out** — no wire change, no stub renderings, no curation policy (the user's call on the spike's concepts).
- 2026-10-14 — The namespaces reuse the shipped spellings: `<backend>:` for a vendor's roster, `local:` for the store; nothing invents a third grammar.
- 2026-10-14 — The ordering rule is one function over every value kind: configured first, rosters, locals, case-insensitive within bands; chats most-recent-first (the per-kind table above is this item's contract).
- 2026-10-15 — Bare roster ids stay directly completable once typed: the map governs only the empty-word Tab, and any typed partial prefix-matches everything, so muscle memory and scripts keep working (the default, confirmed 2026-10-15).
- 2026-10-15 — `local:`'s final insertion form is decided by the insertion-validity tests — whichever spelling the parser already accepts — never by taste (the default, confirmed 2026-10-15).


**Guardrail(s).** The insertion-validity rule: every candidate the shaping emits is run through the real parser in tests — a candidate that cannot be typed is a failing test; the shaping matrix and ordering goldens; the wire-shape pin (protocol v2 bytes unchanged); the user-facing before/after captured in the item's tests (top-level count ≤ the map for a many-source install).

**Acceptance criteria:**
- [ ] `--model <Tab>` on a many-source install offers the map (configured keys + vendor prefixes + `local:`), not the union; each prefix completes only its shelf; a typed partial still matches everything.
- [ ] Every emitted candidate parses when typed; ordering is configured-first and case-insensitive everywhere; chats complete most-recent-first.
- [ ] The wire is byte-shape-identical (`:values` + lines); no stub changed; all four shells benefit by candidates alone.
