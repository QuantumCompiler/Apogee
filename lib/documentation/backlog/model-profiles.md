# Model profiles: the local-model quirk layer

**What / why.** A `ModelProfile` registry that bundles, per model **family**, everything Apogee must know to talk to a local model correctly: which chat template renders its prompt, where generation stops, what framing to strip from its output, how it wraps private reasoning, and how it calls tools. Cloud backends need none of this — a vendor API returns typed blocks — so the layer is local-only and reaches the rest of the system as `harness::ModelBehavior`, plain data, never an include.

**The reason this is one bundle rather than five per-concern lists is the whole point of the item.** These behaviours are not independent. Ommi discovered that the hard way: Gemma 4 needed a bespoke prompt template, needed control tokens made visible, emitted a channel header mid-answer that had to be excised, and called tools with its own tokens instead of the injected protocol — **four facts about one model, found one crash at a time, over four separate bug reports.** Bundling them means adding a family is a single reviewable entry and a half-characterized family is visible as a gap rather than as a runtime surprise. Apogee builds the bundle from day one instead of retrofitting it, which is the sequencing lesson this item exists to apply.

The failure this prevents is specific and expensive: **an unrecognised tool call is not a no-op.** Nothing dispatches, *and* the raw markup is printed to the user as if it were the answer. A blank or garbage turn is the visible symptom of every gap in this layer.

**Core constraint(s).**
- **A family's quirks live in its profile, never in package-level global token lists.** Marker sets differ by one character across families; a shared list is how one model's fix becomes another's bug.
- **Resolution ladder, explicit and table-tested:** config `chat_template:` > profile declared by the model file > name auto-detect > generic fallback. **Specific before family** at every rung, so `gemma4` never renders `gemma` markers.
- **Unknown is permissive.** `ModelBehavior`'s zero value means *uncharacterized*, and every consumer must then recognise every format it knows and strip nothing it is not certain about. Being too eager costs one suppressed line; being too cautious prints markup as the answer. `known()` is what separates "no information" from a verified fact — an **empty** reasoning-tag list on a known profile means "this family emits none", which is a characterization result, not an absence of one.
- **Profiles are characterized from real weights, not from published formats.** A `verified` flag records which is which, and an unverified profile is still used (a documented guess beats the generic fallback) but is surfaced as unverified rather than quietly assumed. Under Apogee's open-model policy this matters *more* than it did in Ommi, not less: there is no allowlist to make any family a promise, so honesty about characterization state is the only signal a user gets.
- **Filter markup at the source.** Display, persisted history, tool parsing, and any cached prefix must all see the same filtered text, or they disagree about what the model said.
- **The display's opener list and the parser's accepted formats must provably share one source.** A marker missing from the display list leaks raw markup to the user; one missing from the parser silently drops the call. Two lists that must agree are two lists that will not.

**Seam + files.** New: `lib/src/cli/source/backends/model_profile.h/.cpp` (the registry, the profile struct, the resolution ladder), `backends/think_filter.h/.cpp` (streaming open/close reasoning-pair filter with a hold-back buffer sized to the longest opener), `backends/markup_filter.h/.cpp` (streaming control-token *header* excision), `backends/native_tool_calls.h/.cpp` (control-token tool-call parsing plus the shared `tool_call_openers()`). Extended: `backends/chat_template.h/.cpp` (widen the shipped ChatML/Llama-3/Mistral name-matching registry into the profile layer's template slot), `backends/llamacpp.cpp` (consume the profile; implement `ModelBehaviorReporting`), `harness/behavior.h` (already carries the struct — this fills it), and the `agentloop/` streaming lookahead so suppression and parsing key off one opener list. Tests: `lib/src/cli/tests/backends/` per-family golden-transcript fixture suites recorded from real model output.

**Reference (Ommi).** `lib/cli/src/backends/model_profile.go` (322 lines — the registry, the `nil` vs empty reasoning distinction, the `verified` flag), `chat_template.go` (361 — `showSpecial`, `headerMarker`, `AutoDetectTemplate`'s deliberately generous family substrings), `think_filter.go` (232 — the streaming pair filter, `Pairs` restriction, the `OnThinking` side channel), `markup_filter.go` (208 — **read its package comment**: it explains at length why a header filter is deliberately *not* the think filter, and why bounding a header by its identifier run rather than by its close marker is what makes an unterminated header cost one word instead of a paragraph), `native_tool_calls.go` (291 — `ToolCallOpeners()`, the next-opener bound that stops a truncated call swallowing the valid one after it, and the control-token string delimiter that survives values containing commas and quotes).

**Deliberate divergences.**
- **The template engine is llama.cpp's, not ours.** Ommi shelled out to `llama-completion -no-cnv` and therefore had to hand-render every prompt as a raw string. Apogee links llama.cpp in-process and can apply the model's *own* embedded template from the GGUF metadata. So the ladder inverts: **use the model's embedded template by default, and carry a bespoke override only where the model ships none or ships a wrong one.** Gemma 4 shipping no template is exactly why Ommi had to reverse-engineer it, and is the case the override slot exists for.
- **`showSpecial` becomes a detokenization flag,** not a subprocess argument — in-process this is `parse_special` when turning tokens back into text. Same purpose: a framing control token rendered as empty leaves its payload behind as bare prose with nothing to key off.
- **No `approved` flag.** Ommi's profiles carried one because it had an allowlist of promised models. Apogee's open-model policy (SPEC → Background, divergence 4) deletes the concept; `verified` survives alone and does all the work.
- **GBNF grammar-constrained tool calls** are an option Ommi never had, since in-process llama.cpp exposes the sampler.

**Open calls:**
- [default: fallback behind the prose protocol first; promote per-profile only where characterization proves it reliable] GBNF grammar-constrained sampling for local tool calls. A grammar that constrains a model into a format it was not trained on trades one failure mode for a worse one.
- [default: record it in the profile as a hint, never auto-apply] What to do with a chat template a model file or an Ollama layer *declares*, when it disagrees with the resolved profile. Ommi's sidecar already treats Ollama's template layer as advisory for this reason.

**Guardrail(s).**
- Per-family **golden-transcript fixture suites** recorded from real model output — the fixtures are the characterization, and they are what makes `verified` true.
- The **display-vs-parser opener-parity assertion** as a unit test: the streaming lookahead's opener list and the parser's accepted formats must come from one function, asserted, not reviewed.
- Streaming filters replayed at **adversarial chunk sizes** (1/2/3/7/4096 bytes) with an identical result required at every size — the discipline already proven on `JsonlFramer` and the vendor-CLI fixtures.
- A **regression test for Ommi's negative-slice panic**: an empty tag-pair set must not underflow the hold-back buffer.
- Every guardrail **mutation-tested before it is trusted**, per the repo discipline: remove a marker from the display list and the parity test must fail; feed a split tag and the chunk-size suite must fail.

**Acceptance criteria:**
- [ ] A Gemma-style fixture (bracket-pair template, mid-answer channel header, control-token tool calls) produces clean display, clean persisted history, and a dispatched tool
- [ ] A response that opens like a tool call but fails to parse **displays its text** — never a blank turn
- [ ] Reasoning tags split across chunk boundaries filter correctly; an empty tag-pair set cannot underflow the hold-back buffer
- [ ] Display lookahead openers and parser formats provably share one source (asserted, and the assertion mutation-tested)
- [ ] The resolution ladder is table-tested including the specific-before-family case
- [ ] An unknown/unprofiled model is treated permissively: every dialect recognized, nothing stripped that isn't certain
- [ ] `models info` reports a resolved profile and its `verified` state — the surface shipped 2026-09-07 ([MILESTONES.md](../assistant/MILESTONES.md) → Milestone N) and currently prints `unprofiled` for everything; this item is what fills it in
