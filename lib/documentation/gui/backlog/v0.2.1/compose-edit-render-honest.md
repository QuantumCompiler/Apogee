# An edit's Render says it plans again, and shows where the render differs from its preview

**What / why.** In Compose, **Edit by instruction** offers **Preview the changes** and then **Render**. The sheet presents them as a preview followed by a commit: the diff is drawn, and Render sits beside it. They are not that. The CLI's edit dry run writes nothing (the CLI's recorded decision, 52c), so Render runs the planner a second time and draws new seeds a second time. With any real LLM, the rendered edit can differ from the diff the person approved, and a cloud planner is billed twice. The app does not say either thing. Found by the second bug sweep (2026-10-31) and re-verified at HEAD the same day:

1. **Render plans the edit again, and nothing says so.** `previewEdit` (`source/presentation/compose/ViewModels/ComposeViewModel.swift:419-421`) runs `form.arguments(..., dryRun: true)` with `--output-format json` and draws the planned document's diff (`ComposeView.swift:302-304`). `renderEdit` (`ComposeViewModel.swift:479-484`, documented as "the same command, without the dry run") clears the preview at :482 and starts the same `form.arguments(output:)` without the dry run (:483). On the CLI side, every edit run that does not resume calls the planner: `video::edit_scenes(base, options.edit, …, seams.plan(backend, …), draw)` (`lib/src/cli/source/presentation/cli/video_compose.cpp:538-543`). That call draws a seed for each new or changed scene (`lib/src/cli/source/business/video/compose.cpp:620`), and each `--redo-scene` draws a fresh seed again (`video_compose.cpp:553-554`). Then `if (options.dry_run) { … project.status = "planned"; … return result; }` (:589-595) returns before the first `save(project)` (:606). `lib/src/cli/tests/scripts/sh/video_e2e.sh:591-594` asserts that an edit dry run writes no `dry.mp4.json` and no `dry.scenes`, and the sweep's scratchpad probe (p4) confirmed that an edit `--dry-run` left no sidecar. So nothing from the preview reaches the render. GUI MILESTONES.md:701 (1n) records "**Render** runs the same command without it", and :706 records "An edit is always previewable", but neither mentions the second planning call. Scenario: open Edit by instruction on a project, type "make it about storms", and click Preview the changes. The diff shows scenes 2 and 3 changed. Click Render. The CLI plans again and may change a different set of scenes, or put them in a different order. What renders is not what was previewed, and a cloud planner has been called twice. No backlog item covered it.

A related gap was found while re-verifying: **a preview stays on the sheet after the form changes.** `preview` is cleared only by a new composition, an opened edit, a timed-out or failed preview, and Render (`ComposeViewModel.swift:160, 410, 444, 456, 482`). So if the person edits the instruction or toggles a re-roll after previewing, the sheet still shows the diff for the earlier arguments, right beside Render.

What already works: rendering a *brief's* dry run renders the kept plan and never plans again (52c: `video_compose.cpp:510-514`; the plan is saved at :673-678). Running the same edit command again resumes the kept project instead of editing it again (55c: `asks_kept_edit`, `video_compose.cpp:121-124`, used at :387-389), so a stopped edit render's Resume does not plan a third time. The project page already draws the rendered project's own diff against its parent (`ComposeView.swift:194-196`, `ComposeViewModel.diff(_:)`). And the preview is a bounded run that Stop reaches (4f).

**Core constraint(s).**
- **The GUI is a machine-mode client.** The app never plans, never writes the CLI's project document beside the output, and never re-creates the edit from the previewed document. Writing the dry run's document where the CLI would find it would make the app the owner of the CLI's project format. The fix only reports what the CLI does.
- **The CLI's 52c decision stands** (CLI MILESTONES.md:9247: "The edit's dry run keeps its shipped 'writes nothing' contract"). This item does not change it.
- **The protocol grows additively.** The planner's name comes from the document's `plan.backend` (`lib/src/cli/source/data/contracts/video_project.cpp:89`), and the read tolerates its absence: an older binary gets the line without the name.
- **MVVM (ADR 0002) and a preview for every view (ADR 0004).** The comparison lives in the view-model and Business, and the views only draw it. Each new state the person sees gets its own named `#Preview` over recorded documents.
- **Development runs on the dev channel.** A live pass drives `apogee-dev` over `~/.apogee-dev`, never the release `apogee` or `~/.apogee`. Until M18 ([`app-dev-channel.md`](../maintenance/app-dev-channel.md)) ships, a live pass with a development build is asked of the user first.
- **The render's command is unchanged.** Render still runs exactly the argv it runs today (pinned at `tests/presentation/compose/ComposeViewModelTests.swift:103-104`).

**Seam + files.**
- `lib/src/darwin/source/business/media/Projects.swift`: `ProjectRecord` reads `plan.backend` as an optional `planner`. `MediaLibrary` gains a comparison of two edits' changes: per scene in order, its source (`from`), its change words and its narration. Seed values are not compared, because a re-rolled scene's seed is new on every run and the preview never promised it.
- `lib/src/darwin/source/presentation/compose/ViewModels/ComposeViewModel.swift`: `previewEdit` keeps the arguments it previewed beside `preview`. A form whose arguments no longer match drops the preview. `renderEdit` keeps the previewed record for that output for the life of the run. Once the render's document is done, the page's diff is compared to the preview's, and a `renderPlansAgain` line (with the planner's name when known) is exposed for the sheet.
- `lib/src/darwin/source/presentation/compose/Views/ComposeView.swift`: the edit sheet's line beside Render (shown once a preview is drawn), Render's `.help`, and the project page's line above its diff when the rendered changes differ from the preview.
- `lib/src/darwin/source/presentation/compose/Previews/` (`ComposePreviews.swift`, `PreviewDocuments.swift`): a recorded preview document with `plan.backend`, and a rendered document whose changes differ from it.
- Tests: `lib/src/darwin/tests/business/media/ProjectsTests.swift` (the `planner` read and the changes comparison), `lib/src/darwin/tests/presentation/compose/ComposeStudioTests.swift` and `ComposeViewModelTests.swift` (the sheet's line, the dropped preview, the page's comparison).
- Design: `lib/design/spec/html/main.html`'s edit sheet (the Preview and Render buttons at :1927) draws the line, and the canvas version is bumped (the design lives in `lib/design`).
- Docs on ship: GUI MILESTONES (a new entry that corrects 1n's Render line), DEVELOPER's compose section, and the Codebase Map's `compose` row.

**Decisions made** (dated):
- 2026-10-31: Specced from the second CLI/GUI bug sweep (the user's call: every finding becomes a v0.2.1 item in its queue, CLI track 57, GUI track 6).
- 2026-10-31: One finding, one item. The stale preview after a form change goes with it because both are the same promise: the diff beside Render is what Render will do. A preview drawn for other arguments breaks that promise more plainly than a second planning call does.
- 2026-10-31: The fix is on the GUI side. The sheet says that Render plans again, and the page shows where the render differs from its preview. The CLI's "an edit's dry run writes nothing" (52c) is the user's recorded decision, so the app reports what the CLI does rather than working around it.

**Open calls:**
- [default: the GUI-side honesty fix is sufficient, and this item is that fix. The alternative is to keep the edit's plan on the CLI side: an edit dry run would write its project beside the output as `planned`, the way a brief's does, so that Render (the same command) renders exactly what was previewed. 55c's kept-edit path (`asks_kept_edit`) is the likely seam. That alternative would reverse 52c's recorded decision (CLI MILESTONES.md:9247), so it is the user's call and is not taken here. If the user wants it, it becomes a CLI sibling in track 57, and this item's line changes to "Render renders this plan".]
- [default: the sheet's words, shown under the diff once a preview is drawn: "Render plans the edit again with <planner>: what renders can differ from this preview, and the planner is called a second time." With no `plan.backend` in the document: "Render plans the edit again: what renders can differ from this preview." Render's `.help` says the same in brief.]
- [default: after the render, if the rendered project's changes differ from the preview's (per scene, in order: source, change words, narration), the page says "The render planned again, and its changes differ from the preview" above its own diff. If they match, nothing extra is drawn. The previewed record is kept in memory for this app's run only and is never written to disk. A render the app did not start from a preview gets no line.]
- [default: changing the instruction or a re-roll after a preview drops the preview. The sheet goes back to offering Preview the changes and draws no diff for other arguments.]
- (consumed decision) CLI 52c: an edit's dry run writes nothing. This item reads that behavior and does not change it.

**Guardrail(s).** Hermetic, over scripted jobs and recorded documents, with no binary and no network:
- A drawn preview shows the replanning line naming `plan.backend` from the recorded document. A document without `plan.backend` shows the line without a name.
- A preview, then a change to the instruction (and separately a re-roll toggled): `previewDiff` is nil, and the line is gone.
- A preview, then Render, then a rendered document whose scenes differ from the preview (a different scene changed, or a reorder): the page's comparison says they differ. A rendered document that matches the preview: no line. A re-rolled scene whose seed differs but whose words match: no line.
- Render's argv stays byte-identical to today's (the existing `ComposeViewModelTests` pin).
- `ProjectsTests`: the `planner` read, present and absent. The comparison's cases: same, changed set, reorder, removal, seed-only difference.
- Named `#Preview`s: "An edit's preview, Render's replanning said" and "A rendered edit that differs from its preview". The layering check stays green.

**Acceptance criteria:**
- [ ] With a preview drawn, the edit sheet says, before Render is clicked, that Render plans the edit again and names the planner when the document carries it.
- [ ] A diff drawn for earlier arguments never stays beside Render: changing the instruction or a re-roll drops it.
- [ ] After a render whose plan came out different, the project page says the render's changes differ from the preview. A render that matches says nothing extra.
- [ ] The command Render runs is unchanged, and the CLI's edit dry run still writes nothing.
- [ ] The design prototype's edit sheet draws the line, and the full darwin suite is green.
