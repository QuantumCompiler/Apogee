# The machine-mode client core: the CLI as a Swift type

**What / why.** The integration is proven cheap: a ~40-line Swift Foundation probe spawned the installed v0.1.9 binary and drove the documented protocol end to end — `hello` accepted, the `session` event announcing capabilities, `thinking`, and an `ask_user` arriving as a `question` event, first event in about a second (the GUI spike, 2026-10-20, against a sandboxed `APOGEE_HOME` with the scripted mock backend). What the probe also measured is the wall this item owns (W3): **a GUI app inherits no shell `PATH`**, and `machine-schema.json` is **not installed as a file** (`~/.local/bin` holds binaries only; the archive carries the schema but the installers place binary + completions) — while the binary itself prints it (`apogee __machine-schema`, verified). This item builds the GUI's Data and Business layers around those facts: **Infrastructure** — the child process (spawn with exactly three pipes, stderr captured into a bounded tail, termination and exit observed); **Data** — the protocol as Swift types: **tolerant event decoding** (an unknown event type or field is kept and surfaced, never fatal — the additive-protocol law from the client's side), the driver lines (`hello`, `user`, `answer`, `attach`, `cancel`), the reads' `--output-format json` documents, and **binary discovery** (the install channels' known paths — `~/.local/bin/apogee`, the dev/test channels — plus a user-pointable override, each candidate verified by running it); **Business** — the session: spawn `chat --output-format stream-json --input-format stream-json [--tools]`, the `hello` handshake, events delivered as an `AsyncStream` to whoever renders, answers and cancellation sent back down, turn lifecycle tracked from the protocol's own events; and the reads runner (one bounded captured run of a read command, its document decoded).

**Core constraint(s).** **The GUI docs' ⚠ whole**: every capability through the spawned binary; nothing linked, nothing reimplemented, no port. **Tolerance is law** (the CLI's ADR 0006 consumed): decoding never throws on an unknown; a new event in a newer binary flows through as "unknown, kept". **The child's stderr is captured, never shown raw** — a bounded tail folded into failures (the CLI's own discipline, mirrored). **Cancellation is the protocol's `cancel` line first**; termination is the escalation, never the first resort. **Discovery is honest**: no binary found is a stated, typed condition the Presentation layer can render with the install hint — never a crash or a silent retry. Hermetic tests: a **scripted fake apogee** (a small script emitting protocol lines, the house fake-driver idiom) carries the whole matrix; a committed fixture of real protocol lines pins the vocabulary; a pass against a real installed binary exists but is **skipped and said** when none is present — no test requires an install.

**Seam + files.**
- `source/infrastructure/process/` — the child: three pipes, the stderr tail, exit observation (Foundation `Process` behind one small interface a test fakes).
- `source/data/protocol/` — the event union (typed cases + the tolerant `unknown`), the driver lines, the reads' documents; `source/data/discovery/` — the channel paths, the override, the verify-by-running probe.
- `source/business/session/` — the machine-mode session over the two below: handshake, the event stream, answer/cancel, turn lifecycle; `source/business/reads/` — the one-shot read runner.
- `tests/` mirroring each — the scripted fake apogee, the fixture lines, the tolerance matrix, the discovery table, the cancel path.

**Reference.** [`machine-mode.md`](../../cli/reference/machine-mode.md) — the contract, consumed as written (the spike drove it knowing only this document); the CLI's M10 install channels — the discovery paths; the CLI's captured-stderr invariant — mirrored client-side; the GUI spike (2026-10-20) — the probe and measurements above.

**Decisions made** (dated):
- 2026-10-20 — The core is Swift-native over Foundation (`Process`, `AsyncStream`) — no bridging layer; the spike's probe showed none is needed.
- 2026-10-20 — The schema's vocabulary is taken from the binary (`__machine-schema`) and from committed fixtures, never from an installed schema file (none exists — the spike's W3 measurement).
- 2026-10-20 — Unknown events are kept and surfaced, never dropped silently and never fatal.

- 2026-10-20 — **Discovery order**: the override setting, then the release channel path, then dev/test channels — finalized at build; the override lives in the GUI's own persisted preferences (Data layer), never in the CLI's config (the default, confirmed at grooming).
- 2026-10-20 — **The event union's shape**: an enum with associated values plus `unknown(type:raw:)`, and the `AsyncStream`-vs-delegate choice, at build within the stated tolerance law (the default, confirmed at grooming).

**Open calls:** none — groomed 2026-10-20.

**Guardrail(s).** The fake-apogee matrix (handshake, a full turn's events in order, a question answered, cancel acknowledged, a dying child's tail folded into the failure); the tolerance tests (an unknown event type, an unknown field on a known event — both kept, nothing throws); the discovery table (override > channels, a missing binary the typed condition, a candidate that fails verification skipped and said); fixture lines committed from the real binary's stream, refreshed deliberately; the optional real-binary pass skipped-and-said without an install.

**Acceptance criteria:**
- [ ] The core drives the scripted fake through a whole conversation — session, streaming, a question answered, a result — delivering typed events in order.
- [ ] `cancel` reaches a turn in flight through the protocol; termination only on escalation; the stderr tail rides every failure.
- [ ] Discovery finds the installed binary on the dev host, honors the override, and reports absence as the typed condition.
- [ ] Unknown events and fields flow through non-fatally; the full suite is hermetic and green.

**Scope note.** Earmarked for v0.2.0; gated on 1a, the darwin scaffold (shipped 2026-10-20, [MILESTONES → Milestone A](../assistant/MILESTONES.md#milestone-a--the-macos-application)): the seed packages it fills -- `infrastructure/process` (`ChildCommand`), `data/protocol` (`MachineProtocol`), `business/session` (`ChatLaunch`) -- and the layering check its new packages must pass. Out of scope: any UI ([`session-window.md`](session-window.md)), task runs and plays (the protocol carries them; the core's event union keeps them as events, a window for them is later work), MCP host-side tools, linux/windows ports of the core (the shared-core question stays open until a second app exists).
