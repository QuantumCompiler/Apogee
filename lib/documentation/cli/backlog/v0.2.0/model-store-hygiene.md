# Model-store hygiene: delete, rename and register see every reference

**What / why.** The model-store verbs grew through M14–M16 and the MLX-for-every-kind wave (53e–53m) faster than their edges were held. The CLI/GUI audit (2026-10-22, three-lens verified) found seven defects:

1. **`models delete` is blind to `draft:` pairings and the video role** (high). `backends_inside` iterates only `{backend.model_path, backend.mmproj_path}` (`models_pull.cpp:258`), while `BackendConfig` carries `draft` (`data/contracts/config.h:262`) and `adapters` (`:251`). The delete's warning and the M14 `--and-backends` offer are both built from that list alone (`models_pull.cpp:3711-3729`), and `models.default_video` (`config.h:306`) is never consulted. Deleting a drafter therefore strands its base silently: a dangling `draft:` makes the MLX ladder refuse the whole backend (`mlx_local.cpp:536-544`). Deleting the default pipeline leaves a dead pointer unannounced. M25 and 53i's "not done" cover `models rename` and the footprint only.
2. **`models rename` by family name refuses MLX families.** `quant_level`'s regex (`operations/renames.cpp:422`) knows only GGUF level spellings, so backends the MLX register chain names `<base>-4bit/-8bit/-bf16` (`models_pull.cpp:2963`) never form a family (`renames.cpp:491`). The refusal advises "the backend without its -F16 or -Q4KM", which is GGUF-only. Probe: `models rename TestM NewName` over `TestM-4bit` exits 1, while renaming by the stored directory works fully (`derived_level`, `renames.cpp:131`).
3. **`rename_stored_model` dereferences an empty optional.** `renames.cpp:539` declares `std::optional<harness::Config> config`, filled only when the config file exists (`:541-548`), yet `:588-589` read `config->models.default_video` unguarded (the backends loop at `:552` is guarded). Renaming a pulled model on a fresh install with no config is undefined behavior. Probe: the path executes.
4. **A pulled draft head's closing hint names refused commands** (the M14 class). `print_snapshot_next` (`models_pull.cpp:365-377`) special-cases diffusion models only. On a draft-head snapshot it suggests `models convert <repo>` and `--register-with Q4_K_M`, and both are refused with `draft_head_refusal`, which itself names no `--mlx` drafter door. The one decision exists: `snapshot_conversions` answers `["mlx"]` or `[]` for a draft head (`snapshot.cpp:540-551`).
5. **Register chains tell the person to chat with an embedding backend.** `register_mlx_backend` (`models_pull.cpp:2917-2918`) and GGUF `register_backends` (`:2708-2710`) set `log.next = "chat with one: apogee chat -m <name>"` unconditionally, printed last (`model_chain.cpp:66-68`) under the chain's own note that the backend embeds and answers no chat. The GGUF route never prints the `config set-default-embedding` door that only the MLX helpers carry (`:1334-1346`).
6. **Chain summaries print `note: note:` doubled prefixes.** `run_chain` prepends `note: ` (`model_chain.cpp:63`) to notes that already begin with `note: ` (`base_model_note`, `models_pull.cpp:227`; `embedding_role_note`, `:1334`) or `warning: ` (`:2431`). `model_chain_test.cpp:218` asserts `"note: note: a base model"` verbatim, so the defect is locked in by its test.
7. **A stored MLX voice or video set is accepted as a chat backend** (completeness pass, with probe; reproduce first). `MlxKind::registers()` is defined (`data/modelstore/mlx_info.cpp:521`) and never called. MLX readiness turns away only `drafter` and routes `embedding` (`mlx_local.cpp:495-545`). Probe with a stored set whose record says `kind: voice`: `config add-backend vox --type mlx --model-path <set>` and `config set-default vox` both succeeded, `check` said `ok default_backend vox`, and `models info` showed `roles: chat, embedding, extraction` beside its own "never a chat backend" line. This is not M22 (shipped 2026-10-24, whose inferred kinds `registers()` now also sees): the kind is recorded, not guessed.

**Core constraint(s).** **Every reference is found**: delete's warning and offer, and rename's sweep, walk one list of what can point into a stored set. That is `model_path`, `mmproj_path`, `draft`, `adapters` and the `models.default_*` pointers, declared once, never per-verb lists. **Every hint is runnable** (M14's bar): a printed next step is a command the binary accepts on that state. **The kind decides the role**: a set's recorded kind gates what it may register as, through the one existing predicate (`registers()`), at add-backend, set-default and the readiness ladder alike. **No undefined behavior**: the optional is checked. The format and tests follow the corrected wording; the test that pins the doubled prefix is fixed, not deleted.

**Seam + files.** `presentation/cli/models_pull.cpp` (`backends_inside` → the one reference walk; the closing-hint branch on `snapshot_conversions`; `log.next` by kind), `presentation/operations/renames.cpp` (MLX levels in the family regex or a level reader shared with the chain's naming; the optional guard), `data/backends/mlx_local.cpp` + the config/add-backend path (`registers()` enforced), `data/modelstore/snapshot.cpp` (`draft_head_refusal` names the `--mlx` door when offered), `presentation/cli/model_chain.cpp` (one prefix). Tests: a delete matrix over every reference kind (draft, adapters, default pointers); an MLX family rename by name; a configless rename; draft-head hints runnable; embedding chains' last line; the corrected chain golden; a voice/video set refused as chat with the kind named.

**Reference.** M14/M15/M16 and 53e–53m (shipped, CLI MILESTONES Milestone N and AQ); M25 ([`../maintenance/drafters-follow-renames.md`](../maintenance/drafters-follow-renames.md)), which owns rename's drafter half and the footprint, consumed here (`consumed decision`), not duplicated; the CLI/GUI audit (2026-10-22).

- 2026-10-22: Delete's reference walk becomes the one declaration rename and future verbs reuse. M25's rename half consumes it when M25 builds.

**Guardrail(s).** Each finding's probe pinned; the reference walk's matrix; the corrected chain golden.

**Acceptance criteria:**
- [ ] Delete names and offers every config reference into the set; an MLX family renames by its shared name; a configless rename is safe.
- [ ] Every hint a pull or chain prints is runnable on that state; embedding chains end on the embedding door; no doubled prefixes.
- [ ] A voice or video set cannot become a chat backend, refused by its kind; the full suite is green.
