# Adapters and shared bases, closed: every path honors the set and the pin

**What / why.** Track 53 (runtime LoRA adapters, one base many roles) shipped 2026-10-21. The CLI/GUI audit (2026-10-22, three-lens verified) found that several paths outside its core never learned about adapters, and one shared-base path prices memory as if sharing didn't exist:

1. **A sharer joining a resident base fits its window as if the weights loaded twice** (high). `llamacpp.cpp:1009-1011`: `fitted = loaded ? base->model().fitted_window() : runtime_->fit_window(load)`. A joiner's fit runs `fit_default_window` (`llama_real.cpp:1379-1407`, `needed = file_size + cache_bytes + margin`) against free memory measured while the base is already resident. The pre-check therefore passes only when memory could hold the weights twice, and otherwise falls to the full `fit_window` re-read (0.13-0.72 s), which can return the minimum window ("nothing fits, not even the weights"). The second member of a shared-base suite gets a collapsed window. The dated 53d decision's premise ("as a second load does today", MILESTONES:9522) was removed by 53d itself.
2. **An MLX embedding entry silently ignores its registered, pinned adapters.** Config accepts adapters on any mlx entry with the kind unexamined (`config.cpp:220-235`). `config set-backend --adapters` pins them, and `check_adapters` (`check.cpp:996-1184`) reports them applying. But `factory.cpp:212-215` routes an embedding-kind mlx directory to `MlxEmbedProvider`, whose `options_from` (`mlx_embed.cpp:58-76`) never reads `config.adapters` and whose child argv is driver plus `--model` only (`:297`). Every embed runs the bare base while config, pin and doctor say the fine-tune applies, and those vectors land in collections. This contradicts 53a's shipped contract ("set on every context, chat and embedding alike").
3. **`set-backend --model-path` moves the base under pinned adapters silently**, though the same edit re-pairs a drafter. In `backend_fields.cpp`, adapters are re-pinned only when `--adapters` is among the edits (`:197-207`), while `:213-225` re-pairs `draft` on a model_path move. Probe: the edit printed `set model_path` alone, the next `chat` turn refused `pinned to other base weights (sha256 385e8da63748) than … holds now (e98d1934d63b)`, and `check` turned FAIL.
4. **An MLX adapter directory without `adapters.safetensors` passes every gate, then fails as mlx-lm's raw exception.** `adapter_files`' directory case (`adapters.cpp:210-213`) requires only `adapter_config.json`, while `mlx_adapter_verifier` (`train.cpp:265-275`) wants both files. The driver catches the load failure and relays `FileNotFoundError: …` (`assets_mlx.cpp:1754-1777`) with no named refusal and no remedy.
5. **`train rollback` repoints an adapter version without checking its pin against today's base.** The adapter branch (`train.cpp:2562-2598`) writes the ledger's recorded `base_sha256`, but nothing compares it to the base the entry runs now. Promote does (`train.cpp:969-987`). After a re-pull, requantize or model_path move, rollback prints `rolled back <b>: v2 -> v1` and the next load refuses by hash (`adapters.cpp:259-274`).
6. **A collection's embedding space is named by the model alone, so adapters silently mix spaces.** `embedding_model_name()` (`llamacpp.cpp:866-871`) uses the config name or GGUF filename, while `embed()` applies the entry's adapters (`:850-854`, `llama_real.cpp:1118-1135`). A collection's recorded `EmbeddingBinding` (`store.h:175-193`, set by `embed_func.cpp:30`) is identical across adapter register, re-pin, clear and promote, so the mismatch-falls-to-lexical guard cannot catch vectors ingested under the bare base and queried under the fine-tune. The prompt cache grew the adapter set for exactly this reason (`prompt_cache.h:43-73`); the space identity did not.

**Core constraint(s).** **One adapter story everywhere**: an entry's adapters either apply on a path or are refused there by name, never silently dropped. That covers chat, embedding (both backends) and the doctor's report. **The pin is checked wherever the base or the version moves**: set-backend's model_path edit re-pins or refuses (as it re-pairs a drafter), and rollback verifies before writing. **Shared bases are priced as shared**: a joiner's fit counts the resident weights once, the footprint's own BaseKey rule (53d). **A space is the model plus its adapters**: the binding's identity includes the adapter set so the existing retriever demotion catches a change. The one-retriever invariant then holds unmodified.

**Seam + files.** `data/backends/llamacpp.cpp` (the joiner's fit against the resident base; the embedding name grows the adapter identity), `llama_real.cpp` (the fit arithmetic's sharing case), `data/backends/mlx_embed.cpp` + `assets/mlx/mlx_embed.py` (adapters applied, or the config refusing adapters on an embedding-kind mlx entry; one of the two), `presentation/operations/backend_fields.cpp` (re-pin on model_path move), `data/backends/adapters.cpp` (the directory requires its weights file), `presentation/cli/train.cpp` (rollback verifies the pin), `presentation/cli/check.cpp` (the doctor follows whichever mlx-embedding choice is made). Tests: a joiner's window over a fake runtime with a resident base; the mlx-embedding adapter matrix; set-backend's model_path re-pin; the incomplete adapter directory refused by name; rollback refusing a stale pin; a collection's binding changing with its adapter set.

**Reference.** Track 53 (shipped, CLI MILESTONES Milestone AP/AQ): the contract these paths now keep; the prompt-cache fingerprint (53a), the precedent for space identity; the CLI/GUI audit (2026-10-22).

**Open calls:**
- [default: MLX embedding entries apply adapters through the driver's `adapter_path` (53a's contract, "chat and embedding alike") rather than refusing them; the doctor's row reports it applied only when it is.]
- [default: set-backend's model_path move re-pins the entry's adapters against the new base when its hash matches each adapter's recorded pin, and refuses the edit naming the adapters otherwise.]

**Guardrail(s).** Each finding's probe pinned; the 53a/53d suites kept green; the no-bleed matrix untouched.

**Acceptance criteria:**
- [ ] A suite's second member on a shared base gets the same window budget the first did, priced once.
- [ ] Every adapter path applies or refuses by name. Moving a base or rolling back never leaves a pin silently stale. An incomplete adapter directory is refused before load.
- [ ] A collection embedded under one adapter set is not silently queried under another; the full suite is green.
