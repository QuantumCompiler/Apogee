# `apogee acp` — Apogee as an agent in Xcode

**What / why.** The user asked whether Apogee could plug into Xcode. The 2026-10-31 research checked five angles: Xcode's classic extension points, its chat providers, its agents and MCP, a read-only probe of the dev Mac's Xcode, and Apogee's own surfaces. A skeptic checked each claim against Apple's documentation, the installed Xcode and this repo, and a completeness critic reviewed the whole. One route fits Apogee's rules and gives a full agent: the **Agent Client Protocol** (ACP). Since Xcode 26.6 (2026-06-25), Settings › Intelligence › Agents › "Add an Agent" registers any ACP agent binary. Xcode starts it as a child and speaks JSON-RPC over its stdin and stdout. Apple pitches ACP as the way to "bring in any agent, any model, including ones that run locally" (WWDC26 session 382). The same day, the user made it the CLI's fifth core surface ([SPEC.md](../../assistant/SPEC.md):32). This item builds it. It removes **wall W1** (Apogee speaks no ACP) and measures **wall W4** in its live pass. Measured, not guessed (2026-10-31; the commands named were re-run while writing this):

- **Xcode's side exists.** The dev Mac runs Xcode 27.1 (27A9275, `xcodebuild -version`); Xcode 27 needs macOS Tahoe 26.6 or later on Apple silicon. `strings -a` on its `IDEIntelligenceACP` lists the client's message types: initialize, authenticate and logout; new, load, list, resume and close for sessions; `PromptRequest`, `CancelNotification`, `PermissionRequest`, `ElicitationRequest`; `SetSessionModelRequest`, `SetSessionModeRequest`, `SetSessionConfigOptionRequest`; and the `fs/*` and `terminal/*` families. It also lists the update kinds `agent_message_chunk`, `agent_thought_chunk`, `tool_call_update`, `current_mode_update`, `config_option_update` and `usage_update`, the field `configOptions` (and no `availableModels`), and all four permission kinds, `allow_once`, `allow_always`, `reject_once` and `reject_always`. There is no session fork, no `notice` and no `notices` string. These are strings, not a captured conversation.
- **The protocol, re-read at agentclientprotocol.com (2026-10-31).** `protocolVersion` is "a single integer that identifies a MAJOR protocol version"; today it is **1**. On stdio, messages are newline-delimited, the agent "MUST NOT write anything to its stdout that is not a valid ACP message", and stderr is for logs. `session/new` carries an absolute `cwd` and, as a MAY, the client's `mcpServers`. A turn streams `session/update` notifications and ends with one stop reason: `end_turn`, `max_tokens`, `max_turn_requests`, `refusal` or `cancelled`; a cancelled turn must end with `cancelled`, never an error. Session modes "will be removed in a future version" in favour of session config options, and the spec advises offering both until then. Neither the schema nor its draft lists `session/set_model`: a model is a config option of category `model`.
- **Apogee has no ACP code.** `git grep` over `lib/src` finds no `agentclientprotocol`, `session/prompt`, `Agent Client Protocol` or word `ACP`. It has two stdio protocols. Machine mode is its own JSONL over a child's pipes ([machine-mode.md](../../reference/machine-mode.md)), the contract the macOS app drives. The MCP stdio server, hidden as `__mcp-tools` when this was written, is public as `mcp serve` since [54a](../../assistant/MILESTONES.md#milestone-w--the-mcp-client) (2026-11-01), the hidden spelling its alias.
- **The filesystem layer (W4).** Xcode 27 adds a Coding Intelligence security layer that "monitors and controls filesystem access by coding agents and any processes they spawn" (release notes, 178289431). It is opt-in. Nobody knows yet what it does to an agent that reads `~/.apogee-dev`, loads models from its store and drives Metal.

What the person gets in Xcode's coding assistant: Apogee's models in its picker (if Xcode draws the `model` config option there, which the live pass checks), Apogee's own tools, Apogee's permission gate asking through Xcode's sheet, and a working Stop button. Xcode's own build and test tools reaching the session are [56b](acp-host-tools.md)'s work.

**Core constraint(s).**
- **Pipes, never a port.** SPEC.md:66 says local front-ends are pipes, and `serve` "is never a localhost backend for a local front-end". The CLI's [⚠ Interactive turns never open a listening socket](../../assistant/CLAUDE.md#-interactive-turns-never-open-a-listening-socket) applies. `apogee acp` reads its host on stdin, answers on stdout, and opens nothing.
- **stdout is the protocol.** It carries JSON-RPC frames only, one per line. Every diagnostic goes to stderr, machine mode's own discipline (`presentation/machine/json_reporter.h:37`). Every child Apogee starts has its stderr [captured, never inherited](../../assistant/CLAUDE.md#-a-childs-stderr-is-captured-never-inherited).
- **One agent loop, one opening.** Two principles apply: "Parity is the product" and "One source of truth per concern" (SPEC.md:65, :70). A prompt is one turn of the one loop. A session opens through `execute`'s own path ([ADR 0011](../../adrs/one-session-opening.md)): `AGENTS.md`/`CLAUDE.md` read, the folder attached, the coder persona. ACP never gets an opening of its own.
- **Apogee's gate decides what runs.** Every gated call is put to the host, and the host's choice is the answer. No answer, a cancelled turn or a broken pipe means no, as `Ask` with nobody to ask is deny (`business/agent/tool.h:228-231`).
- **Additive** ([ADR 0006](../../adrs/backwards-compatibility.md)). Machine mode grows only by new events and fields. ACP capabilities are added later, never changed, and an unknown field from the host is ignored.
- **The dev channel.** Live passes name `apogee-dev` over `~/.apogee-dev`, never `apogee`, and `~/.apogee` is read-only to development. Tests use a temporary `APOGEE_HOME` ([Development runs on the dev channel](../../assistant/CLAUDE.md#development-runs-on-the-dev-channel), the user's call, 2026-10-31).

**Seam + files.** The shape: `apogee acp` translates between ACP and machine mode. Each ACP session is a captured child of the binary's own `execute`, running in machine mode in the session's folder. That is how the macOS app drives Apogee, moved inside the binary. The first open call records why, and the alternative.
- **`presentation/acp/`**, a new Presentation module. Its row goes in `lib/src/cli/cmake/modules.cmake` (the layer's list at `:31`; links settled in review, expected `contracts harness machine platform version`), and `cli`'s links (`:75`) gain it. It has three parts:
  - **`jsonrpc.*`**: JSON-RPC 2.0 over newline-delimited stdio. Requests go both ways with ids (the agent asks `session/request_permission` and `elicitation/create`). An unknown method gets `-32601`; a line that is not a message gets `-32700` or `-32600`, and the process keeps running. Unknown fields are ignored, and one writer owns stdout.
  - **`translate.*`**: pure functions, and the item's heart. One maps machine events to ACP updates, the other ACP requests to machine lines.
    - **Text:** `thinking_delta` → `agent_thought_chunk`, `answer_delta` → `agent_message_chunk`.
    - **Tool calls:** the new `tool_call` event (below) → ACP `tool_call`, then `tool_call_update` as the state moves (`pending` → `in_progress` → `completed`/`failed`). The title is the tool and its target, and `locations` holds the target when it is a path. The kind comes from a table of Apogee's native tools: `read_file` read, `grep_files`/`search_files` search, `write_file`/`edit_file` edit, `delete_file` delete, `run_command` execute, `fetch_url` fetch; the rest of the native registry (`list_directory`, the `git_*` reads, the notes tools, `search_documents`, `web_search`, `todo_write`) is classified the same way. MCP tools, and anything a native row does not name, are `other`.
    - **The todo:** `todo` → `plan`, mapping `pending`/`active`/`done` (`data/contracts/todo.h:26-30`) to `pending`/`in_progress`/`completed`. A permission `question` → `session/request_permission` (open calls).
    - **The end of a turn:** `result` → the `session/prompt` answer. `finish_reason` maps `stop` → `end_turn`, `length` → `max_tokens`, `content_filter` → `refusal`, `cancelled` → `cancelled`, anything else → `end_turn`. `error` → a JSON-RPC error on that prompt, in Apogee's words.
    - **Inbound:** a prompt's text blocks become one `user` line. A `resource_link` is named in that line as an `@`-mention, which the session attaches through its own mention path (`attach_mentions`, `presentation/cli/chat_session.cpp:443`), as a terminal's `@path` is. `session/cancel` → `{"type":"cancel"}`, which trips the turn's own cancellation token (`presentation/machine/driver_input.h:18-24`). A model or mode change → a `set` line.
  - **`session.*`**: one ACP session and its child. The child is started with `platform::start_child` on `platform::executable_path()`, the way the shell runs its own binary (`presentation/cli/tui_cmd.cpp:114-116`). Its arguments are `execute --input-format stream-json --output-format stream-json --tools --private` plus the flags the `acp` line carries, and it runs in `session/new`'s `cwd`. A `cwd` that is not an absolute path to an existing folder is refused with `-32602`, naming it. The request's `mcpServers` are accepted and left unused until [56b](acp-host-tools.md), which says so on stderr. A reader thread serves each child. Its stderr is drained to an 8 KiB tail and folded into a failure, and under `--verbose` the raw stream goes to `acp`'s own stderr. The child is ended by closing its stdin, as any driver ends machine mode. When the host closes `acp`'s own stdin, every child's stdin is closed and `acp` exits 0 once they have ended.
  - **What `initialize` answers:** `protocolVersion` 1 and `agentInfo` (`apogee`, the version). `agentCapabilities` has `loadSession: false`, `promptCapabilities` all false (text and `resource_link`, the baseline) and `mcpCapabilities` `{http: false, sse: false}`. `authMethods` is `[]`: a vendor CLI signs itself in (SPEC.md:69). **What `session/new` answers:** a minted `sessionId`, `modes`, and `configOptions` for model and mode.
- **`infrastructure/platform/child_process.*`.** `ChildCommand` (`child_process.h:31-41`) gains an optional working directory, applied in the spawn. Left unset, every child starts as it does today. Only the session's `execute` child needs it: everything that child starts, 56b's host servers included, inherits the folder.
- **`business/agentloop/reporter.h` and `business/agent/tool.*`**, the one structural growth. `Reporter` gains `on_tool_call`, with a no-op default, beside `on_tool_status` (`reporter.h:83`). `agent::DispatchContext` (`tool.h:203-210`) gains a structured callback beside `on_status`. `dispatch` reports each call, keyed on the model's call id: `pending` before its gate, `running` where it now says `[tool] <name>` (`tool.cpp:215`), then `done` or `failed` from its outcome.
- **`presentation/machine/`**: the growths ACP needs, made for every driver ([ADR 0002](../../adrs/mode-parity.md), ADR 0006). They are a `tool_call` event (`id`, `name`, `state`, `target`); `tool_call_id` on a permission `question`; and `permission_mode` on the `set` line (`protocol.cpp:397`), which takes the words `--permission-mode` takes, with `bypass` only for a session launched allowing it. `kMachineSchemaVersion` moves (`protocol.h:47`), and `machine-mode.md` documents them. `tool_status` is unchanged, and the terminal and the shell keep drawing it. The macOS app adopting `tool_call` is named as not this item's work.
- **`presentation/cli/acp_cmd.*`**: the verb `apogee acp`, with help. It binds `execute`'s own flag table by reference (`bind_session_flags`, `presentation/cli/chat_session.h:150`), so `-m`, `--suite`, `--permission-mode`, `--allow-bypass` and `--allow`/`--deny` reach every session and complete for free ([ADR 0007](../../adrs/tab-completion.md)). The flags the protocol owns (`--output-format`, `--input-format`, `--resume`, `-c`, `--private`, `--no-color`, `--raw`) are refused at launch, in the command's words. [56d](xcode-setup-from-apogee.md) adds `acp registration` under it.
- **Parity rows.** `presentation/cli/tui_parity.cpp` ([ADR 0010](../../adrs/the-shell-is-a-mode.md)) gets a carve-out, "run by an agent host such as Xcode over its stdio, never from the shell", with its exec-line refusal (open calls). `tests/presentation/httpserver/parity_test.cpp` gets a carve-out, "an ACP agent on this process's own stdio, spawned by an agent host", as `__mcp-tools`' row (`:205-207`) and `mcp serve`'s (`:202-204`, 54a) read. Once [56d](xcode-setup-from-apogee.md) gives `acp` a subcommand, that test walks leaves only, so 56d replaces this row with `acp registration`'s, its comment keeping this reason.
- **Docs, in the same change.** A new `lib/documentation/cli/reference/acp.md` covers what is advertised, the mapping table, the sheet's fields, and the limits: W3, W4, and a managed Mac's `CodingAssistantAllowExternalIntegrations=false`, which turns the coding assistant off. Also updated: `machine-mode.md`; the presentation card (`lib/src/cli/source/presentation/CLAUDE.md:5`, its module list) and DEVELOPER.md's module table; and the CLAUDE.md never-listen and stderr sections, which name the new child.

**Reference.**
- **Machine mode**, the front-end contract (28d–28g). Every ACP need either maps onto it or grows it.
- **The macOS app**, a machine-mode driver of a child `apogee`. This item takes its shape.
- **The shell**, which runs the binary's own commands as captured children (37h, ADR 0010).
- **`cli.reference_driver`** (`tests/scripts/py/reference_driver.py`): a worked example that is also a test lock. The conformance suite below copies the pattern.
- **[54a](../../assistant/MILESTONES.md#milestone-w--the-mcp-client)'s `mcp serve`** (shipped 2026-11-01): a stdio protocol mode beside this one.
- **Prior art.** Devin's guide registers its binary in Xcode by absolute path with the argument `acp` (`docs.devin.ai/cli/acp/xcode`), and a field report does the same for OpenCode; this verb takes that spelling. A dev.to guide registers Copilot with its model pinned in Environment Variables (`COPILOT_MODEL`). Devin and OpenCode report that the model cannot be switched from Xcode's menu. Apogee departs there: it advertises its models as a config option (open calls), and the live pass checks the menu.
- **Where this item departs from ACP's full surface:** no `fs/*` or `terminal/*`; models as a config option, not `set_model`; no `notice` to a host that lacks it.

**Decisions made** (dated):
- 2026-10-31 — Specced from the day's Xcode research. The user's call: `apogee acp` is the CLI's fifth core surface, the agent over ACP on stdio, pipes only, on `execute`'s session core and agent loop. `serve` stays server-only, so Xcode's "Locally Hosted" chat provider is not pursued (SPEC.md:32, amended that day). This item removes W1 and measures W4. W2 is 56b's, W5 is [56c](acp-sessions-saved.md)'s, and W6 is 56d's.
- 2026-10-31 — The user's call: the subscription backends (`claude-cli`, `codex-cli`, `gemini-cli`, `ollama-cli`) are offered to Xcode through `apogee acp`, as the macOS app offers them. `serve` refuses them by type (`presentation/cli/serve_cmd.cpp:207-219`); `acp` is a local front end and does not.
- 2026-10-31 — The user's call: no Xcode plug-in now. People add Apogee by hand in "Add an Agent", with the fields 56d prints. The plug-in stays a ROADMAP idea: one that ships a binary would want Developer ID signing and notarization, against the ad-hoc signing recorded at `lib/src/darwin/scripts/build.sh:36-42`.
- 2026-10-31 — (consumed) Routes rejected, with their evidence:
  - **Xcode's "Locally Hosted" chat provider pointed at `apogee serve`.** It is against SPEC.md:31 and :66, and it breaks in practice. `serve` answers any request carrying `tools` with 400, "client-side tools are not supported" (`presentation/httpserver/handler.cpp:648-652`), and Xcode's requests carry its file tools (Xcode 27.1 binary strings). A request without tools falls to `tool_mode` `all` (`handler.cpp:165-167`), which runs Apogee's own loop in the server's folder, not Xcode's project.
  - **A Source Editor Extension.** It gets only the current file's text, with no path or project. It is a sandboxed app extension that needs development signing on every target, and the app is ad-hoc signed.
  - **Swift package plugins.** They are sandboxed, and the processes they start inherit the sandbox. Under an approximation of SwiftPM's sandbox, `MTLCreateSystemDefaultDevice()` returned nil: no GPU for llama.cpp or MLX.
  - **The Xcode 27 plug-in**, deferred by the call above.
- 2026-10-31 — Signing (wall W3) cannot be fixed here. `codesign -dv` on `apogee` says `flags=0x20002(adhoc,linker-signed)` and `TeamIdentifier=not set`. Xcode's binaries suggest that an agent's approval is tied to its signature and its hash, and that an unsigned agent gets time-limited approval: `unsignedRequiresExpiration`, `unsignedTTL` and "Unsigned agent attached" in `IDEIntelligenceFoundation`, and "Refusing …: no valid code signature." in `IDEIntelligenceChat`. These are strings, not observed behaviour. The likely cost is approving again after every `make install`, and approving `apogee-dev` apart from `apogee`. The live pass records the prompts seen. 56d states this to the user, and `acp.md` repeats it.

**Open calls:**
- [default: **the translator shape**: each session is a captured child, `apogee execute` in machine mode in the session's `cwd`. The alternative was an ACP `SessionOutput` over `run_session` in-process, as the shell's Session view does it. It lost on three counts. First, the session core reads the process's folder (the project opening at `chat_session.cpp:1356`, the attachments' folder at `:1827`, the tools at `business/tools/toolsets.cpp:40-62`, whose comment says "Nothing in Apogee changes the working directory after startup"), and every child it starts inherits that folder. Second, "a fatal error inside llama.cpp takes the process down" (SPEC.md:19): in-process, Xcode would lose its agent; as a child, it loses one session and is told why. Third, as a translator, ACP can only say what machine mode says, and `cli.machine_schema_conformance` pins that. Cost: a second process per session, and POSIX only, since `start_child` has no Windows implementation (`child_process.h:113`) — a recorded skip, as for the vendor CLIs. Xcode runs only on macOS, so the skip costs Xcode nothing; it bounds other ACP hosts on Windows. Recommendation: take it.]
- [default: **ACP protocol version 1**, pinned in one constant with the day it was last checked against the schema (2026-10-31). A host asking for another version is answered 1, as the spec says. Recommendation: take it.]
- [default: **one live session per process.** A `session/new` ends the session before it: its child's stdin is closed. A prompt to an ended session gets a JSON-RPC error saying a newer session replaced it. Each child holds its own model, so this keeps one model in memory. Xcode 27.1 has no `notice` string, so for a host without it they lead the next turn's `agent_thought_chunk` stream, where the person can unfold them, never inside the answer. **Guardrail(s).**
- **`cli.acp_conformance`** (`tests/scripts/py/acp_host_check.py`, registered beside `cli.reference_driver`). A scripted JSON-RPC client drives the real binary over pipes, as an ACP host would, with the mock backend, a temporary `APOGEE_HOME` and a temporary project folder holding an `AGENTS.md`. It checks:
  - **`initialize`:** version 1 and the capabilities above; a request for version 2 is answered 1.
  - **`session/new`:** the project's notices, the folder attached and the coder persona; the modes and config options, default first; a relative `cwd` refused with `-32602`.
  - **A prompt:** thought chunks, message chunks, a `tool_call` with its kind and updates, a `plan` from `todo_write`, then `end_turn`.
  - **Cancel mid-turn:** `cancelled`, no error, and the session takes the next prompt.
  - **Permission, every answer:** `allow_once` runs the write; `reject_once` leaves the file byte-identical; a `cancelled` outcome denies.
  - **Switching:** `session/set_config_option` across two mock backends, after which the next turn is the second's; a subscription-type backend is listed (a fake CLI on `PATH`). Plan mode refuses a write in plan's words.
  - **Bad input:** an unknown method gets `-32601`; a frame with unknown fields is still answered; a non-JSON line gets `-32700`, and the process lives.
  - **stdout:** every line parses as one JSON-RPC message, with a noisy child's stderr nowhere on it.
  - **A dying child:** the prompt's error carries its last stderr line, and `acp` keeps answering. A second `session/new` ends the first. Closing `acp`'s stdin ends every child and exits 0.
- **Units.** The `translate` tables, where every machine event type is mapped or deliberately dropped and an unmapped type fails, as the parity laws do. The kind table, held to the native registry, so a new native tool is classified or the test fails. JSON-RPC framing. `dispatch`'s `tool_call` states (`tests/business/agent/`). `ChildCommand`'s folder (`platform/child_process_test`).
- **Standing checks.** `cli.machine_schema_conformance` covers the growths. `cli.no_listen_symbols` scans the new module by construction. `cli.complete_opens_no_listening_socket` (`tests/scripts/sh/no_listen_check.sh`) gains a phase that samples an ACP turn across `acp`'s whole process tree and requires that it saw the child. The shell law (ADR 0010), the HTTP parity table and completion tests for `acp`'s flags all hold. The Xcode fixture is replayed once captured.

**Acceptance criteria:**
- [ ] `apogee acp` serves an ACP host on stdio. A prompt is one turn of `execute`'s loop in the session's folder (project context, folder attached, coder persona), streamed as updates and ending in the right stop reason, and `session/cancel` ends a turn as `cancelled`. Apogee's gate asks through `session/request_permission` and obeys the answer. Every configured chat backend, the subscription CLIs included, is offered as a model, default first; manual, accept-edits and plan are offered as modes.
- [ ] Nothing but JSON-RPC reaches stdout, no socket is opened (both checks), and the child's stderr is captured.
- [ ] Help, completion, the shell carve-out and its refusal, and the HTTP carve-out all land. Machine mode's growths are documented and pinned, `reference/acp.md` is written, and the full suite is green.
- [ ] The Xcode fixture is captured and replayed, or the schema's examples stand in and the reference doc says so.
- [ ] **The user's live pass**, on the dev channel. Install with `make -C lib/src/cli install MODE=dev`. In Xcode 27.1's "Add an Agent", register `apogee-dev` by its absolute path, written out in full (Devin's guide: Xcode does no `~` or `PATH` lookup), with the argument `acp`. With a project open: a local model answers; a write asks in Xcode's sheet, and both answers do what they say; Stop ends a turn; a subscription backend picked from the model menu answers (call 2).
