# An unusable rerank reply keeps the chunks, a query rewrite searches with the query, and cancel stops a turn's side calls

**What / why.** Before a chat turn reaches the agent loop it can make several model calls of its own: compaction, the follow-up's query rewrite, the attachments' and the collection's retrieval (an embedding of the question, then the rerank judge), and recall. Each of these is meant to help the turn and never cost it anything. The second CLI/GUI bug sweep (2026-10-31) found three places where one of them costs the turn its context or its Stop button. Re-read at HEAD (`b26550bb`):

1. **A rerank reply with no usable ids is taken as the judge's "none help" verdict, and every retrieved chunk is dropped.** `parse_rerank_ids` (`rerank.cpp:100-130`) reads the first bracketed span in the reply. When that span is a JSON array, it returns the ids it could use, skipping a non-integer entry (`:117-119`) and one out of range or repeated (`:121-125`). So an array with entries but none usable comes back as an empty vector, not `nullopt`. That covers string ids such as `["2","1"]`, and a prose mention such as `Passage [3]` when there are fewer than 3 candidates. `rerank()` checks only `has_value()` (`:173-179`) and then applies the empty vector as a verdict: `applied = true`, zero hits (`:181-187`). `rag.cpp:401-405` takes those hits and `reranked = applied`, nothing is injected, and the notice says `no matching context in '<collection>'` (`retrieval.cpp:137-139`). Because only the first span is read, a reply like `Passage [3] is off-topic; the ranking is [2, 1]` with 3 or more candidates is applied as the one-item ranking `[3]`, and the judge's real ranking is dropped without a word. Probe (`complete -m actor --rag notes --rerank judge --rag-limit 2 'where do pelicans nest'`, a 2-chunk lexical collection, the mock judge replying in turn): `[2, 1]` gave `2 chunk(s) from notes ... [lexical, reranked]` and both excerpts in the system message. `["2", "1"]` gave `[apogee] no matching context in 'notes' [lexical]` and `ANSWER sys=[]`. `Passage [3] is off-topic; the ranking is [2, 1]` gave the same empty result. Regression of [Milestone S](../../assistant/MILESTONES.md#milestone-s--the-retrieval-matrix)'s (ranked, applied) contract (MILESTONES.md:4465: "every failure path returns raw order with `applied = false`; an empty array is a verdict, not a failure"). The existing parse test (`tests/business/agentloop/rerank_test.cpp:72-85`) pins junk ids dropped from a mostly good ranking, but no reply whose ids are all junk.
2. **A chat turn's pre-loop model calls get an empty cancellation token, so the GUI's Stop and the terminal's Ctrl-C wait for them to finish.** `run_chat_turn` takes the turn's token (`chat_turn.cpp:40`) but hands it only to the loop (`loop_options.cancellation`, `:104`). Every call before the loop gets `{}`: compaction (`:75-76`, `compact_history(harness, session.messages, compactor)`, whose token defaults to `{}` at `content.h:133-136`), both query rewrites (`:177` and `:196`, `rewrite_query(..., input, {})`), the attachments' retrieval (`:215`, `attached->for_turn(..., rag.limit, {}, side)`), and the collection's embedding and rerank judge (`:232-234`, `retrieve_for_collection(..., session.rerank, {}, session.backend, ...)`). Recall cannot be given one at all: `ChatRecall::for_turn` takes no token (`chat_recall.h:133-135`), its `RagTurn` leaves `cancellation` unset (`chat_recall.cpp:203-216`, the field at `rag.h:133`), and its knowledge search passes `{}` (`chat_recall.cpp:243-245`). So a machine-mode `cancel` (the GUI's Stop) or a Ctrl-C does nothing until all of these finish. A long compaction, or a hung judge or embedder, cannot be stopped. Failure scenario: a chat on a local 27B near 90% of a 128k window; the user sends a message and auto-compaction starts summarising the whole conversation (minutes of prompt processing); the user presses Stop or Ctrl-C; nothing happens until the compaction (and then the rewrite, embedding and rerank calls) completes, and only then does the turn end `cancelled`. `serve` shows this is not deliberate: its handler passes its token to the same calls (`handler.cpp:412-413`, `:475-482`). `task run` and `task resume` reach the same function (`task_cmd.cpp:868`). This contradicts [machine-mode.md](../../reference/machine-mode.md#stopping-a-turn-cancel) (line 555, "The model call is abandoned"), [Milestone M](../../assistant/MILESTONES.md#milestone-m--the-front-end-contract)'s "Cancel is Ctrl-C" (MILESTONES.md:3270), and Milestone S's "Judge timeout" decision (MILESTONES.md:4484), which accepts a hung judge only because "Ctrl-C cancels". It also leaves 26d's tested cancel-while-embedding (MILESTONES.md:1059, the "cancellation ignored while embedding" mutant) unreachable from chat.
3. **A query rewrite that opens with a chatty line searches with that line, and the follow-up's retrieval is lost.** `query_of` (`query_rewrite.cpp:43-70`) takes the first non-empty line of the utility model's reply. It strips `Query:`, `query:` or `Search query:` only when the line starts with one (`:58-62`). `rewrite_query` (`:143-149`) accepts any non-empty line of 400 bytes or less with `rewritten = true` and no note. So a reply that opens with `Sure! Here is the standalone search query:` and gives the real query on a later line searches with the preamble. The retrieval floor (26s) then rejects every match, and the follow-up gets no excerpts. Probe (machine-mode chat, `--rag notes` over one chunk `Pelicans nest on the coast of Peru...`, a mock utility set with `config set-default-utility util`): with util replying `Sure! Here is the standalone search query:\n\nwhere do pelicans nest in Peru`, turn 2 logged `nothing relevant in 'notes' -- the best match is under the floor (0.000 [lexical], none of the question's words)` and `ANSWER sys=[]`. With util replying just `where do pelicans nest in Peru`, turn 2 logged `1 chunk(s) from 'notes', strong match (... 3 of 3 question words)` and the excerpt was injected. No test covers a preamble line (`query_rewrite_test.cpp:106-114` pins a label on the first line). The header's "never fails a turn" promise (`query_rewrite.h:20-21`) names errors, empty replies and long answers; a preamble falls outside that list but defeats the same purpose. Rated medium to low: how often it bites depends on how often the utility model ignores the one-line instruction (`query_rewrite.cpp:26-29`).

What already works: a judge reply of `[2, 1]` reorders and is reported `reranked`; a genuine `[]` is a verdict; a reply with no array, or a judge that throws, degrades to raw order with a note. A bare-query rewrite retrieves. `serve` passes its token to compaction, the rewrite and retrieval. `rewrite_query` already rethrows `CancelledError` (`query_rewrite.cpp:136-137`). The loop's own cancel and half-turn rollback work, and machine mode restores the session to before the turn on a cancelled outcome (`chat_session.cpp:1711-1724`, `:1784-1786`).

**Core constraint(s).**
- **One retriever per turn, resolved once, reported honestly**: its sub-rule "Rerank can never cost context: every judge failure returns raw order with `reranked: false`, and `reranked` is set from the same place as the ordering." A reply that is not a usable ranking is a judge failure. Only an empty array is the "none help" verdict.
- **How strong a match is, and the floor, are per retriever too** (26s): unchanged. Entry 3 is about what is searched, not how its scores are read.
- Machine mode's cancel contract ([machine-mode.md](../../reference/machine-mode.md#stopping-a-turn-cancel)): the model call is abandoned, the half-turn is rolled back, and the session is left as the last finished turn left it. That now holds for every model call in the turn, not just the loop's.
- **The harness never includes backends** (the four layers): the token is threaded through `business/agentloop` and `presentation/operations` as it already is for `serve`; no new seam.
- The item's own rules: a side call that fails or is misread degrades to the turn as it would have run without it, and says so. A cancel is said as a cancel, never as a failed compaction, a raw-order rerank or a lexical fallback.
- **Development runs on the dev channel**: any live check runs `apogee-dev`, never the release `apogee` or `~/.apogee`. Probes use a temporary `APOGEE_HOME` under the scratchpad.

**Seam + files.**
- `business/agentloop/rerank.cpp/.h`: `parse_rerank_ids` returns `nullopt` when the array has entries but no usable id, and when the reply holds more than one array-shaped span. A whole-number string id (`"2"`) is read as the number. `rerank()` lets `CancelledError` through its catch (`:165`) instead of degrading it to raw order.
- `business/agentloop/query_rewrite.cpp`: `query_of` skips lead-in lines (a line ending in `:`) and strips the labels wherever the chosen line starts with one, case-insensitively. A reply made only of lead-ins is "not a query".
- `business/agentloop/content.cpp`: `compact_history`'s catch (`:144`) rethrows `CancelledError` before the `HarnessError` it degrades.
- `business/agentloop/rag.cpp`: the catches that degrade a retrieval (`:185`, `:220`, `:292`, `:304`, `:388`) rethrow `CancelledError` first.
- `presentation/cli/chat_turn.cpp`: the turn's `cancellation` reaches compaction, both rewrites, `ChatAttachments::for_turn`, `retrieve_for_collection` and `ChatRecall::for_turn`. Today the pre-loop section (`:59-260`) runs before the `try` that maps `CancelledError` to a cancelled outcome (`:298`, the catch at `:313-315`), so a cancel thrown there would escape `run_chat_turn`. The fix brings it under that mapping (the `try` widened, or the pre-loop calls given the same catch), so a cancel there ends the turn the way a cancel in the loop does.
- `presentation/cli/chat_recall.cpp/.h`: `for_turn` takes the token, sets `RagTurn::cancellation`, and passes it to the knowledge search.
- Tests: `tests/business/agentloop/rerank_test.cpp` (the parse cases and the cancel), `tests/business/agentloop/query_rewrite_test.cpp` (the preamble cases), `tests/business/agentloop/content_test.cpp` and `rag_test.cpp` (a cancelled side call throws `CancelledError`, not a degraded result), `tests/presentation/machine/machine_mode_test.cpp` (a `cancel` during compaction, during the judge and during recall ends the turn `cancelled` while the call is still running), and `tests/presentation/cli/complete_sources_test.cpp` or a new `chat_turn_test.cpp` mirroring `chat_turn.cpp` (the probes' rerank and rewrite cases end to end).

**Open calls:**
- [default: an array with entries, none of them usable, is "not a ranking": raw order, `applied = false`, the existing note. Only a literally empty `[]` is the "none help" verdict.]
- [default: a string that holds a whole number (`"2"`) is read as that id. The prompt asks for numbers, but the parser already tolerates prose and fences (Milestone S), and a quoted id is plainly an id.]
- [default: a reply with more than one array-shaped span (`Passage [3] ... [2, 1]`) is ambiguous and degrades to raw order with a note naming that. The alternative, taking the last span as the conclusion, guesses; raw order costs only the improvement, which is what Milestone S accepts for a misbehaving judge. A fenced reply has one span and is unaffected.]
- [default: in `query_of`, a non-empty line that ends in `:` is a lead-in and is skipped; the first line after the lead-ins is the query, with `Query:` / `Search query:` stripped case-insensitively. Later lines are ignored, as now. A reply of lead-ins only keeps the question as asked, with the "not a query" note.]
- [default: no second search with the original question when the rewritten query is floored. That would be a retrieval policy change, not this fix.]
- [default: a cancel during any pre-loop call ends the turn `cancelled` and discards the whole turn, including a compaction that finished before the cancel: the session is left as the last finished turn left it, as machine-mode.md:555 says. Machine mode already restores its `before` snapshot; the terminal chat's cancelled path is checked to do the same.]
- [default: every catch that degrades a side call (compaction, rerank, the embedding fallback, retrieval's own catches) rethrows `CancelledError` first, as `rewrite_query` already does, so a cancel is never reported as "compaction failed", "using raw retrieval order" or "searched lexical only". This also corrects `serve`, whose rerank catch today swallows a cancel the same way.]

**Guardrail(s).**
- `parse_rerank_ids`: `["2","1"]` with 2 candidates reads `{2, 1}`; `[3]` with 2 candidates, `["x"]`, `[0, -1]` and `[1.5]` are `nullopt`; `Passage [3] is off-topic; the ranking is [2, 1]` is `nullopt` with 2 candidates and with 5; `[]` still has a value and is empty; the existing prose, fence and junk-id cases still pass. `rerank()` over each of those: raw order, `applied = false`, a note.
- The probe's three judge replies through `complete --rag notes --rerank judge` (temp `APOGEE_HOME`, mock backends): none of them ends in `no matching context`; `[2, 1]` is `reranked`, the other two inject both chunks in raw order and say why.
- `rewrite_query` with the preamble reply returns `where do pelicans nest in Peru`, `rewritten = true`; a lead-in-only reply keeps the question with the note; the existing first-line and label cases still pass. The probe's two-turn machine-mode chat injects the chunk on turn 2 with the preamble reply.
- Machine mode with a mock or fake provider that blocks until its token is cancelled, one case each for compaction, the query rewrite, the rerank judge, the embedder and recall: a `cancel` ends the turn in one `result` with `finish_reason: "cancelled"` within a bounded wait, the blocked call saw its token cancelled, and the saved session equals the one before the turn. A side call's degrade catch, given a `CancelledError`, rethrows it (one case per catch).
- `serve`'s existing cancel and rerank tests stay green.

**Acceptance criteria:**
- [ ] A rerank reply that is not a usable ranking (string ids, out-of-range ids only, more than one bracketed span) keeps the retrieved chunks in raw order and says so; only `[]` drops them.
- [ ] A rewrite reply that opens with `Sure! Here is the standalone search query:` searches with the query on the next line, and the probe's follow-up gets its excerpt.
- [ ] Stop in the GUI and Ctrl-C in the terminal end a chat turn while compaction, the rewrite, the embedding, the rerank judge or recall is running, without waiting for it; the turn ends `cancelled` and the session is as the last finished turn left it.
- [ ] No cancel is reported as a failed side call on any surface; the full suite is green.
