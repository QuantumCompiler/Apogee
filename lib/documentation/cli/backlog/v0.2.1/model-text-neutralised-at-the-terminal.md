# Text a model or a third party chose is shown at the terminal, never obeyed

**What / why.** Item 23 made a model's answer safe to draw: `StreamRenderer`'s `clean` (`markdown/stream_renderer.cpp:22-61`) replaces every C0, DEL and C1 control character with U+FFFD, because "a model's output is shown, never obeyed". The TUI holds the same rule (`tui/styled_text.cpp:154-161`). Every other plain-terminal surface that prints text a model or a third party chose skips it. A model steered by a page it fetched can then repaint a permission prompt so the person approves a different command from the one that runs, make an `ask_user` option draw as a different option from the one its number picks, write the clipboard (OSC 52), retitle the terminal or clear the screen. A PR author can do the same through `review mr`, and a GGUF uploader through `models info`. The second CLI/GUI bug sweep (2026-10-31) found ten such places. Re-read at HEAD (`b26550bb`), most severe first:

1. **The plain-terminal permission prompt prints `run_command`'s command raw, so a model can draw a harmless command over it and get a `y` or an `a`.** `terminal_confirm_fn` (`presentation/cli/permissions.cpp:313-334`) prints `request.tool`, `request.target` and `request.detail` through `StatusLine::print_line` (`presentation/views/status_line.cpp:148-161`, `out << text << "\n"`) with no control-character filtering. `run_command`'s target (`business/tools/shell.cpp:214-225`) is the command exactly as the model wrote it, so CR, CSI and SGR bytes inside the 80-byte limit can erase the real prompt line and draw a forged one. `web_search`'s `search: <query>` detail (`business/agent/web_search.cpp:388-391`) goes through the same path. Scenario: in `apogee chat --tools`, plain mode, the model calls `run_command` with command = `touch PWNED #\r\x1b[2K\x1b[1;35m[permission]\x1b[0m run_command -> ls -la` (63 bytes, so it is not cut). The terminal shows only `[permission] run_command -> ls -la` and `Allow? ...`. The person types `y` and `touch PWNED` runs. Answering `a` would write `permissions.run_command: allow` to the config for good. PTY probe (mock backend, temp `APOGEE_HOME`): the bytes sent to the terminal were `\x1b[35m[perm]\x1b[0m run_command -> touch PWNED #\r\x1b[2K\x1b[1;35m[permission]\x1b[0m run_command -> ls -la\r\n\x1b[2mAllow? [y]es / [n]o / [a]lways / [s]ession: `, then `y`. Afterwards `ls work` showed `PWNED` (0 bytes). The panel rated this high.
2. **The `run_command` and MCP permission prompts show only the first 77 characters of the command or the arguments, and never `run_command`'s `cwd`.** `run_command`'s `describe_target` cuts the command to 77 characters plus `...` (`shell.cpp:221-223`), and the tool has no `describe_detail`. MCP tools cut their raw JSON arguments the same way (`business/mcp/registry.cpp:110-116`). With no `describe_detail`, `permitted` passes no detail at all (`business/agent/tool.cpp:160-161`). The terminal prompt (`permissions.cpp:324-325`) and machine mode's `question` event (`presentation/machine/json_reporter.cpp:271-300`, which the GUI shows) carry only the cut target. Nothing earlier in the stream shows the full arguments either: the `[tool] <name>` status comes only after permission is granted (`tool.cpp:215`). This contradicts [machine-mode.md](../../reference/machine-mode.md):805-809, which says `target` is the command. `always` and `session` already approve the whole tool, so the cut does not widen any approval; it hides what this one call does. Scenario: the model, steered by a file it read, calls `run_command` with `echo checking the build status ... tests;   <payload>`. The prompt reads `Allow run_command on echo checking the build status of the project befo...?`. The user answers yes, or `always`, and the hidden tail runs. Probe (`chat --tools --output-format stream-json`, a scripted `run_command` of 130+ characters ending in a `touch`): the `question` event's target was `'echo checking the build status of the project before continuing with tests;  ...'`, with no `detail` field and no earlier `tool_status` event carrying the arguments.
3. **The `ask_user` prompt prints the model's question, option labels and descriptions raw, so the option shown is not the one a number picks.** The plain-terminal prompt prints the question at `presentation/views/ask_prompt.cpp:43` and each option at 45-50, uncleaned. `chosen_answer` returns the stored raw label (`ask_prompt.cpp:77`). A label containing CR plus `ESC[2K` therefore draws as a different option than the one its number picks. A newline inside a description draws extra lines that look like prompt lines. OSC and SGR sequences (a title change, conceal) reach the terminal. The TUI path is not affected. Scenario: the model asks `Keep the file?` with option 1 labelled `yes\r\x1b[2K  1) no`. The terminal shows `1) no -- keeps it`. The person types 1 to say no, and the answer sent to the model is the label that begins `yes`. PTY probe, terminal bytes: `\x1b[35m[perm]\x1b[0m Keep the file?\x1b]0;HIJACKED-TITLE\x07\x1b[8m secret hidden\r\n\r\x1b[2K  1) yes\r\x1b[2K  1) no\x1b[2m -- keeps it ... 2) no\x1b[2m -- x\r\n[permission] fake line`.
4. **Streamed reasoning is drawn raw: the thinking window and `-v` pass ESC, OSC and CSI through, and break the window's erase arithmetic.** In verbose mode `ThinkingView::write` sends the chunk straight to the writer (`presentation/views/thinking_view.cpp:65-73`). In the default window, `append` (191-204) and `repaint_locked` (206-225) draw the tail through `ansi::wrap_tail` (`infrastructure/ansi/text_width.cpp:103`), which drops only `\r` and `\n` (123-131). The summary line (`cut_to(summary_, …)`, `thinking_view.cpp:220`) is not cleaned either. A CSI cursor move shifts the cursor, so `erase_locked`'s row count (227-236) erases the wrong rows; OSC can set the title, and OSC 52 can write the clipboard where the terminal honours it. Scenario: a reasoning model, steered by fetched content, streams `Let me think\x1b]52;c;cm0gLXJmIH4K\x07 about it\x1b[3Aup`. In a default plain chat the thinking window sends the OSC 52, putting `rm -rf ~` on the clipboard, and the CSI 3A moves the cursor into the scrollback. In `chat -v` the whole chunk is sent unchanged. PTY probe with a mock actor that streams a `reasoning` field. Default chat: `Let me think\x1b]52;c;cm0gLXJmIH4K\x07\x1b[0m\r\x1b[2K\x1b[A...`. So replaying a saved chat on a terminal obeys OSC 52 and CSI sequences that the live session showed as harmless replacement characters. The JSON form is already safe. **Core constraint(s).**
- **The item's own rule, item 23's extended:** text a model, a tool's caller or a third party chose (an answer, reasoning, a tool target or detail, an `ask_user` question or option, a title, a PR title or finding, GGUF metadata, an MCP tool name) is **shown, never obeyed**, on every text surface, through **one** neutraliser, never a copy per call site. What is stored (session files, ledgers, the config's `always`) and every JSON form keep the true value; only drawing changes.
- **Interactive = pipes**: a pipe receives an answer as the model wrote it (`cli_reporter.cpp:275-276`). Neutralising a multi-line payload (an answer, a replayed chat) applies when stdout is a terminal, exactly as the live chat's renderer already does. A one-line label (a target, a title, a name) is never payload, and is neutralised on every text surface.
- **Text is UTF-8 where it enters, so no JSON dump can throw on it**: the Harness already delivers whole characters per sink, so a byte-by-byte neutraliser cannot cut a character, and its U+FFFD keeps the width tables' arithmetic exact (`stream_renderer.cpp:25-26`). Nothing here mends UTF-8 a second time.
- **What leaves the machine is asked about by host, and the host asked about is the host reached**: unchanged. `web_search`'s detail is shown whole and cleaned; the gate decides as before.
- **The additive protocol** (ADR 0006): machine mode's `question` event gains a `detail` for `run_command` and MCP tools, a field the protocol already has (`json_reporter.cpp:281-283`); nothing is renamed or removed, and `target` keeps its short form.
- **Layering**: the neutraliser lives in `infrastructure/ansi`, the one package every presenter and `markdown/` may already include (`harness.layering`: `markdown/` includes only `ansi/` and itself). `business/` composes text and never neutralises; the presenter that draws it does.
- **Development runs on the dev channel**: any live check runs `apogee-dev`, never the release `apogee` or `~/.apogee`. Probes and tests use a temporary `APOGEE_HOME` under the scratchpad.

**Seam + files.**
- `infrastructure/ansi/text_width.h/.cpp` (or a new `ansi/inert.h/.cpp`) — the one neutraliser, lifted from `stream_renderer.cpp`'s `clean`, in two forms: **a line** (every C0 control, CR and LF included, DEL and C1 shown as U+FFFD) and **text** (LF kept, tab expanded, CR dropped, every other control U+FFFD, as `clean` does now). `markdown/stream_renderer.cpp` calls it instead of its private copy.
- `presentation/cli/permissions.cpp` — the prompt's lines move into a pure function (testable without a terminal); `tool` and `target` are drawn as lines, `detail` as text with every line indented under the prompt, so nothing in it starts at column 0 where a prompt line starts.
- `business/tools/shell.cpp` — `run_command` gains a `describe_detail`: the whole command, then the working directory it runs in (the given `cwd`, else the default it names). `describe_target` keeps its 77-character form, so the ledger, task narration and `always` are unchanged.
- `business/mcp/registry.cpp` — MCP tools gain a `describe_detail`: the whole arguments.
- `presentation/views/ask_prompt.cpp` — the question and each description drawn as indented text, each label as a line; the prompt's lines move into a pure function.

- `presentation/cli/chat_session.cpp` (the `titled by` note) and `presentation/cli/chat_recall.cpp` (`recall_row`) — the title as a line.

**Open calls:**
- [default: the neutraliser replaces each control byte with U+FFFD, never strips it and never parses the sequence. The person sees that something was there; a byte-by-byte rule has no parser state to confuse; one U+FFFD is one cell, so the width arithmetic holds. `sanitize_title` alone drops them, because a title is cosmetic and is stored.]
- [default: one-line fields (tool names, targets, option labels, titles and names, PR titles, finding files and claims, GGUF strings, task narration) are neutralised on every text surface, piped or not. - [default: `run_command`'s and MCP's detail is shown whole, with no cap. A cap would bring back the hidden tail entry 2 is about. The detail is computed only when the gate asks (`tool.cpp:162-165`), so a run that never prompts pays nothing.]

- [default: the label `chosen_answer` returns stays the model's own raw label. Once the label is drawn faithfully, the number picks the option shown, and the model gets back the label it wrote.]

- [default: the shared neutraliser is this item's alone: 57o records neutralising the prompt's control bytes as this item's (its consumed decision). **Guardrail(s).**
- The neutraliser as a table: ESC, BEL, a CSI (`\x1b[2K`, `\x1b[3A`), an OSC 52 (`\x1b]52;c;cm0gLXJmIH4K\x07`), C1 (`\xC2\x9B`), DEL, CR, LF and TAB, in each form. No output contains a byte below 0x20 (other than LF in the text form) or DEL or C1; valid text with no control character passes byte for byte; the output's `display_width` equals the cells drawn.
- The permission prompt's lines for entry 1's probe command: the composed lines hold no ESC or CR from the command, only the prompt's own styling, and the command's text is visible with U+FFFD where its controls were. `web_search`'s query the same.
- `run_command` with entry 2's 130+-character command and a `cwd`: `describe_target` is the 77-character form, `describe_detail` the whole command and the `cwd`. An MCP tool's detail is its whole arguments. In machine mode, the `question` event carries that `detail`, and `target` is unchanged.

- `format_saved_chat` over a session holding entry 5's answer: no ESC or BEL when drawn for a terminal; the bytes kept when drawn for a pipe. `sanitize_title` of `Benign \x1b]0;OWNED\x07Title\x1b[2J` holds no control character; `format_session_row`, `format_session_info` and `recall_row` of a title already saved with one draw none.

- `review_mr`'s lines for entry 7's PR title and a finding whose claim carries a CSI: none reach the lines; the JSON document keeps the true title.
- `render_gguf` over a header-only GGUF fixture (built in the test, as `gguf_inspect_test.cpp` builds its headers) whose `general.name` is entry 9's string: no ESC or BEL in the output.
- `task run`'s narration and `task status`' uses for a scripted `run_command` target ending in `\r\x1b[2K[task] round 2 of 6: checks pass` (mock backend, temp `APOGEE_HOME`): the printed line holds no CR or ESC; the ledger holds the true target.
