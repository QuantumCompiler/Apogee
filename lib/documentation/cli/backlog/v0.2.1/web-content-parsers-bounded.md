# The web-page reader stays linear on hostile pages, an HTML attachment keeps its declared charset, and a `#` redirect stays on its page

**What / why.** `agent/readable` is the one reader that turns untrusted HTML into the text a model reads: every page `fetch_url` brings back, and every `.html` file given to `--attach` (`agentloop/attachments.cpp:265`). The page is chosen by whoever runs the site, so the reader's cost has to grow with the page's size and nothing else, and what it returns has to be the page's own words. The second CLI/GUI bug sweep (2026-10-31) found three shapes of page that make the reader super-linear, one place where an attachment loses its declared charset, and one redirect form resolved to the wrong page. The cost cases matter because a `fetch_url` call holds the turn: one CPU core runs flat out, nothing prints, and every read-on call with an `offset` fetches and extracts the page again (`fetch_url.cpp:327-346`, then `extract_readable` at `fetch_url.cpp:422`), so a hostile page costs the same again for each page of it. Re-read at HEAD (`b26550bb`):

1. **Nested tables take exponential time.** `render_table` (`readable.cpp:894`) renders every cell once as a line to measure it (`inline_text(cell)`, `readable.cpp:907`), and a cell that holds a table marks the table as layout (`readable.cpp:908`). Then the layout path (`if (layout || widest < 2)`, `readable.cpp:939`) renders every child again as blocks (`readable.cpp:944`). Each level renders the level below it twice, so N nested tables cost 2^N. The cap `kMaxDepth = 256` (`readable.cpp:220`) limits the parse depth of elements, not this. A page of `<table><tr><td>x` repeated N times: a probe linked against the built `libapogee_business_agent.a` took 114 ms at n=18, 444 ms at n=20 and 3486 ms at n=23 (about 2x per level; on a second run n=14/16/18/20 took 6/28/113/454 ms). On the real binary (mock backend, a local `http.server`, `--allow-host 127.0.0.1`), a 431-byte `deep.html` (25 levels) went from fetch to answer in 16 s, output `x x xdeep`. N=30 takes about 8 minutes and N=40 days. Ordinary old-style layout pages slow down too: the same 229 KB of posts inside 0/4/8/10 nested two-cell tables took 0.02/0.07/0.97/3.86 s. The 16 s and layout-page figures were not re-measured by the panel; the library doubling was. [25f](../../assistant/MILESTONES.md#2026-09-28--fetch-url-reader-backlog-item-25f-fetch_url-reads-a-page-as-a-model-should) (MILESTONES.md:4928, "nesting capped at 256") presents the cap as the guard against pathological nesting, and it does not cover this.
2. **A run of bare `&` is quadratic.** `decode_entities` (`readable.cpp:103`) calls `text.find(';', i + 1)` across the rest of the string for every `&` (`readable.cpp:111`), and only then rejects a semicolon that is missing or more than 12 bytes away, moving on one byte. Text nodes, attribute values and `<title>` all go through it (`readable.cpp:323`, `369`, `376`, `412`, `415`). `fetch_url` hands it the whole body, up to the 5 MiB `kFetchMaxBodyBytes` (`presentation/cli/helpers.h:127`). Probe: 200k `&` took 361 ms and 1M took 8.7 s; a standalone -O2 copy of the loop took 358 ms and 8.8 s. Real binary, mock backend: a 1.5 MB `amp.html` took 21 s from fetch to answer (`Page 1 of 123`). Extrapolated to the 5 MiB cap: about 230 s per call. A local `.html` attachment under the 50 MiB large-set threshold (`agentloop/attachments.h:47`, which asks first only above it) scales to hours. The attachment path's re-reads were not checked.
3. **Empty links nested deep cost depth x size.** When a link's inline text is empty, `render_link` (`readable.cpp:854`) walks every node after it while `tree_.within(k, index)` holds (`readable.cpp:859`), looking for an `<img>` whose alt text to use, and `within` (`readable.cpp:258-267`) climbs parent links one at a time to decide each step. The tokenizer never closes an open `<a>`: `open` (`readable.cpp:463`) implies ends only for `p`, `li`, `dt`/`dd`, `tr`, `td`/`th`, the table sections and `option` (`imply_ends`, `readable.cpp:437-461`). So nested `<a>` elements each render through `inline_text` -> `render` -> `render_link`, and every level re-scans everything below it, bounded only by the 256-level stack cap. Measured with the built agent library on 250 nested `<a href=x>` followed by empty `<i></i>`: 0.52 s at 142 KB, 1.14 s at 282 KB, 2.2 s at 562 KB and 22.6 s at the 5 MiB fetch cap; the same 5 MB with no nesting takes 0.13 s. At a fixed size the growth is about linear in depth (125 levels 1.03 s, 250 levels 2.2 s). A second probe: 142 KB 0.62 s, 282 KB 1.16 s, 562 KB 2.56 s, against about 0.02 s for an ordinary 229 KB page. About 20 s of CPU per fetch and per read-on call.
4. **An HTML attachment ignores its `<meta charset>`.** `read_html` (`agentloop/attachments.cpp:246`) calls `agent::extract_readable(agent::as_utf8(bytes, {}), base)` (`attachments.cpp:265`): an empty charset, and no `meta_charset` call anywhere in `agentloop/` (grep). `fetch_url` does both: `charset_of` the response's type, else `meta_charset(result.body)` for HTML, then `as_utf8` (`fetch_url.cpp:415-419`). `meta_charset` (`readable.cpp:1190`) and the Latin-1 / windows-1252 table in `as_utf8` (`readable.cpp:1213`) exist and are tested (`readable_test.cpp:332-336`). `looks_binary` checks for NUL bytes only (`attachments.cpp:253`), so the file is accepted and quietly garbled instead of refused. `apogee-dev chat --attach legacy.html`, where the file declares `<meta charset="iso-8859-1">` and says "café, naïve, Müller": the text indexed and handed to the model reads "caf�, na�ve, M�ller". The same page fetched with `fetch_url` reads correctly.
5. **A fragment-only `Location` resolves to the parent directory.** `resolve_redirect` (`fetch_url.cpp:235-268`) handles an absolute URL, `//host`, `/path` and `?query`, and treats everything else as a relative path joined to the base path's directory (`fetch_url.cpp:265-266`). `#x` lands there, and `encode_target` (`fetch_url.cpp:43-47`) then drops the fragment. So a 30x from `https://example.com/a/b.html` with `Location: #top` is followed to `https://example.com/a/`, and that page's content (or a 404) comes back as `b.html`'s. Resolved correctly (RFC 3986 section 5.2.2: a fragment-only reference keeps the base's path and query), it points back at `b.html` and ends in the redirect-limit error (`fetch_url.cpp:366-368`). Probe, `resolve_redirect(base=https://example.com/a/b.html)`: `#frag` gave `https://example.com/a/`; `?q=1` gave `https://example.com/a/b.html?q=1` (correct). The same resolution serves `<head><base href="#x">` (`readable.cpp:557-563`), which shifts every link on the page to the parent directory. Page links that start with `#` are unaffected: `link_target` filters them out first (`readable.cpp:843`).

What already works: element nesting deeper than 256 is flattened, not overflowed (`readable_test.cpp:310`, 20,000 `<div>`s read as `bottom`); an ordinary 229 KB page extracts in about 0.02 s; `fetch_url` honours both the `Content-Type` charset and a `<meta charset>`; a redirect to another scheme is refused, every other relative form in the redirect table (`fetch_url_test.cpp:236`) resolves right, and a new host on a hop goes through the gate.

**Core constraint(s).**
- **What leaves the machine is asked about by host, and the host asked about is the host reached**: `resolve_redirect` is part of that path (one hop at a time through `TargetGate`, at most ten). The fragment fix keeps every hop on the base's own host, so it adds no host the gate has not seen; the gate and the rebuilt URL are unchanged.
- **Text is UTF-8 where it enters, so no JSON dump can throw on it**: an attachment is a door text enters through. It is converted with the charset it declares, the way `fetch_url` already converts, and anything that is still not text becomes U+FFFD as now. `as_utf8` stays the one converter.
- The item's own rules: the reader's cost is linear in the page's bytes (a small constant times the node count), whatever its nesting, its entity text or its links. Every output the current tests pin stays byte-identical: a layout table still reads as paragraphs, a data table as `|` rows, an image link as its alt text, an unknown or unterminated entity as written. One reader for both callers: the attachment path keeps calling `extract_readable`, not a copy of it.
- **Development runs on the dev channel**: any live check runs `apogee-dev`, never the release `apogee` or `~/.apogee`. Probes use a temporary `APOGEE_HOME` under the scratchpad.

**Seam + files.**
- `business/agent/readable.cpp` —
  - `Reader::measure` (`readable.cpp:593`), the one bottom-up pass the reader already makes, also records per node whether it holds a `table` and the index of its first `img`. `render_table` reads the flag rather than `tree_.find("table", cell)` (which walks the subtree, once per level), and a cell that holds a table marks the table as layout **before** anything is rendered, so its `inline_text` is never built. A cell with no table inside is still measured by `inline_text`; the layout re-render then costs one more pass of a subtree with no tables in it, which cannot compound.
  - `render_link` takes its alt text from the recorded first `img`, with no `within` scan.
  - `Tree::imply_ends`: an `<a>` start tag closes an open `<a>` (HTML's rule: links do not nest, and browsers parse it this way), so each link's subtree is its own.
  - `decode_entities` looks for `;` only in the 12 bytes after the `&` (`text.substr(i + 1, 12).find(';')` or its equivalent), the bound the code already applies after the search.
- `business/agent/fetch_url.cpp` — `resolve_redirect`: a location that starts with `#` resolves to the base's path and query (`origin + base.target`), the fragment dropped by `encode_target` as now. `<base href="#x">` gets the same answer through the same function.
- `business/agentloop/attachments.cpp` — `read_html` passes `agent::meta_charset(bytes)` to `as_utf8`.
- Tests: `tests/business/agent/readable_test.cpp` (the hostile shapes and the unchanged outputs), `tests/business/agent/fetch_url_test.cpp` (the redirect table, and a scripted 30x with `Location: #top`), `tests/business/agentloop/attachments_test.cpp` (a Latin-1 `.html` attachment).
- Docs: none required; no help text or reference changes (the reader's behavior on ordinary pages is unchanged).

**Decisions made** (dated):
- 2026-10-31: Specced from the second CLI/GUI bug sweep (the user's call: every finding becomes a v0.2.1 item in its queue, CLI track 57, GUI track 6).
- 2026-10-31: One item, because all five are the same promise, that the parsers Apogee runs over untrusted web content are bounded and correct: entries 1-3 are the reader's cost on a hostile page, entry 4 the reader's input on its second door, entry 5 the URL resolution the reader and `fetch_url` share. They touch three source files (`readable.cpp`, `fetch_url.cpp`, `attachments.cpp`) and their three tests, and land together.
- 2026-10-31: The sweep rated entry 1 high, entry 2 medium, entries 3-5 low. Entry 3's first claim of depth² cost is corrected by its own measurement: at a fixed size the growth is about linear in depth, so the cost is depth x size.
- 2026-10-31: Each cost case is fixed at its root, not with a budget, so no page is cut short to stay fast.

**Open calls:**
- [default: no global time or work budget on `extract_readable`. The three causes are fixed where they are; a budget would truncate legitimate pages silently, and the regression tests below catch a new super-linear path.]
- [default: the cost tests use inputs where the old code is two or more orders of magnitude slower than the fixed code (25 nested tables, 1M bare `&`, 250 nested empty links in 2 MB), each with a generous ceiling of 2 s on the slowest CI row. A ceiling that wide does not flake, and the old code misses it by minutes. No test counts operations.]
- [default: an `<a>` start tag closes an open `<a>` wherever it is, the way a browser's parser does, rather than only when they are direct children. A page that nests links was already rendering them inside one another, which no browser shows.]
- [default: an attachment's charset comes from its `<meta charset>` alone; a UTF-8 BOM or a file with no declaration reads as UTF-8 as now. No `--charset` flag.]
- [default: a fragment-only redirect is not special-cased as a self-redirect: it resolves to the page itself, and the existing ten-hop limit ends it with its own error.]

**Guardrail(s).**
- `readable_test.cpp`, the hostile corpus, each under the 2 s ceiling: `<table><tr><td>x` repeated 25 times reads `x`s and the inner text, as now; 10 nested two-cell layout tables around 229 KB of paragraphs; 1,000,000 `&` in one text node, one attribute value and the `<title>`, each returned as written; 250 nested `<a href=x>` with empty `<i></i>` filling 2 MB. Each also at the 5 MiB fetch cap, under a ceiling of 5 s.
- `readable_test.cpp`, unchanged outputs: a data table still renders as `|` rows; a table whose cell holds a table, and a single-column table, still render as paragraphs; an image link reads as its alt text; `&amp;`, an unknown `&name;`, an entity 13 bytes long and a `&` with no `;` decode as the current characters test expects; `<a href=a>one<a href=b>two</a>` renders as two links, not one inside the other.
- `fetch_url_test.cpp`: in the redirect table, against `https://example.com:8443/docs/page?x=1`, `#frag` gives `https://example.com:8443/docs/page?x=1`. A scripted fetcher answering every request to `/a/b.html` with a 302 and `Location: #top` ends in the redirect-limit error and never requests `/a/`. A page with `<head><base href="#x">` and `<a href="c.html">` resolves the link to the page's own directory.
- `attachments_test.cpp`: an `.html` attachment in a temp directory, Latin-1 bytes for "café, naïve, Müller" under `<meta charset="iso-8859-1">`, reads back as "café, naïve, Müller" with no U+FFFD; the same with `windows-1252` and a curly quote (0x93); a file with no declaration and valid UTF-8 is unchanged.

**Acceptance criteria:**
- [ ] The sweep's 431-byte `deep.html` (25 nested tables), fetched by `apogee-dev` through `fetch_url` with the mock backend, answers in well under a second, with the same text it answers today.
- [ ] A 5 MiB page of bare `&` and a 5 MiB page of 250 nested empty links each extract in seconds, not minutes, per fetch and per read-on call.
- [ ] `apogee-dev chat --attach legacy.html` (Latin-1, declared by `<meta charset>`) indexes and hands the model "café, naïve, Müller".
- [ ] A 30x with `Location: #top` from `/a/b.html` never fetches `/a/`; it ends in the redirect-limit error. `<base href="#x">` leaves the page's links where they were.
- [ ] Every existing reader, fetch and attachment test passes unchanged, and the full suite is green.
