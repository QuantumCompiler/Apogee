# Setting Xcode up from Apogee

**What / why.** Two routes join Apogee and Xcode, and today Apogee points a person at neither. **Xcode's tools for Apogee's agents:** Xcode 26.3 and later serve their own tools to outside agents through Apple's stdio bridge, `xcrun mcpbridge` — build, run, tests, previews, documentation search, the issue navigator, file reads and writes; Xcode 27 adds the debugger, schemes, build settings, the simulator and String Catalogs. Apogee's MCP client can use it by config alone (an `mcp_servers` entry running `xcrun mcpbridge`) — in principle: the client accepts whatever protocol version a server answers with (`business/mcp/types.h:19-23`), but it has never met `mcpbridge`, so the user's run below is the first test. Yet `mcp presets` lists only `code-exec` and `self` (`presentation/operations/mcp_presets.cpp:18-44`), `check` has no Xcode row, and nothing names the Xcode setting it needs. **Apogee as Xcode's agent:** Xcode 26.6 and later add any Agent Client Protocol agent by hand in Settings › Intelligence › Agents › "Add an Agent" — 56a's [`apogee acp`](acp-agent-mode.md) ([SPEC.md:32](../../assistant/SPEC.md)). The sheet takes a Name, an Executable (an absolute path: no `~`, no PATH lookup, per Devin's guide), an optional Interpreter (for a script), Arguments (one per line) and Environment Variables, and nothing in Apogee prints those. This item makes the setup a command: `check` gains an **Xcode section**, `mcp presets` gains **`xcode`**, and **`apogee acp registration`** prints the sheet's fields, as text and as a typed document the macOS app's [5a](../../../gui/backlog/v0.2.1/xcode-in-settings.md) reads. It removes **wall W6** (the reverse route works by config alone, and nothing says so) and **states wall W3** (Xcode's approval is tied to the binary's signature and hash).

Measured, not guessed (2026-10-31, the dev Mac, read-only commands). `xcodebuild -version` answers `Xcode 27.1` / `Build version 27A9275` in 0.04–0.05 s (`time -p`, twice; `xcrun xcodebuild -version` 0.05 s). `xcrun --find mcpbridge` answers `/Applications/Xcode.app/Contents/Developer/usr/bin/mcpbridge`, whose `--help` says it reads JSON-RPC 2.0 on stdin as a "STDIO Bridge for Xcode MCP Tools". `strings` on Xcode 27.1's `IDEIntelligenceACP` holds "Add an ACP Agent", "Environment Variables" and the interpreter hint for a script; `IDEIntelligenceChat` holds "Allow External Agents to Use Xcode Tools" and the tool names `BuildProject`, `GetBuildLog`, `RunAllTests`, `XcodeRead`, `XcodeListWindows`. The research's timeline: 26.3 (RC 2026-02-03) brought `mcpbridge`; 26.6 (2026-06-25) ACP; 27 (27A266a, 2026-09-14) the new tools; Xcode 27 needs macOS Tahoe 26.6 or later on Apple silicon.

**W3, measured the same day.** `IDEIntelligenceChat` holds "Refusing %{public}s: no valid code signature." and "The agent binary has been updated since you last approved it. You will need to re-approve it to continue."; `IDEIntelligenceFoundation` holds "Unsigned agent attached", `unsignedRequiresExpiration` and `unsignedTTL`. `codesign -dv ~/.local/bin/apogee` (the installed 0.2.0) shows `flags=0x20002(adhoc,linker-signed)` and `TeamIdentifier=not set`; the CLI's build has no signing step (no `codesign` in `lib/src/cli`'s Makefile or CMake, in `lib/release` or in `.github`). So, as those strings read (not yet observed), every install or update of `apogee` or `apogee-dev` makes Xcode ask again, on both routes, and an unsigned agent's approval may lapse on a timer. Fixing it needs Developer ID signing (and notarization, for a binary a plug-in ships), against the ad-hoc call of 2026-10-20 (`lib/src/darwin/scripts/build.sh:36-42`), so this item **says it** where a person sets Xcode up. `apogee-dev` is not installed on the dev Mac yet (`ls ~/.local/bin/apogee-dev`: absent).

**Core constraint(s).**
- **Apogee prints; the person types.** Nothing writes Xcode's settings, its agent registry, or `~/Library/Developer/Xcode/CodingAssistant/` (where Xcode keeps `mcp-servers.json` and its Claude Agent's config directory). Nothing reads them either: no `com.apple.dt.Xcode` defaults, no managed policy (`CodingAssistantAllowExternalIntegrations=false` turns the coding assistant off on a managed Mac), nothing under `~/Library/Developer/Xcode`. This is the spirit of [SPEC.md:40](../../assistant/SPEC.md) ("never reads a CLI's credentials or session files") and `:69` ("A vendor CLI is spawned, never opened"). `check` asks only Xcode's command-line tools for their version and paths. What it cannot see (whether "Allow External Agents to Use Xcode Tools" is on), it says in words.
- **A fresh install stays green (M11).** Every Xcode row is Ok or Skipped, never Warn or Fail. Xcode is optional, as ffmpeg's abilities are (`presentation/cli/check.cpp:2271-2279`).
- **Children are captured and bounded** ([⚠ A child's stderr is captured, never inherited](../../assistant/CLAUDE.md#-a-childs-stderr-is-captured-never-inherited)). Each probe is a child on pipes: stdin closed, stdout read, stderr a tail, a deadline. This is the run 52e's ffmpeg rows use (`infrastructure/platform/ffmpeg.cpp:45`). It never runs a `/usr/bin` developer-tools shim when no developer directory is selected (see Open calls).
- **One create core** (47c). `mcp create xcode --from xcode` writes the config byte for byte as typing the same command and arguments by hand (`presentation/cli/mcp_cmd.cpp:98-104`).
- **A registered `xcode` is a server like any other.** It connects at the start of every tool-using run, and `mcp list` connects to it (`mcp_cmd.cpp:163`). `check` never does: `check_mcp` only looks for the command (`check.cpp:1485-1532`). With Xcode closed or its setting off, the failure is that server's, "logged and skipped, never fatal" (`business/mcp/registry.h:18`). What `mcpbridge` does when no Xcode is running was not measured; the user's run records it.
- **The registration is this binary's.** Its Executable is the running binary's absolute path (`platform::executable_path()`, `infrastructure/platform/platform.h:62-70`), never `argv[0]`, `~` or a bare name. The app's 5a, spawning the CLI it drives, gets that very binary's path and computes none of its own (the GUI's machine-mode client invariant).
- **Pipes only** ([⚠ Interactive turns never open a listening socket](../../assistant/CLAUDE.md#-interactive-turns-never-open-a-listening-socket); [SPEC.md:66](../../assistant/SPEC.md), "local front-ends are pipes … never a localhost backend for a local front-end"). `mcpbridge` is a stdio child like any MCP server, and nothing here listens.
- **Parity is the product** ([SPEC.md:65](../../assistant/SPEC.md)). The new verb completes ([ADR 0007](../../adrs/tab-completion.md)), is placed in the shell's table through `acp`'s row ([ADR 0010](../../adrs/the-shell-is-a-mode.md)), is classified in the HTTP table, and has its machine read ([ADR 0002](../../adrs/mode-parity.md)).
- **Additive** ([ADR 0006](../../adrs/backwards-compatibility.md)). `check`'s document gains rows, `mcp presets`' gains a row and a field, and `acp.registration` is new. The section and row names below are a contract 5a reads.
