How the app runs Apogee
One app process starting apogee children and speaking to them over their pipes. It never links Apogee and never opens a port: only apogee serve owns one, and that is for server deployments.

Each open session: one chat child, alive while it is in view or mid-turn
apogee chat --output-format stream-json --input-format stream-json --resume ‹id›
in: user, answer, attach, cancel · out: the turn’s events, a question, then result or error
Each task the app starts: one task run child
apogee task run "‹goal›" --tools --allow … --rounds 8 --output-format stream-json
task_started, task_plan, task_round, task_finished around each round’s events
Each clip, composition or speech: one run
apogee video generate | video compose | voice say … --output-format json
its document when it ends · progress is stderr text (G11) · a project file re-read as it saves
Reads: one-shot, run again after every change the app makes
models list | info | status · chats list · task list | status · check · graph … --output-format json
no push channel: the app knows what it changed, so it reads that back
Changes: one command each, the one a person would type
config set-* · models pull | delete | rename · chats title | delete · auth add · train setup --with …
an API key goes to auth add on stdin, never on a command line
The machine, while the system monitor is open
apogee system --output-format json, every 2 s
plus the memory of the app’s own children, which only the app knows
