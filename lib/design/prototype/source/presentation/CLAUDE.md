# The Presentation layer

**Position.** Fourth of the four ([the design's ADR 0001](../../../../documentation/adrs/design/react-design-prototype.md), applying [GUI ADR 0001](../../../../documentation/adrs/gui/layer-enforcement.md)): the windows, views and drawing, in React, whose packages and `.tsx` files stay here and nowhere below. Each module mirrors the Mac app's module of the same name ([its card](../../../../src/darwin/source/presentation/CLAUDE.md)). `styles`, `shell`, `app` and `monitor` are built (1e), `session` (1u: its turn, its composer and its four plain presets; 1v: its five scenarios, its states and nine presets, and `chat` the default start again), `sessions` and `console` (1g: the session list on every screen, the inspector, the execute door and the console, and the presets `execute` and `console`), `models` (1h: Backends, Stored weights, Jobs and Roles, their sheets and confirms, and nine presets), `settings` (1i: the ten-pane window, Appearance driving `styles`' theme service, Keyboard the shell's key map, and thirteen presets), `training` (1j: Runs, Pipelines, Cycle, Regimes and Datasets, the promote and pull sheets, the five train confirms and a refused promote, a run, a pipeline, a pass, a promote, a pull and a prepare replayed from the CLI's streams, and ten presets), `video` (1k: the clips over the records the CLI wrote, a clip's page with its player, the generate form, a run replayed from the job stream, the install consent and card -- the player, the phase row, the install card and the consent sheet promoted to `styles` for Compose and Voice -- and four presets), and `compose` (1l: the compositions in Video's second tab, through the app root's slot -- a brief planned on paper and rendered, a render read from the project the composer saves after every step, Stop and Resume, an edit previewed and rendered as a new video, the chosen voice and captions read through `styles`' `MediaPreferences` -- and five presets); until its item ports it, each other place holds a stub that says its name, and the shell shows the place's placeholder.

**Modules:** `styles` (the shared visual vocabulary: tokens, type and the common components, 1e -- among them the markdown and code a model's answer draws, 1u, a model's kind glyph, 1h, the segmented choice, 1i, and the media pieces Video, Compose and Voice share -- the player off the clock, a run's phase row, the install card and the install consent sheet, 1k -- and the window's media preferences, the voice new speech and compositions start from and whether new compositions are captioned, and a record's words, its age, seconds and path, 1l), `shell` (the window around every screen: the sidebar and its places, the route and the keys, 1e), `session` (one chat session: its turn grown from replayed machine-mode streams, its header and composer, the suite chooser and the private confirm, 1u; its scenarios -- the question and permission cards, sources and citations, a failed turn's fixes -- its states -- Restarting, Not sent, Session ended, the held lines -- and the compact jobs, 1v), `sessions` (the Sessions place: the saved conversations' list in the sidebar, the one session open with the inspector beside it, the row menu's details, rename, compaction and delete, recall, and the execute door, 1g), `models` (the Models place: Backends, Stored weights, Jobs and Roles, the store, download, adapters and pair sheets, five confirms, a pull and a conversion landing from what their runs report, 1h), `training` (the Training place: Runs with the promoted versions, Pipelines run and resumed stage by stage, the Cycle with one pass, a halt and a resume, Regimes, Datasets with a pull and its prepare, the promote and pull sheets, 1j), `settings` (the Settings window: its ten panes over the CLI's reads and verbs, Appearance changing the theme service, Models & roles drawn through the app root's slot, Keyboard the shell's key map, the Register… sheet and two confirms, 1i), `graph` (the Code graph place, 1o), `knowledge` (the Knowledge place, 1o), `compose` (compositions, Video's second tab through the app root's slot: the list, a new composition planned and rendered, a project's page with its phases, player, timeline and scenes, and the edit previewed and rendered as a new video, 1l), `console` (the console: any apogee command run as typed, Tab asking the binary, the prototype's three refusals, 1g), `library` (the Library place, 1n), `review` (the Review place, 1n), `suites` (the Suites place, 1p), `tasks` (the Tasks place, 1p), `video` (the Video place's clips: the library over the records the CLI wrote beside its clips, a clip's page with its player, the generate form as the command a person types, a run replayed from its job stream, and the one-time install a refusal names, asked first and run with Stop; the compositions tab a slot the app root fills, 1k), `voice` (the Voice place, 1m), `monitor` (the system monitor overlay, 1e), `app` (the application: the composition root, where the running app's stand-ins and the places' view-models are built and each place's screen is handed to the shell, 1e).

**Shape** ([darwin ADR 0002](../../../../documentation/adrs/darwin/presentation-mvvm.md), as the design's ADR 0001 §2 applies it): every module but `styles` is `Views/` + `ViewModels/`, with `Components/`, `Models/` or `Previews/` only when real files need them, and no file at its root. A view binds to its view-model, the view-model consumes Business, and a view never reaches Business. A view-model is a plain TypeScript class in a `.ts` file that never imports React, its services injected through its constructor. `styles` leans on no sibling, and every other module may use it; a component a second module wants is promoted there, never copied. The shell never imports a place: `app` hands it each place's screen.

**Seen on its own** ([darwin ADR 0004](../../../../documentation/adrs/darwin/module-schemes-and-previews.md), as ADR 0001 §2 applies it): every component a module's `Views/` or `Components/` exports is drawn by a preview in its `Previews/`. A preview is a named export in a `Previews/<View>.preview.tsx` file that draws one view over a view-model built on fakes, one export per state a person sees differently. Vitest runs one module's tests by path (`npx vitest run tests/presentation/<module>`); there are no schemes.

**The entry point** is not a module: `source/main.tsx`, one file that imports only `presentation/app` and calls its `start`, as the Mac app's `source/main/` starts `PresentationApp`.

**May import:** every layer below, React and the other packages `package.json` lists as dependencies, and `styles` from any module. Never a Node built-in or a dev dependency. Only `styles` reads the tokens (`@tokens`, 1e); every other module takes them from it, and writes no color, type size, font or motion but through their variables.

**Enforced by:** [`tests/architecture/layering`](../../tests/architecture/layering/LayeringCheck.ts), which reads [`modules.json`](../../modules.json): the edges, `styles`' independence, the shell's, the MVVM shape, React kept out of view-models, the entry point, every view's preview, the tokens root and this card; and [`tests/architecture/tokens`](../../tests/architecture/tokens/TokenScan.ts), the token scan (1e).

**Changing this layer:** a new module is a folder `source/presentation/<module>/` with `Views/` and `ViewModels/`, its entry in `modules.json` with what it may depend on (and `presentation/app`'s entry gaining it), its tests at `tests/presentation/<module>/`, a preview in `Previews/` for every view it exports, and its name on this card's **Modules** line, in backticks.
