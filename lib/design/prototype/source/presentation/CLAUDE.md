# The Presentation layer

**Position.** Fourth of the four ([the design's ADR 0001](../../../../documentation/adrs/design/react-design-prototype.md), applying [GUI ADR 0001](../../../../documentation/adrs/gui/layer-enforcement.md)): the windows, views and drawing, in React, whose packages and `.tsx` files stay here and nowhere below. Each module mirrors the Mac app's module of the same name ([its card](../../../../src/darwin/source/presentation/CLAUDE.md)); until its item ports it, each holds a stub that says its name and nothing more, and the empty app draws none of them.

**Modules:** `styles` (the shared visual vocabulary: tokens, type and the common components, 1e), `shell` (the window around every screen: the sidebar and its places, the route and the keys, 1e), `session` (one chat session, 1f), `sessions` (the Sessions place: the saved conversations, the inspector and the execute door, 1g), `models` (the Models place, 1h), `training` (the Training place, 1j), `settings` (the Settings window, Appearance among its panes, 1i), `graph` (the Code graph place, 1o), `knowledge` (the Knowledge place, 1o), `compose` (compositions, under Video, 1l), `console` (the console, 1g), `library` (the Library place, 1n), `review` (the Review place, 1n), `suites` (the Suites place, 1p), `tasks` (the Tasks place, 1p), `video` (the Video place's clips, 1k), `voice` (the Voice place, 1m), `monitor` (the system monitor overlay, 1e), `app` (the application: the composition root, where the running app's stand-ins and the places' view-models are built and each place's screen is handed to the shell; today the empty window).

**Shape** ([darwin ADR 0002](../../../../documentation/adrs/darwin/presentation-mvvm.md), as the design's ADR 0001 §2 applies it): every module but `styles` is `Views/` + `ViewModels/`, with `Components/`, `Models/` or `Previews/` only when real files need them, and no file at its root. A view binds to its view-model, the view-model consumes Business, and a view never reaches Business. A view-model is a plain TypeScript class in a `.ts` file that never imports React, its services injected through its constructor. `styles` leans on no sibling, and every other module may use it; a component a second module wants is promoted there, never copied. The shell never imports a place: `app` hands it each place's screen.

**Seen on its own** ([darwin ADR 0004](../../../../documentation/adrs/darwin/module-schemes-and-previews.md), as ADR 0001 §2 applies it): every component a module's `Views/` or `Components/` exports is drawn by a preview in its `Previews/`. A preview is a named export in a `Previews/<View>.preview.tsx` file that draws one view over a view-model built on fakes, one export per state a person sees differently. Vitest runs one module's tests by path (`npx vitest run tests/presentation/<module>`); there are no schemes.

**The entry point** is not a module: `source/main.tsx`, one file that imports only `presentation/app` and calls its `start`, as the Mac app's `source/main/` starts `PresentationApp`.

**May import:** every layer below, React and the other packages `package.json` lists as dependencies, and `styles` from any module. Never a Node built-in or a dev dependency.

**Enforced by:** [`tests/architecture/layering`](../../tests/architecture/layering/LayeringCheck.ts), which reads [`modules.json`](../../modules.json): the edges, `styles`' independence, the shell's, the MVVM shape, React kept out of view-models, the entry point, every view's preview and this card.

**Changing this layer:** a new module is a folder `source/presentation/<module>/` with `Views/` and `ViewModels/`, its entry in `modules.json` with what it may depend on (and `presentation/app`'s entry gaining it), its tests at `tests/presentation/<module>/`, a preview in `Previews/` for every view it exports, and its name on this card's **Modules** line, in backticks.
